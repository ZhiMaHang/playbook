# playbook

智码航提示词工具集(Claude Code 插件)。

## 技能

### prompt-optimizer

把一句没说透的话整理成可直接发送的提示词,固定三步交互:

1. **消歧**:原话有实质歧义时,出选择题让你选定读法(末项"其他"可自由填写);
2. **两道选择题**:覆盖最影响产出的两个未述维度,每道末项"其他"可自由填写;
3. **纯拼接**:原话 + 你的各次选择拼成成品——不扩写、不套模版、不加角色、不编造背景;
4. **交付选择**:成品出来后你选——直接让当前会话照着执行,或自行复制发给目标对象。

面向所有工种,成品可直接发送。

### five-sentence-brief

把一件要办的事按"五句话说清楚"补全成任务简报,同样全程零猜测:

1. **槽位盘点**:我要做什么/给谁用/解决什么问题/基于什么资料/交付成什么样——已说的按原文归位;
2. **只问空槽**:缺的槽位出选择题(末项"其他"可自由填写),明确跳过的整行省略、绝不代填;
3. **五行拼装**:固定骨架 + 你的原话与选择,零扩写零编造;
4. **交付选择**:直接让当前会话照简报执行,或自行复制发送。

### four-part-prompt

把要交办的一件事补全成"目标/背景/输出要求/边界约束"四段式结构化提示词,同样全程零猜测:

1. **槽位盘点**:目标/背景/输出要求/边界约束——已说的按原文归位;
2. **只问空槽**:缺的段落出选择题(末项"其他"可自由填写),明确跳过的整段省略、绝不代填;
3. **四段拼装**:固定骨架 + 你的原话与选择,零扩写零编造;
4. **交付选择**:直接让当前会话照提示词执行,或自行复制发送。

分工:只想把现成一句话理顺 → prompt-optimizer;站在自己角度把要办的事按五句话说清楚 → five-sentence-brief;要一份面向接收方、写明输出要求与边界约束的结构化提示词(或点名四段式)→ four-part-prompt。

### digital-human-video

文本 + 目标时长 + 人像图 → 数字人口播视频(火山引擎·即梦AI):

1. **先出脚本**:分镜表 + 成本表,此轮不花钱;数字人默认只出镜开场收尾,中段用零成本图卡;
2. **确认硬门**:拿到你明确的"开做"才调用计费接口;
3. **制作**:TTS → OmniHuman 数字人 → ffmpeg 竖版合成,显式 AI 角标 + 隐式 aigc_meta 双标识;
4. **交付**:成片路径 + 实际成本。发布一律人工,不在技能内。

肖像须本人授权(或为 AI 合成形象),未确认不制作。

### zmh-short-video-pipeline

智码航短视频采用三步主流程，并提供一个可选评论步骤：

1. **文案确认 → 音频 → Git 推送**：技能先展示将被逐字转成语音的完整文案，等待用户明确确认；确认前不生成试音，确认后用免费 TTS 归档 MP3/WAV，自动核验通过即提交本期文案、音频和核验记录并推送，读回远端验证；不启动视频生成；
2. **源视频＋辅助素材 → 正式发布包**：用户交回做好的口播视频，并为每期提供一份截图、录屏或示意图（三选一即可）；要求继续后，技能按讲解安排素材插入，保持口播声音连续，加完整字幕、关键词高亮与适量轻动效、AI 角标和 BGM，完成三版封面、质检、正式归档和四平台物料，停在 `PACKAGE_READY`；把成片与视频号物料交给用户手工发布，本步不上传任何平台。
3. **成片确认 → 三平台发布**：用户确认成片可用并要求继续第三步后，技能只发布抖音、B站、YouTube，验证公开 URL 并回填状态；视频号始终排除，抖音默认同步今日头条，YouTube Shorts 使用独立 9:16 图片。
4. **明确要求 → 平台评论（可选）**：只有用户明确说“继续第四步”“给平台加评论”或同等意思，才对已有可靠公开 URL 的平台发送锁定评论、确认公开可见、尝试置顶并回填状态。第三步发布后默认停止；用户说不需要评论时记为 `COMMENTS_WAIVED`，不再追问或补做。

Claude Code 中可显式调用 `/zmh-short-video-pipeline`。第二步固定交付发布包并停止；只有用户确认新成片可用并启动第三步后，才发布抖音、B站、YouTube，第三步结束后不会自动发表评论。第四步必须另有明确指令。用户说视频不行、要重做或“等我做好了再发”时，旧包立即停用，必须等新源片重新走完第二步。用户明确说只预览、只发部分平台、私密、定时或不需要评论时，以本轮指令覆盖默认值。每个已授权步骤完成后默认自动 commit / push 本期文件并核验远端，无需另发口令：第一步音频，第二步成片与发布包，第三步发布记录，第四步另获明确授权后的评论记录。部分平台审核中或受阻时，也归档真实结果；只生成本地、不提交或不推送等本轮明确指令覆盖默认。只提交本期改动，保护原有修改与暂存区，不夹带无关待推送提交，不强推；Git 不扩大平台发布或评论授权。

### digital-human-video-init

配置上面那个技能的凭据:火山 API 密钥、可选豆包 TTS、素材服务器,写入 `~/.config/zmh-dhv/env`(600),用假 task_id 做零成本连通性验证。首次使用或换钥时跑一次即可。

### marketing

对营销站按 SEO/GEO/SEM 任务清单做扫描与整改:

1. **双向核对**:线上 `curl` 实态 + 仓库源码,每条结论带证据(URL+状态码、文件路径:行号);
2. **四类判定**:已达标 / 可自动整改 / 需人工 / 不适用;
3. **只改代码层**:metadata、JSON-LD、sitemap、llms.txt、内链、埋点等;部署、投放、第三方发布一律列待办;
4. **固定结构报告**:自动完成 / 等你确认 / 需人工 / 清单之外的发现 / 已达标项。

**首次使用需填站点档案**——⚠️ **必须放在插件目录之外**:

```
mkdir -p ~/.config/zmh-marketing
cp skills/marketing/references/sites.md ~/.config/zmh-marketing/sites.local.md
chmod 600 ~/.config/zmh-marketing/sites.local.md
```

按模板填入你的站点仓库路径、线上 URL、部署方式、收录渠道等。

技能按 `~/.config/zmh-marketing/sites.local.md` → 本技能目录 `references/sites.local.md` 的顺序取第一个存在的。
**别放技能目录里**:装成插件后技能是从 `~/.claude/plugins/cache/<插件>/<版本>/` 加载的,而 `*.local.md`
被 .gitignore 挡在版本库外、永远进不了缓存,放那儿等于没放;就算从仓库直接跑,下次 `plugin update`
换版本目录也会连它一起丢。服务器地址、衡量 ID、密钥位置这类信息只写在 local 文件里,不会进版本库。

## 安装

```
/plugin marketplace add ZhiMaHang/playbook
/plugin install playbook@playbook
```

## 回归测试

改完 SKILL.md 后跑:

```
bash evals/run.sh          # 全部用例
bash evals/run.sh 消歧     # 按名字过滤
```

每个用例 = `evals/cases/<名字>/prompt.txt`(输入) + `rubric.md`(判分标准);脚本无头跑真插件、haiku 判分,全 PASS 退出码 0。只覆盖首轮行为,多轮交互(回"都行"、拒答、部分作答)仍需手测。

## 本地开发测试

不发布也能装,任选其一:

```
claude --plugin-dir /path/to/playbook          # 直接加载,免安装
/plugin marketplace add /path/to/playbook      # 走完整市场流程
/plugin install playbook@playbook
```
