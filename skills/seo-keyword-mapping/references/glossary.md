## 2. 基础原理

易混：抓取（crawl）≠ 爬取（scraping，垃圾政策名）；收录 = 编入索引；SEM 这里只指搜索广告；白帽、黑帽是业内说法，以垃圾政策为准。

| 中文 | English | 定义 |
|---|---|---|
| 搜索引擎优化 | SEO, Search Engine Optimization | 改进网站和它在网上的口碑，让网页在自然搜索里被收录、排得更前、被对的人点击。 |
| 搜索引擎营销 | SEM, Search Engine Marketing | 广义指在搜索引擎上做的一切营销（含 SEO）；这里专指搜索广告，按点击付费买广告位。 |
| 五个环节 | — | 把搜索引擎的工作拆成抓取、收录、排名、展示、点击五环，逐环查问题。注：审计时再加「转化」，共六环（主线） |
| 卡点 | — | 沿五个环节往后查，第一个明显掉队的环节；先修卡点，往后使劲才有用。 |
| 抓取 | crawl / crawling | 爬虫沿链接、站点地图发现网址，并下载网页内容的过程。注：不写「爬取」；Google 垃圾政策里的「爬取」指 scraping |
| 爬虫 | crawler / spider / bot | 自动发现、下载网页的程序，如 Googlebot、百度蜘蛛、Bingbot。注：百度叫蜘蛛；可以被冒充，要验证 |
| 渲染 | rendering | 像浏览器一样执行网页里的 JavaScript 和 CSS，得到用户最终看到的内容。 |
| 收录 / 编入索引 | index / indexing | 搜索引擎分析抓到的网页、存进索引库；收录了才有资格出现在结果里。注：Google 叫编入索引，百度叫收录、建立索引 |
| 排名 | ranking | 搜索引擎按相关性、质量、可用性等信号，给候选网页排先后。 |
| 自然结果 | organic result | 搜索结果页里不是广告的结果，位置不能花钱买。 |
| 搜索结果页 | SERP, Search Engine Results Page | 搜索后返回的整页结果：自然结果、广告、AI 摘要和各种模块。 |
| 零点击搜索 | zero-click search | 搜索之后没有点击任何结果就离开，或者换了一个搜索。 |
| 白帽 / 黑帽 | white hat / black hat | 业内说法：白帽守规则、为用户做好网页；黑帽用欺骗手段让搜索引擎误判。注：不是搜索引擎的官方术语；判断以垃圾政策为准 |
| SEO 五块工作 | — | 技术、页面、内容、站外、数据五块。 |
| 四步循环 | — | 工作方法：提出假设、做改动、记录、按基线验证。 |
| 变更记录表 | change log | 每次改动记下日期、页面、改了什么、为什么、看什么指标、何时复查。 |
| 五步体检表 | — | 抓取、收录、排名、展示、点击五行，各写证据和下一步。 |
| P0–P3 | — | 问题定级：P0 阻断、P1 严重、P2 一般、P3 观察；时限是经验值。 |
| 本站口径 | — | 站点对外怎么说话的统一规定：能写什么、不能写什么；以本站口径文件为准。注：≠ 统计口径；写全，不单说「口径」 |
| 口径文件 | — | 本站对外说法依据的文件（口径登记表）；位置记在站点档案里，用前看最新版。 |
| 标注 | — | 给说法标性质：推断、经验值、厂商数据、弱（如员工发言转述）、演示用虚构值。 |

## 3. 关键词

易混：意图和属性是两个维度，不并列成「五类关键词」；比技术是信息词，比品牌 / 供应商才是商业词；人群不是分类维度；长尾不按搜索量、字数定义，匿名查询不叫长尾。

| 中文 | English | 定义 |
|---|---|---|
| 搜索词 | search query | 用户在搜索框里实际输入的完整字符串；后台「搜索词报告」看到的就是它。注：GSC 界面叫「查询」 |
| 关键词 | keyword | 从搜索词里挑出来、准备去做的词，是研究、统计和投放的单位。 |
| 主题 | topic | 一组意思相同、能由同一个页面满足的关键词；一页承接一个主题。 |
| 搜索意图 | search intent | 用户输入搜索词时真正想完成的事：了解知识、找网站、比较挑选或询价购买。 |
| 客户画像 | buyer persona | 分析一个词时用：可能有哪几种人在搜、各自痛点、本站的方案、由哪页承接。注：不是给词分类的维度，不打人群标签 |
| 信息词 | informational keyword | 搜的人想知道：概念、原理、参数资料、选型、设计、故障、标准、对比、资讯。注：「问题词」「知识词」改说信息词 |
| 商业词 | commercial keyword | 搜的人想买或找供应，分九类：产品浏览、比较挑选、替代查询、找厂家、找供应渠道、询价、现货与下单、样品、定制。注：「采购意图词」「采购词」改说商业词 |
| 导航词 | navigational keyword | 想找某个网站的词，基本就是品牌词，如 digikey；数量少，单独标注。 |
| 未带意图修饰 | — | 光秃秃的品类名或型号，词面看不出意图，以结果页前排的页面类型为准。 |
| 业内四分法 | informational / navigational / commercial / transactional | 信息型、导航型、商业调查型、交易型；后两者合起来约等于这里的商业词。注：只在引用业内说法时用 |
| 属性 | attribute | 词里说的是什么：品牌、型号、品类、参数规格、封装、应用、标准、地域、技术概念。注：与意图是两个维度；与结构化数据的「属性」不同 |
| 品牌词 / 型号词 / 品类词 | branded / part-number / category keyword | 分别是「带品牌、型号、品类属性的词」的简称。注：不和信息词、商业词并列成「五类关键词」 |
| 核心词 | seed keyword | 一次拓词的起点（词根），可以是单词或词组；是相对的，换个范围可能只是长尾。注：不等于「本页主打的词」（那是主题词） |
| 长尾词 | long-tail keyword | 在核心词上加限定，定向、专一地描述某个具体问题或产品类别、场景的词。注：不按字数定义，也不凭某个月的量下结论 |
| 常青词 / 季节词 / 突发词 | evergreen / seasonal / trending keyword | 按热度随时间的变化分：全年平稳、每年固定时段起落、一阵热度。 |
| 主题词 | primary keyword | 一个页面主打的词，放进标题、H1、首段和导航名；取量大、贴近买家的叫法。注：「主词」同义；不要叫「核心词」 |
| 辅助词 | secondary keyword | 与主题词同一主题、同一意图的说法，写进正文、小标题和问答，不放首屏主标题。注：不设固定个数；别堆砌 |
| 身份词 | — | 标明身份的词：制造商、供应商还是代理商，如 manufacturer、supplier、distributor。注：身份必须属实；进不进分类页标题按本站规定，不并列两个身份词 |
| 搜索量 | search volume | 工具估算的每月搜索次数，通常是过去 12 个月的平均值。注：估算值，各工具对不上 |
| 关键词难度 | KD, keyword difficulty | 付费工具估算的「排进前 10 有多难」，主要反映外链门槛。 |
| 点击单价 | CPC, cost per click | 广告主为一次点击付的钱，可当商业价值的信号。 |
| 竞争程度 | competition | 投这个词的广告主多不多，只代表付费竞争，不代表 SEO 难度。注：KE 里叫竞争度 |
| 零量词 | zero-volume keyword | 工具显示搜索量为 0 的词；工具不给数不等于没人搜，先查后台。注：两个以上来源出现即可当真实需求（经验值） |
| 机会词 | striking distance keywords | 已排在第 4–20 名的词，以及展示多、点击少的词，通常见效较快。 |
| 关键词聚类 | keyword clustering | 把意思相同、能由同一页面满足的词归成一组，一组对应一个页面。 |
| 关键词内耗 | keyword cannibalization | 站内多个相似、意图相同的页面争同一组查询，互相分流，哪页都排不好。注：不说「关键词蚕食」；业内说法 |
| 意图 × 属性 | — | 定承接页的规则：看意图和属性两个标签，决定由哪类页面承接。 |
| 料号 / 型号 | part number, MPN | 厂家给每个具体产品的编号；带料号的词量通常小，但离询盘最近。注：「型号」「料号」指同一类东西 |
| 竞品料号 | competitor part number | 别家的料号；客户搜它多是找替代，由替代对照页或对照文章承接。注：承接页写候选型号和验证方法，不承诺直接替换 |
| pin-to-pin / drop-in | — | 客户常用的替代说法；客户这样搜，不等于页面可以这样写，按本站口径。 |
| 关键词研究表 | keyword research sheet | 记录每个词的搜索量、出价、意图、属性、范围、热度、产品线、优先级，带来源和日期。注：字段名写「GSC 展示」，不写「曝光」 |
| 关键词—页面对照表 | keyword-to-page map | 每组词由哪一页承接、现在排第几、下一步做什么；同一主题词只出现在一行。注：简称「对照表」 |
| 下拉联想 | autocomplete | 输入时搜索框下拉给出的补全建议，来自真实搜索，但不是热度排行。 |
| 其他人还问了 | PAA, People Also Ask | Google 结果页里的相关问题模块，可用来收集真实问法。 |
| Keywords Everywhere | KE | 付费积分制的关键词工具，在结果页和 GSC 旁显示搜索量、出价、竞争度和趋势。 |
| 关键词规划师 | GKP, Google Keyword Planner | Google Ads 里的免费找词工具，给月均搜索量和出价；要先完成广告账户设置。注：「平均每月搜索次数」含近似变体 |
| Google 趋势 | Google Trends | Google 的免费工具，显示 0–100 的相对热度，看走势和季节，不给绝对量。 |
| Ahrefs / Semrush | — | 付费 SEO 平台：词库、外链、竞品排名数据较全，数字都是估算（厂商数据）。 |

## 4. 站点结构与内链

易混：承接页（规划用）≠ 着陆页（GA4 用）；点击深度（点几次）≠ 目录深度（网址几层）；分类页 = 类目页；系列页 = 选型页；统一说锚文本。

| 中文 | English | 定义 |
|---|---|---|
| 一页一个主题 | one topic per page | 每个页面围绕一个主题，每个主题由一个页面承接，避免自家页面互相抢词。 |
| 承接页 | target page | 关键词—页面对照表里负责承接某组词的页面（约定用语）。注：不同于 GA4 的「着陆页」；「落地页」只用于广告 |
| 点击深度 | click depth | 从首页出发，最少点几次能到这个页面（业内术语）。注：不等于目录深度 |
| 目录深度 | directory depth | 网址路径里的层数，如 /a/b/c/ 是 3 层。 |
| 孤岛页 | orphan page | 没有任何站内链接指向的页面；这里的口径还限定它在站点地图里。注：百度的说法不带站点地图条件 |
| 页面名 | slug | 网址里标识这一页的那一段，如 /lan-transformers/，要好读、稳定。 |
| 站点迁移 | site migration | 改域名、改网址结构、换协议等改动；要新旧一一对应 301，更新内链和站点地图。 |
| 面包屑 | breadcrumb | 页面顶部「首页 › 产品中心 › 品类 › 系列」一行路径，每一级链回上级。 |
| 支柱页 | pillar page | 概括一个宽主题、链向各子主题页的中心页；B2B 产品站多半就是分类页。 |
| 集群页 | cluster content | 深入回答一个具体问题、链回支柱页的页面，也叫集群文章。 |
| 主题集群 | topic cluster | 一个支柱页加若干集群页，用内链连成一个主题的整体。注：「主题簇」同义 |
| 内链 | internal link | 站内页面之间的链接，帮搜索引擎发现页面、判断哪页重要。 |
| 锚文本 | anchor text | 链接上能看到、能点的文字，应说清目标页讲什么。注：「锚文字」「链接文字」同义，统一说锚文本 |
| 分面导航 | faceted navigation | 按系列、针数、速率等参数筛选产品的导航；每种组合都可能生成新网址。 |
| 聚合页 | aggregation page | 标签页、话题页、站内搜索页等，本身没有正文，内容来自别的页面。 |
| 分类页 | category page | 列出一个品类下系列或型号的页面，承接带品类的商业词。注：「类目页」同义 |
| 系列页 / 选型页 | series page / selector page | 列出一个系列或规格段的料号、可按参数筛选的页面。注：属于分类页的一种 |
| 型号页 | product page | 一个料号一页，承接带型号的信息词和商业词；也叫料号页、产品详情页。注：统一称型号页 |
| 替代对照页 | cross-reference page | 竞品料号对应本站的候选料号，写清参数差异和验证方法。注：也可用对照文章承接 |
| 候选型号 | replacement candidate | 替代的写法：只写「候选型号，用样品验证」，不承诺可以直接替换。 |
| 技术文章 | technical article | 讲原理、选型、设计、故障、对比、标准的文章，承接带品类的信息词。 |

## 5. 页面要素

易混：标题（title）≠ 标题链接（结果页上的蓝字）；摘要（snippet）≠ AI 摘要；描述不叫「元描述」；密度没有官方标准。

| 中文 | English | 定义 |
|---|---|---|
| TDK | — | Title、Description、Keywords 的首字母，指 head 里的标题、描述、关键词标签。 |
| 标题 | title 元素 | 写在 <title> 里的页面标题，显示在浏览器标签上，是标题链接最常用的来源。注：长度没有官方上限，约 600 像素截断（经验值） |
| 标题链接 | title link | 结果页上可点的蓝色标题，由搜索引擎自动生成，可能改用 H1、锚文本等来源。注：百度也会改写标题 |
| 描述 | meta description | 站长写的页面概要，可能被拿来当摘要；不用于排名。注：不叫「元描述」 |
| 摘要 | snippet | 结果页上标题链接下的两三行说明，多取自正文，有时用描述。注：不同于「AI 摘要」 |
| 关键词标签 | meta keywords | 声明页面关键词的旧标签；Google 明确说对收录和排名没有影响。 |
| 站点名称 | site name | 结果页上显示的网站名称，Google 主要取自首页的 WebSite 结构化数据。 |
| H1–H3 | heading tags | 正文的标题层级：H1 是页面上看得见的主标题，一页一个；H2、H3 撑起结构。 |
| 图片替代文本 | alt text | img 的 alt 属性，写清图里是什么，供读屏软件和搜索引擎理解图片。注：也写作 alt 文字、图片替代文字 |
| Open Graph 标签 | Open Graph | 供社交平台生成分享卡片的标签；og:title 也是标题链接的参考来源之一。 |
| 关键词密度 | keyword density | 业内说法：某词在正文里出现的次数或字数占全文的比例。注：三家官方都没有密度标准 |
| 主题词组密度 | — | 内部经验指标：主题相关词组占正文字数的比例，只用来找漏写的叫法。注：不是搜索引擎标准；不设目标，偏高查堆砌 |
| 关键词堆砌 | keyword stuffing | 为操纵排名不自然地重复关键词、罗列地名或号码，违反垃圾政策。注：Google 中文版写「关键字堆砌」 |

## 6. 结构化数据

易混：富结果资格 ≠ 排名提升；富结果测试查 Google 资格，验证器查语法；标记的「属性」≠ 关键词的「属性」；FAQ 富结果已停用，问答文字仍有用。

| 中文 | English | 定义 |
|---|---|---|
| 结构化数据 | structured data | 用标准格式提供页面信息、给页面内容分类的数据，内容要来自页面本身。注：采用 Google 的定义（2025-12-10） |
| Schema.org | — | Google、必应、雅虎等共同发起的结构化数据公用词汇表，定义类型和属性。 |
| JSON-LD | JSON for Linked Data | 用 JSON 写关联数据的 W3C 推荐格式，写在 script 标签里，浏览器不显示。注：Microdata、RDFa 是另两种写法 |
| 类型 / 属性 | @type / property | 类型说明「这是什么」（如 Product），属性用「键: 值」写具体信息（如 name）。注：和关键词的「属性」不是一回事 |
| 富结果 | rich result | 在标题、网址、摘要之外，带面包屑、评分、视频缩略图等附加信息的结果。注：FAQ 富结果 2026-05-07 起已停用 |
| 富结果资格 | rich result eligibility | 标记满足某类富结果的要求，页面才「有资格」出现；不保证显示，也不提升排名。 |
| 结构化数据常规指南 | General structured data guidelines | Google 的红线：标记必须真实代表页面，看不到的、不真实的、误导的都不能写。 |
| Organization | — | 标注「这家公司是谁」：名称、法定名、logo、地址、联系方式、sameAs 等。 |
| WebSite | — | 标注「这个站叫什么」，放首页；Google 主要据它确定站点名称。 |
| sameAs | — | 指向介绍本组织的其他页面，如官方社媒主页；只放核实过、打得开的。 |
| BreadcrumbList | — | 面包屑标记：用 ListItem 写出每一级的名称、位置和网址。 |
| Product | — | 产品标记：name、brand、mpn、sku 等；代理产品的 brand 写原厂。注：分类页、系列页不建议标 Product |
| 商家信息 / 产品摘要 | merchant listing / product snippet | Google 两类产品富结果：前者要能直接购买、带价格；后者用于介绍类产品页。注：无价格、无评价的料号页通常都没资格 |
| Offer | offers | Product 里的报价信息，必填价格和币种；页面没有价格就不写。 |
| ProductGroup | 产品组 | 把同一产品的变体归为一组；变体维度只支持颜色、尺寸等六种。 |
| mpn / sku / gtin | — | 制造商零件号 / 商家库存编号 / 全球贸易项目代码，Product 的识别码。 |
| Article | — | 文章标记：标题、作者、发布和修改日期、发布方，帮 Google 显示得准。 |
| VideoObject | — | 视频标记，必填名称、缩略图、上传日期；可写时长和播放地址。 |
| FAQPage / QAPage | — | FAQPage 是站方写答案的问答；QAPage 是一个问题、由用户提交答案的页面。注：FAQ 富结果已停用；问答文字仍有用 |
| 富结果测试 | Rich Results Test | Google 的在线工具，只测 Google 支持的富结果类型；通过不等于会显示。 |
| Schema Markup Validator | Schema 验证器 | schema.org 维护的通用校验工具，查能否解析、词汇是否用对。注：不判断 Google 富结果资格 |
| 富结果报告 | rich result reports | GSC 增强功能下按「项目」统计有效和有问题的标记，修好后可发起验证。 |

## 7. 技术 SEO

易混：robots.txt 管抓取，noindex 管收录；规范网址不说「标准链接」；叙述说「跳转」，GSC 界面名「重定向」照原样；前端渲染 = 客户端渲染。

| 中文 | English | 定义 |
|---|---|---|
| 技术 SEO | technical SEO | 让搜索引擎能顺利找到、抓取、渲染、收录网站，并让访客体验良好的那部分工作。 |
| 抓取预算 | crawl budget | Google 能抓、又想抓的网址集合，由抓取容量上限和抓取需求决定。注：中小站通常不必专门管 |
| robots.txt | — | 网站根目录的文本文件，告诉爬虫哪些网址不要抓；只管抓取，不管收录。注：挡住抓取的网址仍可能被收录 |
| meta robots / X-Robots-Tag | robots meta tag | 控制收录和摘要的指令，写在 head 的 meta 标签里，或写在 HTTP 响应头里。 |
| noindex | — | 允许抓取、但不要收录的指令；要让爬虫抓得到才能生效。注：百度官方只声明过 nofollow、noarchive |
| nosnippet / max-snippet | — | 控制摘要的指令：不显示摘要 / 限制摘要长度；也影响 AI 概览、AI Mode 取用。注：data-nosnippet 只排除页面里的某一段 |
| 站点地图 | sitemap | 列出希望被抓取的规范网址的文件，帮搜索引擎发现网址，不决定收录。 |
| lastmod | — | 站点地图里网址的最后修改时间，实质变化才更新；Google 在它一贯准确时才参考。注：changefreq、priority 被 Google 和必应忽略 |
| 站点地图索引文件 | sitemap index | 汇总多个子站点地图的文件；百度不支持，要切成多个文件分别提交。注：也叫索引型 sitemap |
| 主动推送 | — | 网址有变化时主动通知搜索引擎，如百度 API 提交、IndexNow、GSC 请求编入索引。注：提交 ≠ 收录 |
| IndexNow | — | 开放协议：网址增删改时主动通知，必应等参与引擎之间共享；Google 不参与。 |
| HTTP 状态码 | HTTP status code | 服务器对每个请求先回的三位数代码，搜索引擎据此决定收录、转移还是删除。 |
| 301 / 308 永久跳转 | permanent redirect | 网址已永久搬到新地址，目标网址成为规范网址，信号随之转过去。注：叙述说「跳转」，GSC 界面名「重定向」照原样 |
| 302 / 307 临时跳转 | temporary redirect | 暂时转到别处，原网址可能继续被收录；用于短期变更。 |
| 跳转链 | redirect chain | A → B → C 多级跳转；Google 最多跟 10 跳，要改成一步到位。 |
| 404 / 410 | Not Found / Gone | 网页不存在 / 已删除；会逐步移出索引，用于删除且没有替代页的情况。 |
| 5xx / 503 | server error | 服务器错误；Google 会降低抓取，持续出错的网址最终被移出索引。 |
| 软 404 | soft 404 | 页面内容是「找不到」「已下架」或几乎为空，却返回 200 等成功码。注：百度叫「内容死链」 |
| 规范网址 | canonical URL | 一组重复或相似网页里被选作代表的网址；可以声明，最终由搜索引擎决定。注：不说「标准链接」；GSC 界面叫「规范网页」 |
| rel=canonical | — | 在页面 head 里声明规范网址的标签；是强提示，不是命令。 |
| 用户声明的 / Google 选择的规范网址 | user-declared / Google-selected canonical | 前者是你在 canonical 里写的，后者是 Google 实际选用的；两者可能不同。 |
| 重复内容 | duplicate content | 相同或高度相似的内容出现在多个网址；效率低，但本身不会招致人工处置。 |
| 参数网址 / 跟踪参数 | parameterized URL / tracking parameter | 带 ? 参数的网址，如筛选、排序、utm_ 跟踪参数；容易生成大量重复。注：跟踪参数用 canonical 处理，不能跳转去掉 |
| 服务端渲染 | SSR, server-side rendering | 在服务器上渲染好，把完整 HTML 发给浏览器，爬虫第一次请求就能读到内容。 |
| 前端渲染 | CSR, client-side rendering | 服务器只给空壳，内容要等浏览器运行 JS 后才出现；别的引擎和 AI 爬虫未必读得到。注：也叫客户端渲染，同义 |
| 静态生成 / 预渲染 | static rendering / prerendering | 构建时就为每个网址生成好完整 HTML，访问时直接返回；风险低，Google 推荐。注：也叫静态渲染 |
| 单页应用 | SPA, single-page application | 只有一个 HTML 外壳、内容全靠 JS 切换的网站。 |
| 原始 HTML / 渲染后的 HTML | raw HTML / rendered HTML | 服务器直接返回的代码 / 执行 JS 后的页面；查看源代码看前者，网址检查看后者。 |
| 核心网页指标 | Core Web Vitals | Google 衡量真实用户体验的三项指标：LCP（加载）、INP（响应）、CLS（视觉稳定）。 |
| LCP | Largest Contentful Paint | 最大内容绘制：首屏最大的内容多久显示出来；≤ 2.5 秒良好，> 4 秒差。 |
| INP | Interaction to Next Paint | 与下一次绘制的交互：点击、输入后页面多久有反应；≤ 200 毫秒良好，> 500 毫秒差。注：2024-03-12 起取代 FID |
| CLS | Cumulative Layout Shift | 累积布局偏移：页面元素会不会突然跳动；≤ 0.1 良好，> 0.25 差。注：写「累积」，不写「累计」 |
| 75 分位 | 75th percentile | 核心网页指标按访问的 75 分位评估：四分之三的访问达标才算良好。 |
| 实测数据 / 实验室数据 | field data / lab data | 真实 Chrome 用户过去 28 天的统计 / Lighthouse 在固定条件下模拟一次的结果。注：Google 判断体验看实测数据 |
| CrUX | Chrome UX Report | Chrome 用户体验报告：开启统计的 Chrome 用户过去 28 天的真实体验数据。 |
| TTFB | Time to First Byte | 首字节时间：从发出请求到收到服务器第一个字节的时间。 |
| PageSpeed Insights | PSI | Google 的免费测速工具，同时给 CrUX 实测数据和 Lighthouse 实验室数据。 |
| Lighthouse | — | Google 开源的网页审计工具，在模拟环境里测性能、无障碍、SEO 等。 |
| 网页体验 | page experience | Google 对访客体验的统称：核心网页指标、HTTPS、无干扰插页等，没有单一信号。注：Google 中文文档用「网页体验」 |
| 移动优先索引 | mobile-first indexing | Google 以手机版内容编入索引和排名；2024-07-05 起只用智能手机版 Googlebot 抓取。 |
| 响应式设计 | responsive web design | 同一网址、同一份 HTML，按屏幕宽度调整显示；内容天然一致，Google 推荐。注：百度叫「自适应」 |
| 动态服务 | dynamic serving | 同一网址按 UA 返回不同 HTML，要加响应头 Vary: User-Agent。 |
| 独立网址 | separate URLs | 手机版用另一个网址（如 m. 子域名），要双向标注、跳到对应页。注：也叫独立手机站、独立 H5 |
| hreflang | — | 标注同一内容的不同语言或地区版本，各版本要双向互指、并列上自己。 |
| x-default | — | hreflang 的兜底值，给没有匹配语言版本的用户，如语言选择页。 |
| 用户代理 | UA, User-Agent | 浏览器或爬虫访问网页时报上的身份；网站常据此给手机版或桌面版。注：谁都能填，要配合反向 DNS 验证 |
| 服务器日志 | server log / access log | 服务器每收到一次请求就记一行：时间、网址、状态码、UA、IP，能看到爬虫真实来访。注：只能证明抓取，不能证明被 AI 引用 |
| 反向 DNS 验证 | reverse / forward DNS lookup | 先用 IP 反查主机名，再正查回到原 IP，确认来访的是真爬虫。 |
| curl | — | 命令行请求工具，可指定 UA 查看状态码、跳转链、响应头和原始 HTML。 |
| 浏览器开发者工具 | DevTools | 浏览器内置工具：看网络请求、响应头、渲染后的元素，模拟手机。 |
| Screaming Frog | Screaming Frog SEO Spider | 英国 Screaming Frog 公司的整站抓取软件，免费版每次最多 500 个网址。注：统称「抓取工具」，不说爬虫工具 |

## 8. 内容与 E-E-A-T

易混：E-E-A-T 是框架，不是分数，也不是排名因素；有帮助、实用、有用内容是同一组概念；实质更新 ≠ 只改日期；「有人把关」≠「必须人写」。

| 中文 | English | 定义 |
|---|---|---|
| 有帮助的内容 | helpful content | 主要为帮助人而做、能让读者满意离开的内容；Google 给了 32 个自查问题。注：Google 中文版译作「实用」 |
| 以用户为中心的内容 | people-first content | 主要为帮助用户、而不是为操纵搜索排名而做的内容。 |
| 以搜索引擎为中心的内容 | search engine-first content | 主要为吸引搜索流量而做的内容；Google 列了 11 条警示信号。 |
| E-E-A-T | Experience, Expertise, Authoritativeness, Trust | 经验、专业、权威、可信：Google 描述好内容的框架，本身不是排名因素。 |
| 经验 / 专业 / 权威 | Experience / Expertise / Authoritativeness | 有没有第一手经历 / 有没有必要的知识技能 / 是否被公认为可靠来源。 |
| 可信 | Trust | E-E-A-T 的中心、最重要的一项：页面是否准确、诚实、安全、可靠。注：E-E-A-T 的 T 是 Trust |
| YMYL | Your Money or Your Life | 可能显著影响健康、财务稳定、安全或社会福祉的话题，可信要求更高。注：以《搜索质量评估指南》2.3 节为准 |
| 内容 SEO | content SEO | 工作定义：按搜索需求决定写什么，写成对口、有证据、合口径的内容，并一直管好。 |
| 内容策略 | content strategy | 对有用、可用内容的创作、交付和治理做规划（Halvorson，2009）。 |
| 常青内容 / 时效内容 | evergreen / timely content | 原理、选型等长期有效、定期复核的内容 / 新品、展会、资讯等写清日期的内容。 |
| 一手资料 / 二手转述 | primary / secondary source | 自己的实测、FAE 记录、实物照片 / 媒体、论坛、AI 的说法，后者只当线索。 |
| 署名 | byline | 写明内容由谁负责；建议署真实个人，或真实团队并配团队页。 |
| 内容生命周期 | content lifecycle | 新建、复核、更新、合并、不收录、删除；删除排在最后。 |
| 实质更新 | substantial update | 补新数据、按新版规格书改参数等实质改动；只改日期是 Google 列的警示信号。 |
| 内容修剪 | content pruning | 定期盘点内容，把过时、重复、没有价值的更新、合并或删除。 |
| 合并 | consolidation | 把讲同一主题的几篇并成一篇：留一篇、并入独有内容、旧网址 301、改内链。 |
| 单薄内容 | thin content | 几乎没有独特价值的页面，如只换型号、正文大段照搬上级的模板页。 |
| 重合度 / 独有字数 | — | 内部检查口径：与同模板页相同句段占正文的比例 / 本页独有的正文字数。注：分数提高 ≠ 排名变好 |
| FAE | Field Application Engineer | 现场应用工程师：负责技术支持；参数核对、替代型号确认以其书面意见为准。 |
| AI 生成内容 | AI-generated content | Google 不反对用 AI 写，只看是否有帮助；要有人把关，发布前人工核查准确性。注：为操纵排名批量生成属滥用规模化内容 |

## 9. 站外与品牌

易混：反向链接 = 外链 = 入站链接；品牌提及（网页里）≠ 提及（AI 回答里）；DR、DA、百度权重都是第三方分数；「权重」先说清指排名信号还是工具分数。

| 中文 | English | 定义 |
|---|---|---|
| 站外 SEO | off-page SEO | 网站以外影响搜索表现的工作，分链接、提及与评价、实体信息三类。 |
| 站外信号 | off-site signals | 别人怎么链接、怎么提到你；搜索引擎据此判断主题和可信度。 |
| 反向链接 | backlink | 别的网站指向你网站的链接，也叫外链、入站链接。注：正文多说「外链」，工具界面说反向链接 |
| 引用域 | referring domain | 至少有一条链接指向你的网站的网站，按网站计数（Majestic 词汇表）。 |
| nofollow | rel=nofollow | 链接属性：不希望传递排名信号；Google 当作提示，不是命令。 |
| sponsored / ugc | rel=sponsored / rel=ugc | 标付费、赞助链接 / 标用户生成内容里的链接；标了就不算违规。 |
| PageRank | — | Google 早期按链接计算网页重要性的算法，至今仍是核心系统的一部分。 |
| 权重 | — | 行业俗称，有时指链接传递的排名价值，有时指第三方工具分数，没有官方定义。注：用之前先说清指哪一种 |
| DR / DA / AS | Domain Rating / Domain Authority / Authority Score | Ahrefs、Moz、Semrush 各自算的网站权威分，是厂商指标，不是搜索引擎的数据。注：各家分数不能互比 |

| PBN | private blog network | 为操纵排名自建或买来的一批博客站，互相给目标站加链接，属垃圾链接。 |
| 链接农场 | link farm | 大量网站互相链接、专为操纵排名而建的网络。 |
| 数字公关 | Digital PR | 用数据报告、调研、新闻素材争取媒体自然报道和链接（业内说法）。 |
| 品牌提及 | brand mention | 别人在网上提到本站，分带链接提及和无链接提及（业内说法）。注：和 GEO 的「提及」不同 |

## 13. GEO 与 AI 搜索

易混：AI 摘要（泛称）、AI 概览（Google）分开叫；检索增强生成（方法）≠ 接地（以来源为依据）；提及、引用、推荐、点击分开记；说「问题集」，不说题库、提示词库。

| 中文 | English | 定义 |
|---|---|---|
| GEO | Generative Engine Optimization | 让 AI 读到、读懂、信任本站的真实信息，从而正确提及、引用或推荐本站。注：看作 SEO 的一部分（Google 2026-07-10 也这样说） |
| AEO / LLMO / AI SEO | Answer Engine Optimization / LLM Optimization | 答案引擎优化、大模型优化等业界说法，没有权威定义，当作 GEO 的同义泛称。 |
| AI 搜索 | AI search / generative search | 用大模型直接生成回答、常附来源链接的搜索；也叫生成式搜索、生成式引擎。注：泛称用「AI 搜索」 |
| AI 摘要 | AI summary | 结果页上用 AI 生成的回答的泛称；专指 Google 时说 AI 概览。注：不说「AI 总结」 |
| AI 概览 | AI Overviews | Google 结果页上方附支持链接的 AI 摘要，只在系统判断有帮助时出现。 |
| AI Mode | — | Google 可以连续追问的 AI 搜索，适合探索、比较等复杂问题。注：Google 中文版写「AI 模式」；统一写 AI Mode |
| 支持链接 | supporting links | AI 概览、AI Mode 回答里附的来源链接；网页要已收录、有资格带摘要显示。注：Google 中文版也译「辅助链接」 |
| 生成式 AI 效果报告 | — | GSC 报告：网页在 AI 概览、AI Mode 里的展示次数；没有查询词和点击。注：也简称「生成式 AI 报告」 |
| 搜索生成式 AI 控制 | — | GSC 的开关：整站或子资源退出 AI 概览、AI Mode 等生成式功能；不是排名信号。 |
| 联网检索 | — | AI 回答前先搜索、读取网页，再根据网页写答案并附来源。 |
| 检索增强生成 | RAG, Retrieval-Augmented Generation | 先检索外部资料、再据此生成答案的技术方法。 |
| 接地 | grounding | 让模型的回答以检索到、可查证的来源为依据；Google、微软的用语。注：和「检索增强生成」不是一个词 |
| 查询扇出 | query fan-out | AI 把一个问题拆成多条相关子查询分别检索，再汇总作答（Google 用语）。注：拆出的查询叫子查询 |
| 提及 | mention | AI 回答正文里出现了本站的品牌名，不一定带链接。注：和站外的「品牌提及」统计对象不同 |
| 引用 | citation | AI 回答把本站的网页列为来源，或链接到本站的域名。 |
| 推荐 | recommendation | 推荐、找厂家、找替代类问题里，把本站放进最终建议名单；只在候选里出现不算。 |
| AI 引荐访问 | AI referral visits | 用户从 AI 回答点进网站的访问；对应四个结果里的「点击」。 |
| 提及率 | mention rate | 提到本站的回答数 ÷ 有效回答数，只算非品牌题。注：不说出现率、命中率 |
| 引用率 | citation rate | 引用本站任一网址的回答数 ÷ 有效回答数。注：多语言站按语言分开记 |
| 推荐率 | recommendation rate | 推荐类问题里把本站列入最终推荐的回答数 ÷ 该类有效回答数；候选不算。注：不用「推荐排位」 |
| 声量份额 | share of voice | 本站被提及次数 ÷（本站 + 固定竞品名单被提及次数之和）。 |
| AI 可见度 | AI visibility | 泛称 AI 回答里有没有本站；不合成一个分数，分开报提及率等四项。注：「AI 可见性」同义 |
| 问题集 | question set | 按买家真实问法整理、带意图和属性标签、有版本号的固定问题清单，用于 GEO 监测。注：不说题库、提示词库；固定问题集同义 |
| 品牌题 / 非品牌题 | branded / non-branded prompts | 问题里带不带本站的品牌名；提及率只算非品牌题，品牌题单独看。 |
| 训练爬虫 | training crawler | 抓网页用于训练模型的 AI 爬虫，如 GPTBot、ClaudeBot；屏蔽后不进以后的训练。注：不写「训练类爬虫」 |
| 搜索爬虫 | search crawler | 为 AI 搜索建索引的爬虫，如 OAI-SearchBot；屏蔽后退出该平台的 AI 搜索。 |
| 用户触发抓取 | user-triggered fetch | 用户提问时 AI 临时打开网页，如 ChatGPT-User；各家对 robots 的态度不同。注：也叫实时访问 |
| 控制标记 | — | Google-Extended 这类写在 robots.txt 里、管 AI 用途的标识，不是独立爬虫。注：不是控制文件，也不是爬虫 |
| Google-Extended | — | 控制标记：管内容是否用于 Gemini 训练和部分系统的接地；不影响搜索收录和排名。 |
| GPTBot / OAI-SearchBot / ChatGPT-User | — | OpenAI 的三类爬虫：训练爬虫 / 搜索爬虫 / 用户触发抓取。 |
| llms.txt | — | 放在网站根目录、给 AI 代理看的 Markdown 网站导读；仍是提案，Google 搜索不用。 |
| 参数文字化 | — | 把参数写成网页文字和表格，不只放在 PDF、图片或脚本里，机器才读得到。 |
| 语料投毒 | corpus poisoning | 批量投放虚假内容来影响模型输出，如 2026 年 3·15 曝光的「AI 投毒」。 |
| GEO 团体标准 | — | 中国商务广告协会 2026-09-16 发布的《生成式引擎优化（GEO）》推荐性团体标准。 |
| 国内 AI 助手 | — | 豆包、腾讯元宝、DeepSeek、Kimi、千问、文心等，都没有公开的站长后台。注：千问也叫通义 |
| 海外 AI 搜索平台 | ChatGPT search / Perplexity / Gemini | ChatGPT 搜索（OpenAI）、Perplexity、Gemini（Google）等，选来源的规则都不公开。 |
