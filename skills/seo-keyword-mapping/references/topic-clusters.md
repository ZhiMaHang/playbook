# 主题集群与支柱页

步骤 5 用。讲清证据强弱、产品站上怎么分工、怎么连、怎么验证，以及新选题和已有页面的关系。集群文章怎么写交 seo-content-writing。

## 1. 术语

- **支柱页**（pillar page）：概括一个宽主题、链向各子主题页的中心页。产品站上多半就是分类页。
- **集群页**（cluster content）：深入回答一个具体问题、链回支柱页的页面，也叫集群文章。
- **主题集群**（topic cluster）：一个支柱页加若干集群页，用内链连成一个主题的整体。「主题簇」同义。

## 2. 来源与证据：当组织方法，不当排名因素

| 时间 | 事件 | 证据强度 |
|---|---|---|
| 2015 | HubSpot 内部实验「Topics over Keywords」：相关页面之间内链越多，排名和展示越好；只有散点图，没有样本量和检验 | 弱 |
| 约 2017 | HubSpot 发表《Topic clusters: The next evolution of SEO》，公开这套方法 | 厂商文章 |
| 2018 | 内容营销协会（CMI）转述「内链越多排名越靠前」，同样没有实验设计和数字 | 弱 |
| 2023-05-23 | Google「新闻主题权威」系统：只用于新闻类查询，不能直接套到 B2B 产品站 | 官方，但不适用 |

检索时没有找到同行评审或带对照组的研究证明它是排名因素（检索于 2026-10-21）。

所以：
- 把主题集群当「信息架构 + 内链」的组织方法用。它的好处是一个主题的页面分工清楚、互相连通，读者和搜索引擎能走完整条路径，文章的读者能一步走到产品；也避免文章和分类页争同一个词。
- 不对用户承诺「做了集群就涨排名」。
- 效果用数据验证（第 7 节）。

## 3. 产品站上的分工

以一个品类为例（示意）：

```
支柱页：<品类> 分类页            ← 品类主题词、带品类的商业词（产品浏览、找厂家、找供应渠道）
 ├─ 选型文章：<品类> 怎么选        ← 信息 · 选型方法
 ├─ 原理文章：<品类> 怎么工作      ← 信息 · 原理机制
 ├─ 对比文章：<类型 A> vs <类型 B> ← 信息 · 技术对比
 ├─ 故障文章：<现象> 怎么排查      ← 信息 · 故障排查
 ├─ 替代对照：<竞品料号> 替代候选  ← 商业 · 替代查询
 ├─ 应用领域页：<设备> 设计        ← 信息 · 设计应用；用同义叫法作锚文本链回支柱页
 └─ 相关支柱页：经常一起选型的另一个品类的分类页（互链）
```

- 分类页接品类商业词；对照页（或对照文章）接带竞品型号的商业词；选型、原理、对比、故障文章接信息词；应用领域页接设计应用。
- 层级不是关键：结构上是四级页，只要它是这个品类词的承接页，就可以做支柱页。
- 聚类时就决定每组词归支柱页还是某篇集群页，判断依据是意图 × 属性（page-roles.md 第 1 节）。

## 4. 链接规则

1. **支柱页链到每篇集群页**：放在「相关资料」这类区块，按主题挑，不放全站共用的一组。
2. **每篇集群页链回支柱页和相关型号页**：每篇文章至少链 1 个相关型号页或分类页（经验做法）。
3. **集群页之间按需互链**，不必两两全链。
4. **相关支柱页之间互链**：经常一起选型的品类互相链接。
5. **集群页的标题、H1 用信息词**（「为什么 X 测试失败」「X 怎么选」），不用品类商业词。否则文章会和分类页争同一组查询，变成内耗。
6. **锚文本写目标页的主题**（internal-links.md 第 4 节）。

## 5. 话题页、标签页和分类页

很多站的新闻或博客按产品品类建话题页、标签页，把文章自动归组。分工：
- 话题页讲「这个品类的文章」，分类页讲「这个品类的产品」；
- 话题页不抢分类页的品类商业词；
- 话题页要在正文里链到对应的分类页，把读文章的人送到产品，只靠页头菜单不够；
- 空的话题页、文章很少的标签页，按 cannibalization-duplicates.md 第 10 节决定收不收录；
- 有多语言版本的，先确认话题页在每种语言都存在，再从那种语言的页面链过去。

话题页本身有没有用，要看它在搜索控制台里的展示、点击，以及读者有没有从它点进分类页。

## 6. 新选题先查有没有页面能接住

一个需求（后台的一个查询、客户的一个问题、关键词表里的一个词）不直接变成「写一篇文章」。先判断意图细类，再查对照表：

| 情况 | 处置 |
|---|---|
| 已有对口的页面 | 更新这一页，不新写 |
| 有页面，但不对口（比如文章在排品类商业词） | 先查是不是内耗（cannibalization-duplicates.md），再决定改承接页还是新写 |
| 商业词，没有页面 | 由产品类页面承接（分类页、型号页、替代对照页），不写成文章 |
| 小问题，没有页面 | 写进相关页面的问答，不单独成篇 |
| 信息词，没有页面，拿得出一手内容 | 新写文章 |
| 信息词，没有页面，拿不出一手内容 | 先不写 |

为什么先查（经验）：新写一篇和已有页面讲同一件事，会和自己抢词；更新一页通常比新写一页见效快，也不会多出一个要维护的网址。

「小问题」怎么判断（经验）：两三句话能答完、没有独立的搜索需求，或答案离不开某个产品的参数，就写进那个页面的问答；有量、有多个子问题，才单独成篇。

处置结果记进选题表（交 seo-content-writing）：处置五选一：新写、更新、并入、写进问答、不做；不是「新写」的，写清并入或更新哪个网址。对照表里「承接页」为空、有量的词，是选题的来源之一。

为 AI 搜索拆出来的每个子问题（查询扇出）批量建页，同样违反滥用规模化内容的规定（Google 生成式 AI 优化指南，2026-07-10）：一个主题一页，把主要的子问题写进这一页。

## 7. 怎么验证

- **改之前**记下支柱页和每篇集群页近 4 周的搜索控制台展示、点击、平均排名，冻结一份基线。
- **4–8 周后**对比：支柱页的展示、排名有没有涨；集群页的读者有没有点进支柱页（网站统计里看从文章到分类页的流转）；内链是否覆盖了每篇集群页。
- 只拿平台数据说「有效」。「已经链上了」只是完成了动作，不是效果。

## 8. 常见问题

| 问题 | 后果 | 怎么改 |
|---|---|---|
| 分类页的推荐区块全站都指向同一篇文章 | 一百多个页面给同一篇文章投票，同主题文章没人链，文章读者也导不到同主题的产品页 | 推荐区块按主题挑文章 |
| 文章拿了大部分点击，却不链产品页 | 读者走不到分类页、型号页 | 流量前 10 的文章先做：正文提到品类、型号处链过去 |
| 文章标题用品类商业词 | 和分类页抢词 | 标题、H1 改用信息词 |
| 话题页正文不链分类页 | 话题页成了死胡同 | 话题页链到对应分类页 |
| 把集群当成「多写文章」 | 文章越写越多，彼此不连，也不连产品 | 先画支柱页和集群页的分工，再补链接；补链接通常不用写新内容，投入小 |
