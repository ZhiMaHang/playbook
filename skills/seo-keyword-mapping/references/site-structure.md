# 站点结构：层级、网址、导航、面包屑、多语言

步骤 4 用。三条原则贯穿全篇：已有页面先改，不轻易新建；已收录的网址不轻易改；删除放到最后。

## 1. 三种结构

| 结构 | 样子 | 适合 | 问题 |
|---|---|---|---|
| 扁平 | 首页直接链到所有页面 | 几十个页面的小站 | 上千个型号时导航放不下，每个链接分量变小，看不出分组 |
| 深树 | 层层下钻，每层只链下一层 | — | 越深越难被发现，抓取和收录更慢 |
| 扁平树形 + 网状互链（推荐） | 首页 → 分类 → 内容页，层级少；同级、相关页面横向互链 | 大多数产品站 | 要专门做横向链接 |

依据：百度《搜索引擎优化指南 2.0》：树型结构（首页—频道—内容页）、层级少、网状互链；每页至少一个文本链接可达；重要内容放浅层。经验值：首页 → 分类 → 系列 → 型号，三次点击内找到任意产品。

## 2. 点击深度比目录深度要紧

- **点击深度**：从首页出发，最少点几次能到这个页面（业内术语）。
- **目录深度**：网址路径里的层数，如 `/a/b/c/` 是 3 层。

两者没有必然关系：`/a/b/c/d/page/` 如果首页导航直接链到它，点击深度是 1；`/page/` 如果只有第 5 层的列表页链到它，点击深度是 5。

依据：
- 百度《网站优化》（2019-03-30）：离首页点击距离越近越受重视，即使目录层级较深；内链形成的逻辑结构才是搜索引擎最关注的。
- Google 人员的发言（2018、2021 答疑，媒体转述，年份较早）：Google 不数网址里的斜杠，更看从首页要点几次；不必人为压平目录。

所以不要为了「扁平」去改网址：层数本身对排名影响很小，改网址却要按迁移处理（第 7 节）。

## 3. 量点击深度、找孤岛页

**孤岛页**：没有任何站内链接指向的页面。本方法的口径还限定它「在站点地图里」，因为实际查的时候是拿站点地图减去抓取找到的网址；百度的说法不带站点地图条件。

五步：
1. **列重点页**：对照表里的每个承接页，加上排在第 4–20 名的机会词所在的页面。
2. **量点击深度**：页面少，手动从首页点；页面多，用 `scripts/click_depth.mjs` 或抓取工具（如 Screaming Frog，完整版付费，免费版有抓取数量上限；结果里 Crawl Depth 是点击深度，Inlinks 是入链数）。
3. **查入链**：搜索控制台「链接」报告 → 内部链接，看每页被多少页面链接。它统计的是被链次数，不是点击深度，两样都要量；表格最多显示 1,000 行，数据不完整（GSC 帮助，访问 2026-10）。
4. **找孤岛页**：站点地图里有、抓取没找到链接指向的网址。从首页抓不到孤岛页，所以一定要把站点地图一起对比。
5. **画进结构图**：每个重点页记一行：页面网址｜层级｜点击深度｜站内入链数｜在不在站点地图｜量的日期和工具。

`click_depth.mjs` 用法：

```
node scripts/click_depth.mjs https://www.example.com/ --sitemap https://www.example.com/sitemap.xml --limit 800 --csv 结构图_20261105.csv
```

- 只跟带 href 的 `<a>`，看的是服务器返回的源代码。脚本插入的链接不算；站点导航全靠前端渲染时结果会偏深，要用浏览器抽查，报告里写明口径。
- 默认遵守 robots.txt，被禁止的网址记为「robots 禁止」。
- 抓取达到 `--limit` 时，孤岛页结果不完整，输出里会提示，汇报时要写明。
- 只抓自己负责、得到授权的站；先看站点档案里有没有限流、防火墙规则，必要时调大 `--delay`、调小 `--concurrency`。

**合格线**（经验值）：
- 重点分类页、系列页离首页不超过 3 次点击；
- 每个想被收录的页面至少有 1 个站内文字链接（Google《链接的最佳做法》2025-12-10）；
- 没有入口的页面先补链接，再提交；
- 量出来比预想深，先查是不是只能靠按钮、脚本才到得了（internal-links.md 第 1 节）。

页头下拉菜单可能把深层页拉近，但菜单里的链接要是可抓取的 `<a href>` 才算数，没实测前在结构图里标「推算」。

## 4. 收录慢时，用结构帮重点页先被发现

搜索引擎主要沿着链接发现页面。站点地图很大、收录很慢，或者平台的主动提交有每日额度时：
- 提交额度优先给分类页和重点型号页；
- 首页、导航、分类页链到重点型号，让它们离首页更近；
- 没有入口的深层页，先补链接再提交；
- 每月复查：已收录的页面里，重点页占多少。
- 「接口接收」不等于已收录。收录率低还可能是内容质量、主体资质、技术原因，交 seo-audit-remediation 一起查。

## 5. 分类怎么设计

- 按买家的选型维度分：速率、端口数、安装方式、是否带磁、是否 PoE、压力等级、材质……
- 参考大型行业分销商的类目名，它们面向的也是工程师和采购（推断）。
- 一个型号只有一个主分类、一个网址；它可以出现在多个列表里，但面包屑按主分类走。
- 分类名用买家的叫法（第 9 节）。

**单独成页的门槛**（经验值，两样都有才单独成页）：
1. 有真实型号：选型表里有料号；
2. 有独有内容：本类的说明、参数差异、问答。

缺一样：先补数据，或并入上级页。露出「待补充」占位文字、选型表筛不出料号、显示的是别的系列料号的页面，对用户和搜索引擎都没有价值。

## 6. 网址规则

新建页面时：

| 要这样 | 别这样 |
|---|---|
| 用可读的词，用受众的语言 | 会话 ID 放进网址（改用 cookie） |
| 用连字符「-」分词，不用下划线 | 用 `#` 片段切换内容（前端改用 History API） |
| 统一小写：网址区分大小写，`/APPLE` 和 `/apple` 是两个网址 | 一长串随机编号或无意义字符 |
| 参数写成「键=值」，用 & 分隔；去掉不改变内容的参数 | 同一个页面几个网址都能打开（要 301 到一个） |
| 几千个网址以上的站，同主题页面放进同一目录 | 无限组合的筛选、日历网址 |

Google 和百度的差别：

| 项目 | Google | 百度 |
|---|---|---|
| 语言字符 | 非 ASCII 要百分号编码；可用受众的语言 | 不建议用中文路径，目录名也不用中文（用英文或拼音） |
| 长度 | 文档没给上限，可读即可 | 去掉协议头后不超过 256 字节 |
| 目录层级 | 文档没限层数 | 不建议超过 2 级 |
| 参数 | 键=值、& 分隔，去掉无用参数 | 参数要少，不放会话 ID、统计代码 |
| 一页多网址 | 首选 301 到最佳版本，不能跳转再用 canonical | 一个网页只对应一个网址，其他形式 301 |

依据：Google《网址结构最佳做法》（2025-06-18 改版）、《SEO 新手指南》（2025-12-10）；百度《搜索引擎优化指南 2.0》、《百度移动搜索建站优化白皮书》（2019-11-22）。百度几份文件年份较早，没有查到更新的版本，照用。

**网址里的关键词**：Google《SEO 新手指南》（2025-12-10）说，域名和网址路径里的关键词除了显示在面包屑里，几乎没有排名作用；网址里放对用户有用的词，比随机编号好，是因为用户在结果页、分享时看得懂。网址真正要紧的是三件事：
- **可读**：用户看得懂；
- **稳定**：收录、外链、内链、站点地图都绑在网址上；
- **一致**：内链、站点地图、canonical、hreflang 都用同一个写法，大小写和结尾斜杠也一致。

所以：已收录的网址不为加词、为好看去改。带数字后缀、不好看但已收录在带流量的网址，留着。型号页的网址写料号就够了，不要把整段参数描述塞进网址。例外（经验值）：网址本身出错（带空格、大小写混用、会话 ID）才改，并按第 7 节做迁移。

## 7. 改网址按站点迁移处理

Google《网址变更的站点迁移》（2026-08-20）把网址路径变化也算作站点迁移。六步：

1. **建对照表**：旧网址 → 新网址，一一对应。
2. **服务器端 301 / 308**：302、303、307 是临时跳转，Google 通常保留旧网址；JavaScript 跳转是下策。
3. **新网址自引用**：新页面的规范网址指向自己。
4. **同步改**：站内链接、站点地图、hreflang 直接写新网址，不让站内链接经过跳转。
5. **一步到位**：不串多次跳转，最好不超过 3 跳（Googlebot 最多跟 10 跳）。
6. **长期保留**：跳转一般至少保留 1 年；观察几周到几个月。

会发生什么：永久跳转不会损失 PageRank；但迁移期间排名会暂时波动，中型站点可能要几周以上才稳定（Google《重定向》2026-04-14、《网址变更的站点迁移》）。

**对照表的检查要点**（经验做法）：
- 每条旧网址只对应一个新网址；没有对应新页的，跳到最相关的上级页，不要全部跳首页；
- 跳转后直接返回 200：不再二次跳转，不是 404；
- 对照表交技术执行前由负责人确认；上线后 1 周、1 个月各复查一次。

**怎么验**：把旧网址清单导入抓取工具的列表模式，逐条看状态码和最终网址：一次 301 就到 200 为合格；302、多次跳转、404 为不合格，返工。

**怎么读数据**：改网址的那个月，新旧网址要合起来看。只看新网址像「新增了一个爆款」，只看旧网址像「暴跌」。在搜索控制台效果报告的「网页」里用正则把新旧两个网址一起筛出来（如 `旧页面名|新页面名`）。排名波动等几周再判断；变化也受内容、季节、算法影响，不能全算到改网址头上。

**改完查三处**：站点地图（只列最终网址，不留已 301 的旧网址）、内链、hreflang；各语言版本一起查，小语种的旧网址也可能还在出展示。改的当天在搜索控制台加一条注释记日期（经验做法）。

网址、301、robots 的改动属于站点改动：只出对照表和检查结果，由负责人批准后交技术执行；对照表和复查结果存档。

## 8. 网址一旦定下，就成了依赖

网址不只是给搜索引擎看的，站里的模板、菜单、程序也可能依赖它。常见的静默故障：
- 页面里手写的网址在另一个站或另一个语言版本里不存在，菜单失效、语言切换链到 404；
- 程序按网址匹配两站的对应页，网址对不上就新建了重复页；
- 模板按栏目网址取，两站网址不同就是两份模板，只改了一份。

这类问题不报错，页面照样能打开，只是板块悄悄失效，要专门去查。规避：
- 站内链接由系统按页面生成，不手写网址；
- 多站、多语言之间按栏目编号（ID）对照，不按网址或标题去猜；
- 改网址前先查有没有模板、菜单、程序写死了这个网址。把查到的坑写进站点档案的「已知坑」。

## 9. 导航

**命名**：导航名是全站每一页都会出现的锚文本，起错了代价很大。
1. 列候选叫法；
2. 查量（没有工具就写「未知」，用下拉词）；
3. 看结果页：前排是不是我们这类产品；
4. 对照行业分销商的类目名；
5. 定名。导航名要短，更完整的说法放标题和 H1。标题和导航是两处，要分别检查。

**改名之前**：
- 先请技术确认有没有功能按栏目名找栏目（产品推荐、关联板块常这样写），改名会让板块悄悄消失；
- 多语言站改主语言的栏目名，其他语言的界面译文可能对不上；
- 能单独设置导航显示名的，只改显示名、不动栏目名，风险最小。

**形式和写法**：

| 位置 | 作用 | 写法要求 |
|---|---|---|
| 主导航（页头） | 全站入口，最稳定 | 文字链接 `<a href>`；用买家的叫法 |
| 下拉面板 | 把深层页拉近 | 分组清楚；不把全站链接都塞进去 |
| 面包屑 | 显示位置、链回上级 | 每级可点；当前页可以不链 |
| 侧栏 / 筛选 | 同级切换、缩小范围 | 筛选结果页单独处理（cannibalization-duplicates.md 第 11 节） |
| 页脚 | 补充入口 | 公司、资料、政策类链接 |

- 百度《搜索引擎优化指南 2.0》：每页都有导航；用文字链接，避免复杂 JS；图片做导航要写 alt。
- Google《链接的最佳做法》（2025-12-10）：每页链接数没有理想值，但过多很可能有问题。下拉列得越全，链接越多，每个链接分量越小：大菜单要分组精简。
- 检查：看源代码或渲染后的 HTML，导航里每一项都应该是带 href 的 `<a>`。

## 10. 面包屑

作用：显示页面在层级里的位置；每级链回上级，给上级页送入链；Google 可能在桌面端结果页显示面包屑路径（2025-01 起手机端不再显示）。

- **Google《面包屑》（2026-09-08）**：反映用户到达该页的典型路径，不必照搬网址结构，所以网址在根目录、面包屑按层级走是允许的；一个页面可以有多条路径；结构化数据至少 2 级（写法交 seo-audit-remediation）。
- **Google 人员发言（2022，媒体转述）**：设了面包屑结构化数据，内部链接仍然非常关键；结构化数据代替不了各层级之间真实的 HTML 链接。
- **百度**：内容多时用面包屑（首页 > 频道 > 当前页），要机器可读、位置突出（《搜索引擎优化指南 2.0》、移动建站白皮书 2019-11-22）。

**检查**：
- 每级都可点（当前页可以不链）；
- 页面上看得见的层级和结构化数据里的层级一致。少一级，那一级的页面就少一批入链，结构化数据也和可见内容对不上；
- 面包屑和结构化数据最好由同一份数据生成；改完抽查 10 页，看页面文字，再在源代码里搜 `BreadcrumbList`；
- 这类问题不报错、不影响打开，检查表里要单列一项。

## 11. 多语言与多站点

**四种结构**（Google《管理多地区和多语言网站》2025-12-10）：

| 结构 | 例子 | 优点 | 缺点 |
|---|---|---|---|
| 国家域名 | `example.de` | 地区定位最清楚 | 成本高，要分别维护 |
| 子域名 | `de.example.com` | 好搭建、服务器灵活 | 看不出指语言还是国家 |
| 子目录 | `example.com/de/` | 好维护、共用主机 | 地区信号弱 |
| 网址参数 | `?loc=de` | — | 不推荐 |

子域名和子目录没有天然的排名优劣，按业务选（《SEO 新手指南》）。

**五条规则**：

| 规则 | 为什么 |
|---|---|
| 1. 每种语言独立网址 | 靠 cookie 或浏览器设置在同一网址上切换，Googlebot 只看得到一个版本 |
| 2. 不按 IP、浏览器语言自动跳转 | Googlebot 多从美国抓取、不发语言偏好；改为提供语言切换链接 |
| 3. 一页一种语言 | Google 按页面可见内容判断语言，不看 lang 属性；不要并排两种语言，也不要「德语页面、英文正文」 |
| 4. 语言版本互相标注 | hreflang 或站点地图，必须双向，自己也列上 |
| 5. 机翻要有人把关 | 经翻译等自动变换批量生成、几乎不提供价值的页面，是垃圾政策（2026-08-28）举的滥用规模化内容例子 |

Google 2025-06-11 从多语言文档里删掉了「用 robots.txt 屏蔽自动翻译页面」一节，这不等于放开机翻：滥用规模化内容的规定还在（推论）。

**两个各自维护内容的站**（比如国内站和海外站各有后台、各自录入）：它们不是「一个站的两种语言」，只有内容真正对应的页面才互标 hreflang；没有对应页就不标，不要把 x-default 或另一语言指向对方首页，对方首页不会指回来，不互相指回的标注会被忽略（Google《本地化版本》2026-09-21）。x-default 是给没有对应语言版本的用户准备的兜底页。

**小语种页面的结构检查**：
- 内链只指向同语言、确实存在的页面；新增页面时同时决定有没有小语种版，没有就别从小语种页链过去；
- 小语种页可能还在用旧菜单、旧模板，点击深度要另量；
- 上线后用抓取工具把每个语言版本跑一遍，查 404；
- 每次改 hreflang，记下抽查网址、日期和结果：查看源代码里的 hreflang，逐个打开对方网址，看内容是否真的对应、对方是否指回来。复核前不说「已做对」。

hreflang 的写法和技术实现交 seo-audit-remediation。
