# 改动效果复查

搜索引擎不会告诉你哪次改动起了作用。判断改得对不对，靠一套朴素的方法：先写假设，再动手，把改动记下来，到期验证。这套方法是教材的归纳，不是搜索引擎的规定。

seo-audit-remediation 的「复测」用同一把评分尺子重量页面；这里看的是平台数据上的效果。两件事都要做，分数涨了不等于有效果。

## 1 统一标准

- 改动上线前冻结前 28 天的基线（数据导出存档，带日期）。
- 上线后第 28、56、90 天各对照一次。
- 没有冻结基线和对照数据，结论写「效果未验证」。
- 自定评分提高、已上线、验收通过，都不能代替这条。
- 同一时期叠了多个改动的，可以用 GSC 回溯补一个基线，但不能把变化归到单项上。

## 2 四步循环

1. **提出假设**，写成一句能被验证的话：「如果把 A 改成 B，C 指标会在 N 周内变化，因为 D。」写不出这句话，说明还没想清楚为什么要改。
2. **改动**：一次只改一类东西；能先在少量页面试点就先试点。
3. **记录**：写进变更记录表。
4. **验证**：到复查日，对比前后等长的时间段；先排除干扰，再下结论。

假设示例（虚构）：「如果在 /ball-valves/ 的问答里加上 trunnion mounted 的定义，那么 4 周内这一页在 trunnion 一类查询上的展示会增加，因为页面第一次出现了这个叫法。」

做对了的标志：到期能用数据回答「假设成立吗」，成立、不成立都算有结论；别人看记录能复现你改了什么。

## 3 变更记录表

表头见 [../assets/change-log.csv](../assets/change-log.csv)。一行记一次改动。

| 列 | 写什么 |
|---|---|
| 日期 | 上线日期（不是提交日期） |
| 站点 / 页面 | 网址或网址规则；涉及多少页 |
| 改动前 | 原来的样子（截图或存档位置） |
| 改了什么 | 具体到字段或板块 |
| 假设 | A → B，C 在 N 周内变化，因为 D |
| 看什么指标 | 例如「这一页在 X 类查询上的展示」 |
| 基线 | 冻结的前 28 天数据存在哪 |
| 对照组 | 同期没改的同类页面是哪些 |
| 复查日 | 第 28、56、90 天，写进日历 |
| 结果 | 到期填：数据、结论（成立 / 不成立 / 无法判断）、干扰说明 |

记录的规矩：同一页面同一时期尽量只改一类东西；做不到时，在记录里写清楚，复盘时心里有数。改动当天也在 GSC 图表上加注释。

## 4 前后对比怎么取数（GSC）

1. 效果报告，搜索类型选「网页」。
2. 日期 → 比较：改动前后各 28 天，跳过改动当天，尽量避开搜索引擎更新期。
3. 添加过滤条件：网页 = 改动的网址，或包含某个目录。
4. 在「查询」标签里看哪些词的展示、排名变了。
5. 导出数据，结论写回变更记录表的「结果」栏。

注意：数据通常延迟 2–3 天，到复查日后再等两三天，数据才齐；按查询筛选后的合计比总数少（匿名查询）；必应「搜索效果」能做类似对比；百度「流量与关键词」只到域名层级，按页面看要靠索引量目录规则和百度统计受访页面。

## 5 排除干扰

| 干扰 | 怎么识别 |
|---|---|
| 搜索引擎更新 | Google 查搜索状态面板；百度、必应看官方公告；对比的两段都避开更新窗口，避不开就在结论里写明重叠 |
| 季节与节假日 | 和去年同期比；看全站是否同时变化；国内长假前后尤其要注意 |
| 口径断点 | 后台是否改过计数方式（reconciliation.md 第 4 节） |
| 网址变化 | 改版、改网址后，新旧网址分开计数，要合并看 |
| 查询结构变化 | 平均排名受「哪些词有展示」影响，看固定词表 |
| 结果页变化 | 结果页有没有新出现 AI 概览、广告或其他模块，会分走点击 |
| 垃圾和机器查询 | 展示暴涨的词是不是人会搜的 |
| 故障与统计代码 | 看可用性记录、统计代码有没有改过 |

顺序：先查自己（故障、统计代码、改网址），再查搜索引擎（更新、口径、结果页），最后才把变化归功于自己的改动。同类页面一起涨跌时，先怀疑外部因素（推断）。

## 6 对照组

SEO 很难做严格的 A/B 测试（推断）：同一个网址在搜索引擎眼里只有一个版本，没法把用户随机分组；搜索引擎和竞争对手一直在变；抓取和收录有延迟；B2B 的词量小，几次点击的波动看起来就像大涨大跌。

能做的是尽量逼近（经验做法）：

- 分批上线：先改一部分同类页面（试点组），同期留一部分不改（对照组），比较两组的变化；
- 一次只改一个变量，观察时间要覆盖抓取和收录所需的几周；
- 收录、展示、排名、点击一起看，记下同期的外部事件；
- 判断标准：改动组的变化明显大于对照组，而且几个指标方向一致。

对照组如果不是随机挑的（例如因为数据问题才暂缓的那批页），两组本来就不一样，结论要打折扣，并写明。

## 7 结论怎么写

| 结论 | 条件 | 写法示例 |
|---|---|---|
| 成立 | 有冻结基线和对照；改动组变化明显大于对照组；方向一致；干扰已排除或已写明 | 「第 28 天：改动组 X 类查询展示 +Y%，对照组 +Z%；同期无更新；暂判成立，第 56 天再看」 |
| 不成立 | 同上条件下，改动组和对照组没有差别 | 「第 56 天两组变化一致，假设不成立；下一步……」 |
| 无法判断 | 没有基线、没有对照、多个改动叠加、窗口和更新重叠且影响大 | 「效果未验证：上线前没有冻结基线，同期还改了 Z」 |

单次复查只是一个时点，到第 90 天再定稿。不说「显著提升」这类空词，写具体数字和口径。

## 8 怎么向负责人说预期

不承诺名次、询盘翻倍、收录多少页，这些都是控制不了的结果。承诺能控制的：改什么、先看哪个指标、哪天复查、有哪些不确定。

例（虚构）：「这次改了 12 个分类页的标题和首段。先看这 12 页的展示和点击率，11 月 20 日第一次复查；同期有一次搜索引擎更新，结论可能要到第 56 天才清楚。」
