# 数据来源与统计口径

平台规则截至 2026-10，每季度按官方帮助复核一次；和官方最新文档冲突时以官方为准。

## 1 三层数据

SEO 用到的数据分三层，每层只看得到漏斗的一段。先说清你看的是哪一层，再下结论。

| 层 | 谁记 | 看得到 | 看不到 | 工具 |
|---|---|---|---|---|
| 搜索引擎侧 | 搜索引擎在自己的服务器上记 | 收录、展示、排名、点击、用户搜了什么词 | 用户进站以后做了什么 | GSC、必应网站管理员工具、百度搜索资源平台 |
| 网站侧 | 网页里的统计代码，在访客浏览器里运行 | 来源、着陆页、浏览、事件、转化 | 没加载代码、拒绝统计、被拦截的访问；多数搜索词 | GA4、百度统计 |
| 业务侧 | CRM / ERP，销售和技术支持的跟进记录 | 询盘内容、是否有效、报价、成交 | 询盘从哪来，除非表单或登记时写下来源 | CRM / ERP |

服务器访问日志是另一种来源，主要用于看抓取（技术 SEO，交 seo-audit-remediation）。三层的划分是教材的整理（参考：Search Console 帮助 96568；Analytics 帮助 9322688）。

## 2 漏斗对照：每一段用哪个工具

| 阶段 | 回答什么 | 海外站 | 国内站 | 核心指标 | 注意 |
|---|---|---|---|---|---|
| 收录 | 多少页进了索引 | GSC 网页索引报告、必应 | 百度资源平台索引量、必应 | 重点页收录率、未收录原因 | 提交 ≠ 收录；站点地图条数 ≠ 收录数 |
| 展示 | 在哪些词上被看到 | GSC 效果报告、必应 | 百度「流量与关键词」、必应 | 非品牌展示、新出现的词 | 排在后面也有展示；先剔除垃圾查询 |
| 排名 | 排第几 | GSC 平均排名 | 百度平均排名 | 目标词进前 10、前 20 的个数 | 全站平均排名会被查询结构带偏 |
| 点击 | 多少人点进来 | GSC、必应 | 百度资源平台、必应 | 点击、点击率 | 搜索引擎记的，不受统计代码影响 |
| 访问与互动 | 来了做什么 | GA4 | 百度统计 | 会话、互动率、着陆页、事件 | 受代码覆盖、同意弹窗影响 |
| 询盘 | 留没留需求 | GA4 关键事件 + CRM | 百度统计转化 + CRM | 询盘数、带来源的询盘数 | 表单、电话、邮件、即时通讯都要登记 |
| 有效询盘与成交 | 值不值钱 | CRM / ERP | CRM / ERP | 有效询盘、报价、成交 | 要销售标注有效性 |

用法：先说清看的是哪一段，问题出在哪一段就从那一段的数据查起。一段没有数（例如询盘不带来源），报告里写「未获取」，不用别的段去推算。

## 4 一手、估算、建模

| 类别 | 是什么 | 例子 | 怎么用 |
|---|---|---|---|
| 一手数据 | 平台或自家系统直接记录的 | GSC、必应、百度后台、GA4、CRM | 下结论；但要写清口径限制 |
| 估算数据 | 第三方用点击流面板、抽样和模型推算的 | 第三方的预估流量、关键词数、搜索量、收录数、权重分 | 比相对大小、看竞品趋势、找没覆盖的词；不算流量、不定 KPI；查不到本站数据不代表真实为 0 |
| 建模数据 | 平台对缺失部分的补算 | GA4 同意模式的行为建模；GA4 会话数本身是算法估算（HyperLogLog++） | 知道它不是精确计数；按行相加和总数差几个属正常 |

依据：Analytics 帮助 9191807、11161109（2026-10 访问）。

## 5 做本站数据口径表

1. 每个来源一行，列见 [../assets/data-caliber-table.md](../assets/data-caliber-table.md)：资源 / 账号、统计什么、不统计什么、延迟、保留期、谁有权限、状态、观察记录。
2. 先查自己有哪些后台权限；没有的写「无权限」，不要跳过这一行。
3. 官方没说明的格子，写观察到的情况和日期，例如「2026-10-12 读数时页面显示 53 小时前更新」。
4. 统计口径变了（换资源、加筛选、改品牌正则、改垃圾词清单、GA4 改归因设置），在表里加一行变更记录，写日期和影响。
5. 验收：每格有依据或观察日期；缺的来源写明原因。

## 6 数据盘点（每次分析前）

分析之前先盘点：哪些能用、哪些缺、缺口有多大，写在报告最前面。

| 数据源 | 状态 | 主要问题 | 能回答什么 |
|---|---|---|---|
| GSC | 已获取 / 未获取 | 例：可见查询只覆盖少部分点击 | 搜索结果里发生了什么 |
| 必应 | 未接入 / 已接入 | | |
| 百度资源平台 | | | |
| GA4 / 百度统计 | 已装代码未取数 / 已取数 | 例：代码在同意弹窗之后加载，会少计 | 站内行为的结构 |
| CRM / ERP | | 例：表单推送不带来源 | 询盘总数 |
| AI 监测 | 无 / 有基线 | | |

状态只写四种：已获取、已接入未取数、未接入、无权限。每个缺口转成一条待办，最优先的通常是：站内统计接同意模式、询盘和样品申请设成关键事件、表单带上来源。

## 7 缺数据时怎么办

原则：替代得了就用替代，并写明「用 X 替代 Y」；替代不了就写「未获取」，不编数字。

| 缺什么 | 替代 | 替代不了时 |
|---|---|---|
| GSC 没有权限 | 请有权限的人导出查询、网页两张表，或给截图；写清导出日期和筛选 | 搜索侧写「未获取」；不用第三方估算流量顶替 |
| 必应未接入 | 可从 GSC 导入站点开通（导入即验证） | 「未获取」，不写 0 |
| 百度资源平台未验证 | 百度统计里百度来源的访客只能看方向 | 搜索侧写「未获取」 |
| GA4 / 百度统计少计或未取数 | 搜索侧的量用 GSC / 资源平台 | 站内行为、转化写「未获取」 |
| 询盘不带来源 | 只报询盘总数，标「来源未知」 | 「SEO 带来几条询盘」写「未获取」 |
| 超过 16 个月的历史 | 查有没有每月存档的导出 | 「未获取」；建议从现在起每月存档 |
| 去年同期 | 16 个月内直接比；国内站用百度指数看行业趋势 | 季节一层写「未核对」 |
| 搜索量 | 关键词工具估算，只比大小 | 「未知」 |
| 没有付费工具 | 用平台自带报告和手工记录表 | 外链、竞品流量写「未获取」 |
| AI 监测没跑过 | 先按问题集跑一轮建基线 | 「暂无基线」 |

## 8 「收录了多少」怎么报

收录是最常被问、也最容易报错的数。每次报都写清三样：工具、口径、日期。

| 方法 | 是什么 | 用处 | 局限 |
|---|---|---|---|
| GSC 网页索引报告 | 「全部已知网页」与「站点地图提交的网址」两种范围的已编入数 | 看重要页收录、未收录原因 | 两种范围的数不同；只显示当前状态；有时停更几天 |
| 百度索引量工具 | 「可以被搜索用户搜索到的网站数据」；可按目录建自定义规则 | 看全站和各目录的趋势 | 最快每天、最慢每周更新；会正常波动；不是流量 |
| 百度「流量与关键词」 | 有展现的关键词 | 有展现 = 已收录且能排上 | 没展现不等于没收录 |
| 搜网址或标题 | 在搜索引擎里搜某页的完整网址或标题 | 抽查单页 | 一次一页（经验做法） |
| `site:` 指令 | 结果数是估算 | 只看个大概 | 和索引量关系未说明，数字常跳动；必应从本机查常不准 |
| 第三方「收录数」「权重」 | 第三方抓取估算 | 和竞品比方向 | 不是搜索引擎指标 |

规则：

- 报重点页收录率（已收录 ÷ 应收录），不报全站总收录数：总数里有大量本来就不该收录的网址。
- 只显示当前状态的报告（GSC 网页索引、百度索引量），每月 1 日读一次存档，否则到月底说不出上月底收录了多少。
- 引用旧读数时写报告日期，例如「8,160（报告日期 10-11，10-22 读取）」。
- 新上线的重点页，记下从上线到能搜到的天数，攒成本站的基线（经验做法）。

依据：百度搜索资源平台索引量、流量与关键词工具页（2026-10-25 访问）；Search Console 帮助「网页编入索引」报告（2026-10 访问）。
