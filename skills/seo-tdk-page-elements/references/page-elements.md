## 1. 八个位置一起说同一个主题

《Google 搜索要素》（Search Essentials，2025-12-10）：用用户会搜的词，放在页面上显眼的位置，例如标题、主标题、图片替代文本、锚文本。

| 位置 | 谁看得到 | 放什么 |
|---|---|---|
| 标题 | 结果页、浏览器标签 | 主题词 + 关键参数或限定 + 品牌 |
| 描述 | 结果页（可能） | 是什么 + 有什么 + 下一步 |
| 关键词标签 | 都看不到 | 少量准确的词，或留空 |
| H1–H3 | 读者 | 页面主题和各板块主题 |
| 网址 | 结果页、地址栏 | 简短、可读的英文词或料号 |
| 首段与正文 | 读者 | 主题词、同义叫法（提一次）、参数、问题 |
| 图片 alt、文件名 | 读屏软件、搜索引擎 | 图片里是什么 |
| 锚文本、按钮 | 读者 | 目标页讲什么 |

八个位置讲同一个主题，但不必每处重复同一个词。Google 的说法是页面应覆盖相关内容，别只重复一个词。

用法：拿一个页面逐行填出 8 个位置现在写的是什么。空着的、跑题的、全站雷同的，通常就是要改的地方。

## 2. H1

### 四条规则

| 规则 | 为什么 | 怎么判断 |
|---|---|---|
| 一页一个 H1 | 多个 H1 一般不会被罚，但主题可能被摊薄，也可能让 Google 挑错主标题（推断）。弹窗、侧栏、页脚、表单里别放 H1 | 源代码里只有 1 个 `<h1>` |
| 看得见 | 主标题要让读者、读屏软件、搜索引擎都读得到：不藏在隐藏区块里（不显示、只有 1 像素高），不做成图片 | H1 在首屏看得见，是文字不是图片 |
| 和标题意思一致 | 标题链接会参考 H1，意思一致时被替换也不跑题 | 主题词相同 |
| 写主题词 | 用买家的叫法，不写口号 | H1 里有本页主题词 |

官方怎么说：
- Google 入门指南（2025-12-10）：标题顺序对搜索不重要（对读屏软件有用）；没有理想的标题数量。
- Google 标题链接文档：让主标题最显眼，例如第一个可见 H1。
- John Mueller（2019，媒体转述，弱证据）：一页多个 H1 很常见，系统能处理。
- 必应：逻辑清晰的 H1–H6 层级和语义化 HTML。
- 百度：没找到 H 标签的官方说法。

所以「一页一个 H1」是业内通行的规则，不是搜索引擎的规定，对用户这样说。

### 标题和 H1 怎么分工

| | 标题 | H1 |
|---|---|---|
| 给谁看 | 结果页上的搜索者 | 已经进到页面的读者 |
| 写什么 | 主题词 + 参数或限定 + 品牌 | 主题词（+ 限定），一般不带品牌 |
| 长度 | 受截断影响 | 不受截断影响，但也要短 |
| 能不能一样 | 意思一致即可，不要求一字不差 | |

示意：标题 `Ethernet Transformers | Gigabit, PoE - Brand X`，H1 `Ethernet Transformers`。

反例：标题写了「供应商」，H1 和正文都没有这个词，标题说的页面接不住。微软广告博客（2025-10-08）也建议标题、H1、描述保持一致。

### 查 H1

- 查看源代码，Ctrl+F 搜 `<h1`：数个数、看写的是什么。
- 用开发者工具的元素面板点开它：是不是被隐藏。
- H1 的问题在页面上往往看不出来：藏起来的、重复的、混在弹窗里的，都要看源代码。改版上线前把「一页一个 H1」写进自动检查。

## 3. H2、H3

### 三类页面的层级

| 分类页 | 型号页 | 文章 |
|---|---|---|
| H1 [主题词] | H1 [料号] + [产品类型] | H1 [问题本身] |
| H2 怎么选：[参数 1]、[参数 2] | H2 产品参数 | H2 先给结论 |
| H2 应用场景 | H2 资料下载 | H2 原理或原因 |
| H2 参数表与资料下载 | H2 替代型号 | H2 对比表 |
| H2 常见问题 | H2 同系列对比 | H2 选型或排查步骤 |
| H3 每个问题一个 | H2 常见问题 / H3 每个问题一个 | H2 常见问题 / H3 每个问题一个 |

- 分类页 H2 按买家的决策顺序：怎么选、用在哪、参数和资料、问题。
- 型号页 H2 按买家查一个型号的顺序：参数 → 资料 → 替代 → 问答。
- 依据：Google 入门指南建议用小标题把内容分段，方便读者浏览。
- 弹窗、表单、侧栏、提交成功提示不用 H1、H2，降成 H3 或普通文字：它们会混进标题大纲。

### 小标题用词

| 示意 H2 | 读者一眼知道什么 |
|---|---|
| `[品类 A] and [品类 B] by Interface` | 产品按接口分 |
| `Datasheets, Selection Guides and Cross-References` | 能找到哪些资料 |
| `Questions About [品类 A] and [品类 B]` | 这里是产品问答 |
| `How [品类 A] Are Made and Tested` | 生产和检测（只写口径允许的） |

规则：
- H2 写板块主题或读者的问题，带上产品名、参数名；不写 Our Products、Resources 这类空话。
- 同一个主题词不要每个 H2 都出现：读着别扭，主题词组的占比也会被顶得很高。
- 产品名用买家的叫法。
- H3 放板块里的细项：每个问题、每组参数。FAQ 的 H3 用真实问法，问题从询盘记录、技术支持记录、结果页的「其他人还问了」里来。
- 反例（示意）：`Our Products`；`LAN Transformer LAN Transformer Selection`。

自查：把所有 H2 抽出来连着读，像不像一份目录。

## 4. 网址

| 来源 | 要求 |
|---|---|
| Google《URL structure best practices》2026-10-21 | 用可读的词，不用长串 ID；用受众的语言（非 ASCII 字符百分号编码）；用连字符，不用下划线；去掉不改变内容的参数；不用 # 改变内容；网址区分大小写；不放会话 ID |
| Google 入门指南 2025-12-10 | 网址里的关键词，除了显示在面包屑里，几乎没有作用 |
| 百度《优化指南 2.0》 | 尽量短、少带参数；动态或静态本身没有影响；一页一个网址，其他用 301 统一 |
| 必应指南 | 网址稳定；永久改动用 301，302 只用于不到 2 天的临时变动 |

新页面建网址（示意）：
- ✓ `/lan-transformers/`、`/a1234/`：英文词、连字符、全小写；
- ✗ `/LAN_Transformers/`（大写、下划线）；
- ✗ `/p.php?id=123&sid=…`（参数、会话 ID）。

已有网址：
- 系统加了数字后缀的网址（如 `/poe-transformer3454/`），可读部分已经够用，为去掉数字而迁移不值得（推断）。
- **改网址 = 迁移**：新旧一一对应、301、更新内链和站点地图、hreflang；中型站点可能要几周以上才稳定（Google 迁移文档 2026-08-20）。迁移交给 seo-audit-remediation。
- 改之前问三个问题：旧网址有没有排名和外链？能不能做 301？内链、站点地图能不能同步改？三个都是「能」再改。
- 改完看数据：新旧网址在 GSC 里是两行，要合起来看，否则会误判成「新增」或「下降」。改网址本身通常不带来排名。

## 5. 首段

四条规则：
1. 第一句出现本页主题词，用买家的叫法。
2. 前两句写清：是什么、关键参数或选项、适合谁。
3. 其他同义叫法在首段或问答里自然提一次，不堆砌。
4. 问题页开头一两句直接回答；关键信息写成文字，不藏在折叠标签、图片、PDF 里。

依据：微软广告博客 2025-10-08；必应指南（关键信息放靠前位置）。描述被搜索引擎换掉时，摘要常从正文里取（推断），这也是首段要点题的原因。

示意写法：
- 英文分类页：`Ethernet transformers (also called LAN transformers) sit between the Ethernet PHY and the RJ45 port. This page lists 10/100/1000BASE-T and 2.5G parts, including PoE types, by speed, port count and package.`
- 中文分类页：`网络变压器（也叫网口变压器、以太网变压器）用在 PHY 芯片和 RJ45 网口之间。本页按速率、端口数和封装列出百兆、千兆、2.5G 型号，含 PoE 型。`

身份句：分类页的 H1 下一句写我们是什么身份（按口径文件，见 titles.md 第 6 节）。

标题说的，正文要接得住：标题里的词（品类叫法、身份词），首段或正文里要出现。

自查：把首段第一句单独读：看得出讲什么、给谁用吗？主题词在不在、是不是买家的叫法？同义叫法有没有带一次？

## 6. 正文用词与「密度」

### 官方怎么说

| 来源 | 说法 |
|---|---|
| Google《How Search works: Ranking results》 | 关键词在标题或正文里是最基本的相关性信号；但页面应覆盖相关内容，而不是重复同一个词 |
| Google 垃圾政策（2026-08-28） | 关键词堆砌：为操纵排名堆砌关键词或数字，如无附加价值的电话号码列表、罗列城市和地区、不自然地重复同一词句 |
| 百度 | 优化指南、标题规范、质量标准都没有密度数值，只要求不堆砌；内容页标题同一表述重复不超过 3 次 |
| 必应 | 过度重复、塞无关关键词、刻意设计的语言属于违规 |
| 「密度 2%–8%」 | 从业者说法，没有官方依据，不采用 |

结论：官方文档里没有密度数字，要求的是覆盖相关内容、别堆砌。**不设密度目标，也不设单个词的比例上限。**

Google 的理解类系统（神经匹配、RankBrain）能把同义说法对上，2026-07 的生成式 AI 优化指南也说不必覆盖每一种问法；但通篇不写买家最常用的叫法，相关性和点击率仍会吃亏。关键区别（带不带某个部件、速率、方向）要写清，差一个词意思可能相反。

### 用词覆盖：每类词各有位置

以一个分类页为例（主题词 ethernet transformer，示意）：

| 词在本页的角色 | 例子 | 放在哪里 |
|---|---|---|
| 主题词 | ethernet transformer | 标题、H1、首段第一句；网址不为它改 |
| 同义叫法 | lan transformer、ethernet magnetics、network transformer | 首段或问答各提一次；应用领域页用这些叫法写正文、链回本页 |
| 辅助词：参数限定 | 10/100/1000BASE-T、2.5G、PoE、SMD | 标题限定、参数表、筛选项（不设个数） |
| 辅助词：应用限定 | 交换机、工业以太网、PoE 供电设备 | 应用板块；链接到应用页 |
| 别页的词：只放链接 | ethernet magnetics explained（信息词） | FAQ 的 H3；链接到承接它的文章 |

- 主题词取量最大、最贴近买家的叫法（交给 seo-keyword-research / seo-keyword-mapping 定）。
- 一页一个主题：已经有承接页的词，本页只放链接；新词先查对照表，再决定写不写进本页。
- 把别的页面的词全铺进一页（例如为「覆盖」几十个目标词把它们全写进首页），主题会被稀释，还会和承接页抢词，重复太多有堆砌风险。字数本身不是指标，不为放词扩写。

### 「主题词组密度」只作内部检查

- 定义：本页主题词及其变种、衍生、长尾词合成一组，按不重叠的最长匹配，算它们在正文里占的字数比例。
- 只这样用：找覆盖不足（缺哪些同义叫法、参数、买家问法）；数值偏高当风险（例如改写后某批页面平均到 6% 左右），逐页朗读，排查不自然的重复。
- 不这样用：不设目标、不设上限；不拿数值涨了当效果（看 GSC）；不为凑数值加词；换了工具或口径不能横比。

不用数数的检查：朗读一遍。读着别扭、同一个词挨着出现，就换成同义词或代词。

## 7. 图片：alt、文件名、图里的字

### 官方建议

| 来源 | 建议 |
|---|---|
| Google《Google image SEO best practices》2026-03-02 | 从 `<img>` 的 src 找图片（也可用图片站点地图），不收录 CSS 背景图；alt 是最重要的元数据，有信息量、不堆词；文件名简短有描述；放在相关文字附近；响应式图片保留 src。2026-03-02 新增：缩略图参考 schema.org 标记和 og:image，不要选 logo 这类通用图 |
| Google《Link best practices》2025-12-10 | 图片作链接时，alt 就是锚文本；alt 为空就没有锚文本 |
| 百度《优化指南 2.0》 | 图片加 alt |
| 必应指南 | 描述性的文件名、alt、说明文字；图片不应是理解主题的唯一信息来源 |

Google 文档里的 alt 例子：没有 alt ✗；`alt="puppy dog pup puppies …"` 塞满关键词 ✗；`alt="puppy"` 太笼统 △；`alt="Dalmatian puppy playing fetch"` 具体写出图里是什么 ✓。

### 按图的类型写

| 图 | alt（示意） | 文件名（示意） |
|---|---|---|
| 产品实物图 | `A1234 single-port RJ45 jack with LEDs` | `a1234-rj45-jack.webp` |
| 外形尺寸图 | `A1234 dimension drawing (mm)` | `a1234-dimensions.svg` |
| 脚位图 | `A1234 pin assignment` | `a1234-pinout.svg` |
| 典型应用电路 | `A1234 typical application circuit` | `a1234-application-circuit.svg` |
| 中文站产品图 | `A1234 千兆网络变压器实物图` | `a1234-lan-transformer.webp` |
| 公司 logo | 公司名，和结构化数据、页脚写法一致 | — |

一句话：alt 写「哪个料号 + 什么产品 + 什么图」，不写口号、不堆词。判断：把图片遮住只读 alt，能知道图里是什么、是哪个料号。

文件名：`my-new-black-kitten.jpg` 优于 `IMG00023.JPG`。上线后文件名就是图片网址的一部分，改名等于换网址。

### 比 alt 更重要：参数写成文字

- 参数写成网页文字，不只放在图片或 PDF 里。图里的参数不能指望搜索引擎和 AI 读出来当正文用（推断），买家按参数搜可能找不到你。
- 检查：在源代码里能搜到参数值（如 `1500 Vrms`、`PN16`），才算写成了文字。

### 图里的字也是页面内容

图片里的字、alt、文件名，口径和真实性要求和正文一样。审稿时它们不在文字稿里，最容易漏：
- logo 或横幅图里印着最高级口号（best 之类）：口径禁用词，图片里的字一样算；
- 页脚放了别家公司的标志，或认证机构不许企业使用的组织标志：容易误导，认证用文字写，按口径文件；
- 客户 logo 墙：口径允许保留的，页面文字和 alt 也不写客户名（除非口径登记过）；
- 图库图、效果图当「工厂实拍」用：图片要真实；
- 产品图加电话水印、图片里嵌联系方式：百度细雨 2.0 打击；联系方式写成文字，放联系页。

审稿清单加一项：页面上每张图的文字、alt、文件名都过一遍口径，包括 logo、页脚图标和证书图。

## 8. 锚文本与按钮文字

### 写法

| 不好 | 为什么 | 改成（示意） |
|---|---|---|
| Click here / 点击这里 | 不说明去哪 | `LAN transformer selection guide` |
| Read more / 了解更多 | 同上，全站重复 | `Read the PoE transformer guide` |
| `lan transformer lan transformers ethernet transformer` | 堆砌，违反垃圾政策 | `LAN transformers` |
| 几个链接挨着连成一串 | 难读，目标不清 | 分开放进相关的句子 |
| 图片链接没有 alt | 没有锚文本 | alt 写目标页的主题 |

Google《Link best practices》（2025-12-10）要点：
- 只抓带 href 的 `<a>`；
- 锚文本描述性、简洁，和两端页面都相关；单独读也能看懂；
- 链接前后的文字也有作用；
- 付费链接用 sponsored，用户内容用 ugc（或 nofollow）。

百度《优化指南 2.0》：锚文本要告诉用户目标页的主题，越清楚越好。

### 按钮

- 按钮也是链接，必须是带 href 的 `<a>`，不能只靠点击事件跳转：Google 只抓带 href 的链接，纯脚本按钮抓取不到。
- 按钮文字就是锚文本，写目标页讲什么，不要每个按钮都写同一句。
- 按钮做成什么样子（描边、实心、箭头图标）是设计约定，不是 SEO 规则。

### 锚文本也在帮目标页写标题

- 指向本页的锚文本是 Google 标题链接的来源之一，站内链接的文字写目标页的主题词。
- 同一个词的锚文本只指向一个页面，否则在链接层面制造抢词。对照表旁边加一列「指向它的链接」，上线前查别的页面有没有在用同一段锚文本（内链怎么布局交给 seo-keyword-mapping）。

自查：把本页所有锚文本列出来单独读一遍：看得懂去哪吗？同一个词是不是指向了两个页面？目标页标题和指向它的锚文本，说的是同一件事吗？
