# 智码航短视频三步主流程与可选评论步骤

本技能有三个固定生产步骤和一个可选评论步骤。不要把第二步和第三步合并，也不要把第三步误解为评论：第二步交付成片与视频号发布包，第三步只发抖音、B站、YouTube；评论不是固定流程，只有用户明确要求后才处理。

## 固定契约

### 第一步：先确认文案，再生成音频

第一步必须先把本期完整口播文案展示给用户确认。即使用户已经给出一段可直接朗读的文字，也要原样回显为待确认文案；未收到用户明确的“确认”“可以”“就按这版”等答复前，不运行任何 TTS、不生成试音，也不把文案记为锁定稿。

第一步分两段执行：

1. 定位本期视频编号、周目录和过程目录；可以从仓库与上一期体例查明时，不追问用户。
2. 用户给出完整文案时保持原文；用户只给主题、图片或原始素材并要求据此制作时，整理一版完整口播，不额外提供多套候选，除非用户明确要求。
3. 向用户展示将被逐字转成语音的完整文案、目标或预计时长及必要的事实边界，状态记为 `COPY_PENDING_CONFIRMATION`，停止并等待用户确认。此时不得创建 MP3、WAV 或任何试音文件。
4. 用户修改文案后，合并修改并再次展示完整新版，继续等待确认；只有用户明确确认当前完整文本后，才把状态记为 `COPY_LOCKED`。
5. 默认走免费 TTS，沿用最近一期已验收的音色、语速和输出格式；没有可复用记录时，使用免费的普通话女声与适合短视频的正常偏快语速。不得因为本技能被调用而启动计费视频或 TTS 服务。
6. 按确认后的锁定稿逐字生成 MP3 和 WAV，核对专有名词、数字、首句、末句、时长、采样率和声道。
7. 把文件保存到本期 `wN/prod/...` 过程目录，报告绝对路径和实测规格。
8. 状态到 `AUDIO_VERIFIED` 后停止，等用户拿音频制作视频。

文案有明显事实风险时，在确认文案前说明并体现在待确认稿中。锁定后发现必须修改的事实问题时，先给出完整修订稿并重新取得确认，不能静默改稿后直接重做 TTS；只有涉及无法安全执行的内容时才停止。

第一步读取 [references/production.md](references/production.md) 的证据盘点、文案联动和 TTS 章节。

### 第二步：用户给视频，完成后期并交付视频号发布包

用户交回源视频并说“视频做好了”“继续第二步”“加字幕”或同等意思，只授权完成本地后期、三版封面、正式归档和四平台物料。第二步不上传任何平台，正常终点固定为 `PACKAGE_READY`：把终版视频与视频号发布物料交给用户，由用户手工发布视频号；抖音、B站、YouTube 必须等第三步指令后再发布。

该授权只适用于能通过视频编号、锁定稿、第一步音频和源视频确认属于同一期的智码航短视频链路。无法确认连续关系，或只是与本系列无关的普通字幕任务时，不继承本流程的归档与后续发布约定。

仅收到文件但没有继续制作的意思，不视为第二步授权。用户明确要求“只做预览”时，只完成本地字幕终版和视频质检，状态记为 `PREVIEW_READY`；不提前制作平台封面/文案、不写正式归档、不上传。用户说“视频不行”“我要重做”“等我做好了再发”或同等意思时，立即把当前源片、终版和发布包标记为不可继续发布，状态记为 `SOURCE_REDO_PENDING`，等待新源片；不得用旧包执行第三步。

第二步连续完成：

1. 只读盘点源视频、第一步音频、锁定稿、字幕源文件、用户明确指定或当前已验收的同规格三版平台封面及其生成脚本/模板、平台物料、账号状态和 Git 脏状态。用户已经指出有问题的封面不得继续作为样式基准。
2. 用 `ffprobe` 验证源视频，确认内嵌音轨与锁定稿/第一步音频的关系；用户给的是稳定源片时，不重新生成数字人、不擅自换声或变速。
3. 从稳定源片一次生成终版：校准字幕时间轴，烧录字幕和显式 AI 角标，混入已有权利依据的系列 BGM，输出 1080×1920 成片。字幕覆盖完整实际口播，包括第一句；“标题不要写进字幕”是指不得把封面标题、文档标题、栏目名等未口播元数据额外写入字幕。即使第一句口播与标题文字重合，也必须按口播正常生成和烧录字幕。
4. 沿用用户明确指定或当前已验收的统一样式制作视频号/抖音 3:4、B站 4:3、YouTube Shorts 9:16 三版平台封面，并生成四平台锁定标题、正文/简介、标签、AI 声明和内部归因记录。评论草稿不属于第二步默认交付；只有用户已经明确要求发布后评论或提前准备评论时才生成。四平台正文/简介默认只围绕本期视频内容，不自动加入智码航、引见 YinJen、偕行 Stride、产品能力、价格、试用、官网/产品链接、关注主页等公司或产品营销信息。获明确要求后生成的评论只补充来源、事实边界、清单、解释或问题，不追加营销 CTA、产品介绍、官网/产品链接或“官网见主页简介”。本期主题本身是相关公司/产品时，只写理解该主题必需的中性名称与可核验事实，仍不得自动添加价格、试用、自有官网/产品链接、主页引导或 CTA；只有用户明确要求本期加入营销时，才允许这些推广元素并核对动态事实。不得把平台营销文案自动混入口播或字幕，如需口播必须回到第一步展示完整新版并重新确认。封面允许更换底图、适配构图和本期标题文案，但同规格标题区的黑底/遮罩、字体、字重、颜色、描边、行距、对齐和相对位置必须保持同一模板。B站 4:3 使用独立横版文件，并按当前统一基准采用左侧近黑标题区、右侧人物区，不用竖图居中加模糊柱或人物居中叠全幅大字。YouTube Shorts 固定制作并归档 `封面-youtube-shorts.png`（1080×1920），留待第三步上传；标题块须避开右侧操作列和底部标题/频道信息区。普通 YouTube 16:9 专用图仍不制作。YouTube 标题、简介、标签和评论默认只写中文，不追加成段英文译文；本期内容确需出现的产品名、人物名、技术缩写、命令与外部事实来源 URL 按原样保留，自有官网/产品 URL 仍受上述无营销规则约束，只有用户明确要求英文或双语时才覆盖语言默认。视频号短标题必须先按 Unicode 字符逐字计数并保证不超过 16 字。普通排版与文案适配不再逐项请求确认；预览分支跳过本步。
5. 运行 `scripts/verify_package.py`，完整解码并人工核对首尾、字幕切点、口型、BGM 和角标；逐条确认完整口播（含第一句）都有对应字幕，同时没有混入任何未口播的封面标题、文档标题或栏目名，并将本期三版平台封面分别与用户指定或当前已验收的同规格基准并排检查标题区样式和裁切安全区；YouTube Shorts 版还要缩略核对右侧操作列与底部信息区。预览分支使用不带封面参数的视频验收。未达到 `FINAL_QA_PASS` 不得交付发布包或预览；能安全修复时从稳定源片修复后重验。
6. 更新成片归档、发布物料和 README，状态记为 `PACKAGE_READY`；向用户提供终版、视频号 3:4 封面、视频号标题/简介/AI 声明清单以及其余三平台物料，然后停止。第二步不得打开平台上传页、提交公开视频、发送评论或尝试置顶；预览分支只保留过程目录中的预览终版。

第二步授权不包含任何计费的 TTS、数字人或视频重生成。源片失败且只能通过计费重生修复时，保留诊断证据并停下来取得新的明确授权。

第二步读取：

- 后期与质检：[references/production.md](references/production.md)
- 四平台物料与视频号交付规范：[references/platform-release.md](references/platform-release.md)
- `work-ledger` 归档与台账：[references/work-ledger.md](references/work-ledger.md)

### 第三步：只发布抖音、B站、YouTube

用户在第二步 `PACKAGE_READY` 后说“继续第三步”“视频号我发了，你发剩下三个平台”“发抖音、B站、YouTube”或同等意思，即授权发布本期最终包到 **抖音、B站、YouTube**。第三步永远排除视频号；视频号由用户手工发布，用户未提供可靠分享 URL 时只记录“用户已发布 / URL 待补”，不能猜链接。

“视频做好了”“等我做好了再发”或用户正在重做视频，不等于第三步授权。用户否定当前视频或发布包后，必须停在 `SOURCE_REDO_PENDING`；只有新源片重新走完第二步并再次达到 `PACKAGE_READY`，用户再明确启动第三步，才可上传。

第三步连续完成：

1. 读取本期 `PACKAGE_READY` 终版、三版封面、锁定平台物料和台账，核对文件时间、视频编号、时长、锁定稿与第二步 QA 证据，确认包未被替换或判废；有变化就退回第二步重验。
2. 只处理抖音、B站、YouTube；用户明确指定部分平台、私密或定时时，以本轮指令覆盖默认值。不得打开视频号发布页或代替用户发布视频号。
3. 按平台逐一上传；抖音默认开启“同步发布到今日头条”。公开提交前从实际表单逐项读回并比对非空的标题、正文/简介、实际封面文件或视频帧、AI 声明和可见性，并逐字确认正文/简介没有混入默认禁止的公司或产品营销内容；同步分发只在抖音实际提供该字段时核对。
4. 提交后获取准确公开 URL，从前台核对标题、账号、时长和可见性/审核状态；上传 100%、处理完成、草稿或已提交不能代替公开核验。
5. 每完成一个平台立即回填台账，再继续下一个。三个目标平台全部公开核验后记为 `PUBLISHED_COMPLETE`，部分完成记为 `PUBLISHED_PARTIAL`；评论栏默认记为“未请求”，不得自动转入 `COMMENTS_PENDING`。
6. 三个平台都完成发布尝试并记录结果后，第三步停止。只有用户已经在本轮明确要求“发布后加评论”，或随后明确说“继续第四步”“给平台加评论”等同等意思，才进入第四步；没有该指令时不发送评论、不尝试置顶，也不为评论再次请求确认。用户明确说“不需要评论”时记为 `COMMENTS_WAIVED`。第三步不得重新剪辑成片或修改未获授权的公开视频；发现媒体问题时停止发布受影响平台并退回第二步。

第三步读取 [references/platform-release.md](references/platform-release.md) 的三平台发布步骤和 [references/work-ledger.md](references/work-ledger.md) 的台账口径；不重新运行视频制作，除非包发生变化并退回第二步。

### 第四步（可选）：给已发布平台增加评论

用户明确说“继续第四步”“给平台加评论”“发布后加评论”或同等意思，才授权第四步：对其中已取得可靠公开 URL 的平台发送发布物料中的锁定评论，并在平台允许时尝试置顶。第三步授权不包含评论，评论也不是默认或固定交付；没有明确第四步指令就保持“未请求”并停止。用户说“不需要评论”“这期不评论”时记为 `COMMENTS_WAIVED`，本期不再追问、补发或尝试置顶。视频号只有在用户提供准确公开 URL 并可核对目标后，才纳入第四步。

第四步连续完成：

1. 从本期发布物料读取各平台公开 URL、实际标题、账号、归因要求和当前评论状态；已有锁定评论时使用锁定稿，没有时按本节规则生成并回填。用户指定部分平台时只处理指定范围，否则处理本期所有已公开平台。
2. 逐个平台打开准确的公开 URL，重新核对标题、账号和视频 ID；审核中、URL 待补或无法确认对象的平台暂停评论，不能凭列表顺序猜目标。
3. 先检查同一锁定评论是否已经存在，避免重复发送；如用户或平台已改过评论，以公开页实际状态为准并回写台账。
4. 发送锁定评论并确认公开可见；抖音评论保持单行，不能用回车提交。
5. 平台提供置顶入口且授权条件满足时尝试置顶，并以明确置顶标识、成功提示或菜单变为“取消置顶”为证据；网页版无入口、验证码或手机 App 专属操作则记录待用户处理。
6. 每完成一个平台立即回填“评论已发 / 已置顶 / 待用户处理”，继续其他可安全完成的平台。第四步不重新上传视频、不修改公开视频文案或封面。

第四步只读取 [references/platform-release.md](references/platform-release.md) 的评论步骤和 [references/work-ledger.md](references/work-ledger.md) 的台账口径；不需要重新运行视频制作与质检。

## 第二步、第三步与第四步的授权及停止条件

`PACKAGE_READY` 是第二步的正常终点，不是发布前的瞬时状态。第二步必须交付本地成片和视频号发布包后停止；只有用户明确启动第三步，才发布抖音、B站、YouTube。第三步的三个目标平台都完成发布尝试并记录结果后停止，不自动评论。只有用户明确启动第四步，才对已取得可靠公开 URL 的平台发送评论；用户明确放弃评论时记为 `COMMENTS_WAIVED`，不再追问或补做。

用户否定当前视频、说要重做或要求等待时，当前发布包立即停止使用，状态进入 `SOURCE_REDO_PENDING`。新的源片必须重新执行第二步；旧的 `PACKAGE_READY` 和旧的第三步授权都不能沿用。

以下情况只暂停受影响的平台或动作，并继续能安全完成的其他平台：

- 登录失效、验证码、实名、频道验证或手机 App 专属操作；
- 平台审核、上传处理或安全策略暂时阻断；
- 账号/频道无法可靠确认；
- 某项素材没有可复核的权利依据；
- 源片、口型、字幕或声音没有通过质检。

不得绕过验证码、身份验证或平台安全策略。阻断时保留已完成结果，准确记录 `待用户处理`、`审核中` 或 `PUBLISHED_PARTIAL`，不要把上传、草稿或处理中写成发布成功。

## 证据状态

主流程与可选评论步骤使用以下状态：

```text
第一步：INPUT_UNVERIFIED → COPY_PENDING_CONFIRMATION → COPY_LOCKED → AUDIO_VERIFIED
第二步：SOURCE_READY → FINAL_QA_PASS → PACKAGE_READY
重做回退：SOURCE_READY / PACKAGE_READY → SOURCE_REDO_PENDING → 新源片 SOURCE_READY
预览覆盖：SOURCE_READY → FINAL_QA_PASS → PREVIEW_READY
第三步：PACKAGE_READY → PUBLISHED_PARTIAL / PUBLISHED_COMPLETE
默认收口（没有请求评论）：PUBLISHED_COMPLETE → LEDGER_CLOSED（评论状态保持“未请求”）
第四步（仅明确授权）：PUBLISHED_PARTIAL / PUBLISHED_COMPLETE → COMMENTS_PENDING → COMMENTS_PARTIAL / COMMENTS_COMPLETE → LEDGER_CLOSED
用户明确放弃评论：PUBLISHED_PARTIAL / PUBLISHED_COMPLETE → COMMENTS_WAIVED → LEDGER_CLOSED
可选 Git：GIT_COMMITTED → GIT_PUSHED
```

第三步的 `PUBLISHED_COMPLETE` 只表示抖音、B站、YouTube 三个目标平台均已公开核验，不代表视频号 URL 已取得，也不表示评论已发送；视频号按用户回传证据单独记录。没有请求评论时，`PUBLISHED_COMPLETE` 是完整的主流程终态，可在回填证据后进入 `LEDGER_CLOSED`，评论状态保持“未请求”；明确启动评论步骤后，须在评论结果收口后再关闭；用户明确放弃评论时先记为 `COMMENTS_WAIVED`，再进入 `LEDGER_CLOSED`。

文件名叫“终版”、上传达到 100%、后台显示“已提交”或计划写了 URL，都不能替代实际证据。发布成功必须取得公开 URL，并从前台核对标题、账号、时长和可见性/审核状态。

## Git 边界

第三步三平台发布和另行授权的第四步评论都不包含 Git。保存文件不等于暂存，暂存不等于提交，提交不等于推送。只有用户明确说 commit、提交或 push 时才执行对应 Git 操作；始终保护工作区里用户原有修改，只暂存授权范围内的文件。

## 每步收口

第一步等待文案确认时报告：

- 将被逐字转成语音的完整文案；
- 目标或预计时长及必要的事实边界；
