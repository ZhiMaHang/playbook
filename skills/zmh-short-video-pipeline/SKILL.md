# 智码航短视频两步流水线

本技能只有两个生产步骤。不要重新扩展成选题、文案提案、数字人生成、发布包确认等多轮流程。

## 固定契约

### 第一步：用户给文案，生成音频

用户给出的口播文案就是本期锁定稿。除非用户明确要求改文案，否则不改写、不再让用户确认，也不启动视频生成。

直接完成：

1. 定位本期视频编号、周目录和过程目录；可以从仓库与上一期体例查明时，不追问用户。
2. 默认走免费 TTS，沿用最近一期已验收的音色、语速和输出格式；没有可复用记录时，使用免费的普通话女声与适合短视频的正常偏快语速。不得因为本技能被调用而启动计费视频或 TTS 服务。
3. 逐字生成 MP3 和 WAV，核对专有名词、数字、首句、末句、时长、采样率和声道。
4. 把文件保存到本期 `wN/prod/...` 过程目录，报告绝对路径和实测规格。
5. 状态到 `AUDIO_VERIFIED` 后停止，等用户拿音频制作视频。

文案有明显事实风险时可以提示，但第一步的任务仍是按用户原文配音；只有涉及无法安全执行的内容时才暂停。

第一步读取 [references/production.md](references/production.md) 的证据盘点、文案联动和 TTS 章节。

### 第二步：用户给视频，加字幕并直接上架

用户在这套两步流程中交回源视频，并说“视频做好了”“继续第二步”“加字幕”或同等意思，即表示授权本轮完成后期并直接发布到本系列默认平台：**视频号、抖音、B站、YouTube**。不再停下来询问“是否发布”。这是用户明确写入本技能的常驻默认授权，不是从“加字幕”三个字临时推断出来的授权。

该默认只适用于能通过视频编号、锁定稿、第一步音频和源视频确认属于同一期的智码航两步链路。无法确认连续关系，或只是与本系列无关的普通字幕任务时，不继承四平台发布授权。

用户明确说只发部分平台、设为私密或定时发布时，以本轮指令覆盖默认值。仅收到一个文件但没有继续制作的意思，不视为发布授权。用户明确要求“只做预览”时，只完成本地字幕终版和质检，状态记为 `PREVIEW_READY`；不提前制作平台封面/文案、不写正式归档、不上传。用户说“先别发布”或“暂不上传”时，只撤回平台上传与公开提交；本地仍制作两版平台封面、四平台文案和正式发布包，完成后停在 `PACKAGE_READY`。若同句明确要求只看成片、不做发布包，则按预览分支处理。

第二步连续完成：

1. 只读盘点源视频、第一步音频、锁定稿、字幕源文件、用户明确指定或当前已验收的同规格两版平台封面及其生成脚本/模板、平台物料、账号状态和 Git 脏状态。用户已经指出有问题的封面不得继续作为样式基准。
2. 用 `ffprobe` 验证源视频，确认内嵌音轨与锁定稿/第一步音频的关系；用户给的是稳定源片时，不重新生成数字人、不擅自换声或变速。
3. 从稳定源片一次生成终版：校准字幕时间轴，烧录字幕和显式 AI 角标，混入已有权利依据的系列 BGM，输出 1080×1920 成片。字幕覆盖完整实际口播，包括第一句；“标题不要写进字幕”是指不得把封面标题、文档标题、栏目名等未口播元数据额外写入字幕。即使第一句口播与标题文字重合，也必须按口播正常生成和烧录字幕。
4. 默认直接上架分支和“先别发布”的发布包分支都沿用用户明确指定或当前已验收的统一样式制作 3:4、B站 4:3 两版平台封面，并生成四平台锁定标题、简介、标签、AI 声明、归因和评论。封面允许更换底图、适配构图和本期标题文案，但同规格标题区的黑底/遮罩、字体、字重、颜色、描边、行距、对齐和相对位置必须保持同一模板。B站 4:3 使用独立横版文件，并按当前统一基准采用左侧近黑标题区、右侧人物区，不用竖图居中加模糊柱或人物居中叠全幅大字。YouTube 不制作、归档或上传专用缩略图，包括 16:9 横图和 Shorts 9:16 图；只保留标题、简介、标签、AI 声明、归因和评论等文字物料。YouTube 标题、简介、标签和评论默认只写中文，不追加成段英文译文；产品名、人物名、技术缩写、命令与 URL 按原样保留，只有用户明确要求英文或双语时才覆盖。视频号短标题必须先按 Unicode 字符逐字计数并保证不超过 16 字。普通排版与文案适配不再逐项请求确认；预览分支跳过本步。
5. 运行 `scripts/verify_package.py`，完整解码并人工核对首尾、字幕切点、口型、BGM 和角标；逐条确认完整口播（含第一句）都有对应字幕，同时没有混入任何未口播的封面标题、文档标题或栏目名，并将本期两版平台封面分别与用户指定或当前已验收的同规格基准并排检查标题区样式和裁切安全区。预览分支使用不带封面参数的视频验收。未达到 `FINAL_QA_PASS` 不得公开发布或交付预览；能安全修复时从稳定源片修复后重验。
6. 默认直接上架分支在质检通过后立即按平台逐一上传、公开提交、核验公开 URL、发送评论并尝试置顶；每完成一个平台就立刻回填台账，再继续下一个。预览分支跳过本步。
7. 默认直接上架分支更新成片归档、发布物料和 README，报告每个平台的真实结果；发布包分支完成同样的本地归档与物料后停在 `PACKAGE_READY`，不上传、不评论；预览分支跳过本步，预览终版只留在过程目录。

第二步授权不包含任何计费的 TTS、数字人或视频重生成。源片失败且只能通过计费重生修复时，保留诊断证据并停下来取得新的明确授权。

## 第二步的发布授权与停止条件

`PACKAGE_READY` 在默认第二步只是发布前的瞬时状态；只有用户明确要求先不发布但仍要发布包时，它才是本轮合法终点。只要用户没有撤回平台发布，就继续推进到 `PUBLISHED_COMPLETE` 或真实阻断；用户明确要求只做预览时，`PREVIEW_READY` 是合法终点。

以下情况只暂停受影响的平台或动作，并继续能安全完成的其他平台：

- 登录失效、验证码、实名、频道验证或手机 App 专属操作；
- 平台审核、上传处理或安全策略暂时阻断；
- 账号/频道无法可靠确认；
- 某项素材没有可复核的权利依据；
- 源片、口型、字幕或声音没有通过质检。

不得绕过验证码、身份验证或平台安全策略。阻断时保留已完成结果，准确记录 `待用户处理`、`审核中` 或 `PUBLISHED_PARTIAL`，不要把上传、草稿或处理中写成发布成功。

## 证据状态

两步分别使用以下状态：

```text
第一步：INPUT_UNVERIFIED → COPY_LOCKED → AUDIO_VERIFIED
第二步默认：SOURCE_READY → FINAL_QA_PASS → PACKAGE_READY → PUBLISHED_PARTIAL / PUBLISHED_COMPLETE → LEDGER_CLOSED
发布包覆盖：SOURCE_READY → FINAL_QA_PASS → PACKAGE_READY
预览覆盖：SOURCE_READY → FINAL_QA_PASS → PREVIEW_READY
可选 Git：GIT_COMMITTED → GIT_PUSHED
```

文件名叫“终版”、上传达到 100%、后台显示“已提交”或计划写了 URL，都不能替代实际证据。发布成功必须取得公开 URL，并从前台核对标题、账号、时长和可见性/审核状态。

## Git 边界

直接上架只授权平台发布，不授权 Git。保存文件不等于暂存，暂存不等于提交，提交不等于推送。只有用户明确说 commit、提交或 push 时才执行对应 Git 操作；始终保护工作区里用户原有修改，只暂存授权范围内的文件。

## 每步收口

第一步报告：

- MP3、WAV 的绝对路径；
- 时长、编码、采样率、声道和试听核对结果；
- 明确说明没有启动视频生成。

第二步报告：

- 终版、两版平台封面和发布物料的绝对路径；
- 视频号、抖音、B站、YouTube 各自的公开 URL、AI 声明、评论和置顶状态；
- 仍受验证码、审核或客户端限制的具体项目；
- 归档与台账状态；
- Git 是否未操作、已提交或已推送，以及可验证 SHA。

若用户选择预览覆盖，只报告过程目录中的预览终版、视频专项 QA 结果和 `PREVIEW_READY`；不得把尚未制作的平台资产、正式归档或平台 URL 写成待完成的默认交付。

若用户选择“先别发布”的发布包覆盖，报告终版、两版平台封面、四平台物料、正式归档和 `PACKAGE_READY`，并明确说明没有进行上传、评论或公开提交。

不要用“全部完成”概括部分平台，也不要在第二步质检通过后无故停在“等你确认发布”。
