# 人物口播、辅助素材与特效字幕模板 v3

每期默认采用人物口播＋一份用户提供的辅助素材＋特效字幕。用户提供截图、录屏或示意图中的一种即可，本技能将其插入匹配的讲解位置，口播声音持续，配完整字幕、关键词高亮与适量轻动效。人物源片沿用既定分工：分镜图片交给 Image 2.5 生成，用户在自己的 PC 上通过 ComfyUI 生成口播视频，交回后统一后期。用户的本期明确指令覆盖默认。

这是制作与交接规范，不是已经实现的自动渲染器或可直接导入的 ComfyUI 工作流。本次只更新通用模板与构图示意，不生产新一期素材、不重剪已发布成片。原流程的完整文案确认、视频质检、三版封面和发布边界继续适用。

- 参数与交付清单起点：[storyboard-motion-v2.json](../assets/storyboard-motion-v2.json)（沿用文件名，内容版本为 v3）。复制到本期后填入实测信息；空镜头清单不可用于生产。
- 人物镜头参考：[storyboard-motion-preview.html](../assets/storyboard-motion-preview.html)。仅演示人物景别，不含辅助素材合成或实际字幕动效；没有生成真实图片或视频，无音频。

## 1. 分工与顺序

| 阶段 | 执行方 | 交付与完成依据 |
|---|---|---|
| 文案与配音 | 本技能 | 完整文案确认后锁定；生成并核验完整配音，再按语义切分 WAV |
| 分镜与人物图 | 本技能 | 每镜头人物图、对应 WAV、图片提示词及清单；用户要求 Image 2.5，实际版本另行核实记录 |
| 逐镜头口播 | 用户的 PC / ComfyUI | 每组图片和 WAV 生成同编号 MP4，保持对应关系 |
| 辅助素材 | 用户 | 每期提供一份截图、录屏或示意图，任一类即可；本技能登记文件及对应讲解 |
| 剪辑与特效字幕 | 本技能 | 验收源片及辅助素材，按语义插入画面，保持口播连续，统一完整字幕、原词高亮、可选轻强调、AI角标与混音 |
| 正式交付 | 本技能 | 完整视听质检、三版封面、平台物料，按原第二步交付；发布仍另按第三步授权 |

常规镜头排布、素材插入和字幕动效不重复确认已经锁定的文案。缺少辅助素材时仍可完成文案确认、配音与人物镜头包，并记录待补；第二步合成前补齐可用素材，除用户明确本期不用外，不把无素材的版本当成已完成的成片或发布包。没有本期文案、角色参考或源片时，先完成已有条件允许的准备，并准确说明缺项；模板批准不代表已完成某一期素材生成。

## 2. 五种人物镜头

| ID | 构图 | 适用位置 |
|---|---|---|
| `front_medium` | 正面半身或胸部以上，人物居中、头顶留白 | 开场、概述 |
| `front_close` | 正面近景，保留完整头部与肩部 | 重点、结论或转折 |
| `slight_angle` | 轻微侧角度中近景，眼睛与嘴完整可见 | 举例、承接；实际口型效果不佳时改回正面 |
| `return_medium` | 回到与开场一致的正面中景 | 下一组要点、语义转换 |
| `closing_close` | 与前面同一人物的正面近景 | 末句收束，保留说完后的自然停顿 |

模块不必全部使用。20–35秒可先安排4–6段，通常一段承载一个完整语义单元；句子短时合并镜头，句子长时在自然停顿处切分。以真实配音和用户工作流的可用时长为准，不按每条字幕机械切镜，不为了镜头数量改变原稿。

所有人物镜头保持同一人物、服装、背景、光线和色调，优先改变景别与轻微角度。真实角度变化由对应人物图片和生成的视频提供；单张正面画面裁切只记录为裁切近景，不能标成新侧机位。

## 3. 图片生成规范

1. 使用用户已选的人物参考图；没有参考依据时先确定角色，不能自行替换成另一个人。以同一角色参考派生各镜头，核对脸型、发型、眼镜、服装、背景与光线连续性。
2. 目标为竖屏口播构图。输出尺寸由实际图像服务及 ComfyUI 工作流支持能力决定，记录原图尺寸，不把设计尺寸1080×1920写成模型保证输出。脸、嘴、眼睛清晰，无前景遮挡；避免过度侧脸、夸张表情或复杂手部动作。
3. 图片不嵌入字幕、标题、品牌字样或AI角标，后期统一叠加；背景保持简洁，脸部与后期字幕位置错开。
4. 应用当前可用图像生成技能。用户指定 `Image 2.5`；工具确实支持指定版本时按其入口执行。记录 `requested_model`、实际返回的 `actual_model` 和版本证据；无法核实入口或版本时只交付提示词并标记待生成，不将其他模型产物冒称 Image 2.5。
5. 每张图保存项目副本、角色参考路径、实际完整提示词、生成方式与可获得的版本信息，保留生成源文件。逐张检查一致性后才标为已就绪。

可复用提示词骨架（方括号按镜头填写）：

> 以提供的角色参考图保持同一人物身份、发型、服装、背景和光线。制作一张用于竖屏口播视频的[正面中景/正面近景/轻微侧角度中近景]人物图。人物自然看向镜头，表情放松，嘴、眼睛清楚可见，头部完整，肩部自然，头顶留白，画面下部预留字幕空间。仅调整本镜头指定的构图与轻微角度，不改变人物外貌。不要文字、字幕、水印、角标或拼图。构图以实际生成尺寸及视频工作流要求为准。

## 4. 音频切分与 PC 交付包

先生成一条完整配音，再从同一个未压缩 WAV 切出各镜头音频，避免逐镜头重新 TTS 造成音色和语气跳变。保存完整配音作为最终同步基准。

- 用采样点区间 `[audio_start_sample, audio_end_sample)` 记录每段原始内容，第一段从0开始，上一段末点等于下一段起点，末段覆盖完整主音轨；每个采样点恰好出现一次。
- 优先在词句之间的自然停顿切，不截断音节、尾音或最后一句。标注对应的原稿片段和字幕编号，字幕仍是完整锁定稿。
- 若工作流需要首尾静音，在单镜头输入 WAV 中另加并记录 `input_pad_start_samples` / `input_pad_end_samples`，默认均为0。清单保存实际输入 WAV 时长；后期按真实视频口型与输入音频对齐再裁掉余量，不能只靠文件长度猜测。
- 素材路径全部相对交付包，使用稳定的镜头ID。不要把 Mac 绝对路径交给 PC 当可直接运行路径。

交付目录示意：

```text
comfyui-handoff/
  narration-master.wav
  manifest.json
  分镜.md
  pc-readme.md
  shot-01/shot-01.png
  shot-01/shot-01.wav
  shot-01/shot-01.prompt.txt
  shot-02/...
  returned/shot-01.mp4
  returned/shot-02.mp4
```

`pc-readme.md` 写明每镜头图片与 WAV 的一一对应关系、实测音频时长、建议构图/动作、输出命名及已知工作流设置。用户在 PC 选择对应图片和 WAV，按其实际工作流生成，输出应覆盖完整输入音频，回传同编号 MP4。返回文件名不替代内容核验。

尚不了解用户当前的模型、节点、显卡、分辨率、帧率和单次时长上限；不要从旧记录推断，也不要编造可导入的工作流 JSON。第一次实际制作时，依据用户提供的工作流或已有成功输出确定兼容参数，必要时先由用户生成一段验证。PC 安装、节点配置与视频生成由用户执行，本模板不自动操作 PC 或调用云视频服务。

只在图片、WAV、提示词和清单全部实际就绪并通过对应检查后记录 `handoff_ready=true`。图片待生成、音频待试听、PC视频待回传分别记录，不能合并成“制作完成”。

## 5. 辅助素材、拼接与特效字幕

逐条 `ffprobe` 检查 MP4 的分辨率、帧率、时长和音轨，再查看人物、口型、首尾完整性与镜头ID对应关系。只看参数无法验证口型。记录源视频内容对应主配音的区间，以及最终采用的 `source_in_seconds` / `source_out_seconds`。

最终画面按原配音顺序拼接，使用已锁定的完整配音作为主音轨；默认关闭返回视频中的配音轨，避免人声叠加。先实看实听确认两者同步，不能用“相同文案”推定口型一定一致。统一画布与帧率时保持真实播放时长；有漏词、截断或口型漂移时修复准确定位到的片段，必要时交回用户重生成，不用静默变速、重复帧或冻结正在说话的脸掩盖缺口。

### 辅助素材的使用

每期一份素材即可，不要求截图、录屏、示意图三类齐备。根据口播语义确定插入点和展示时长，不规定每隔几秒切一次，也不强制每句话都配素材。

| 素材 | 画面处理 | 核对重点 |
|---|---|---|
| 截图 | 保留必要上下文，裁切、轻微放大或框出所讲区域 | 关键文字清晰，不能因裁切改变原意 |
| 录屏 | 截取对应操作区间，必要时突出光标/按钮，原声默认静音 | 实看所用操作及首尾，保留足够理解时间 |
| 示意图 | 保留整体关系，按讲解高亮对应节点或连线 | 顺序和关系准确，缩略观看仍可辨认 |

默认在主时间轴上替换对应时段的画面，保持原口播音轨、字幕及总时长连续；同一素材可分段使用。优先全屏展示细节，需要同时看到人物且不影响素材可读性时才用画中画。辅助画面结束后回到主时间轴上的人物镜头，不回到插入前的旧帧。插图不单独生成一段口播音频，不参与人物 WAV 的采样点分区，也不需要人物图/提示词/ComfyUI返回视频字段。

实际打开截图和示意图；录屏必须 `ffprobe` 并观看拟用区间。保存用户原件和本期素材副本，登记路径、类型、来源说明、对应口播与可用区间。不额外延长成片来塞入素材，不用素材遮盖尚未通过验收的口播源片问题。

### 字幕与轻动效

本节就是“用默认的特效风格”对应的默认配置；用户未指定样式时同样使用。字幕文件和特效由本技能制作，无需用户提供字幕文件或参考样片，也不重复询问常规样式。用户提供的字幕截图/参考视频仅在明确要求参考其效果时覆盖默认，不能把参考片中的文字混入本期口播。

| 效果 | 默认做法 | 使用边界 |
|---|---|---|
| 切镜 | 语义或停顿处干净硬切 | 避免叠化形成双脸；保持总片长与主音轨连续 |
| 轻推拉 | 清晰镜头最多约1.05倍，缓慢单向运动 | 源宽低于720px默认关闭；高清仍须实看画质，留足头顶与下巴空间 |
| 关键词高亮 | 每期选择关键原词，在对应发声期间以金色高亮 | 不改文案、不新增结论、不逐字弹跳 |
| 单次轻强调 | 按需对重要数字或结论词做一次轻微放大/淡入 | 与口播同步，不反复跳动、不遮挡脸或素材重点 |
| 完整字幕 | 在当前已验收的 `render_text.py strip` 样式上叠加上述效果 | 包含首句末句，辅助素材出现时仍连续显示；不能用少量大字替代完整字幕 |
| AI角标 | 全程显示措辞常量 `aigc_meta.BADGE_TEXT`（现为「视频由 AI 生成」）；字高≥最短边 5%，按成片实际分辨率用 `render_text.badge()` 计算 | 不被字幕、转场或特效遮挡；新版式首次发布前用手机截图核平台界面不遮挡 |
| 音效 | 默认关闭，可按节奏选0–3处短提示音 | 使用自制或已确认可用素材，不能遮人声或每次切镜都响 |
| BGM | 沿用本期可用配乐与已验收混音 | 人声优先，片尾约0.6秒淡出，混音后测响度并试听 |

设计画布1080×1920；强调金 `#FFD774`，主字 `#F4F6F8`，次字 `#A7B1C0`。信息层参考安全区x=72–900、y=200–1500，仍按真实人像、字幕和各平台UI检查。人物与辅助画面共享相同字幕与角标样式；不因换人物镜头改变肤色或整体亮度。字幕与框选标注避开脸、嘴、素材重点及平台遮挡区；不以特效制造闪白、旋转切屏、粒子遮脸或连续缩放。

## 6. 每期记录与验收

本期 `分镜.md` 写语义、角色参考、景别、原稿范围、辅助素材及预计插入点；`manifest.json` 写 PC 交付素材及逐镜头状态。收到视频和辅助素材后，在本期 `分镜参数.json` 补齐实测源区间、最终时间轴、素材展示方式、特效字幕与混音参数。可从同一参数模板复制生成，保持镜头ID对应。

每个人物镜头（`shots`）必填：`id`、`module`、`narration_text`、`narration_cue_ids`、原始主音轨采样点区间、输入静音余量、图片/WAV/提示词/返回视频相对路径、图片生成记录。视频返回后才填写实测源片区间、最终起止秒数、实际动效和音效；未取得的值为 `null`，不可用猜测填充。

辅助素材单独记入 `visual_assets`，插入安排记入 `visual_inserts`，不混入 `shots`。使用对应的 entry template 登记素材ID、相对文件路径、类型、来源说明、口播字幕编号、实际插入起止秒数、录屏源区间、布局/裁切与标注；字幕原词、对应时间及所用效果记入 `subtitle_effects`。静态图的录屏源区间为 `null`，缺失的实测值不能猜。`visual_asset_requirement` 记录默认每期至少一份用户素材及至少一次语义匹配插入，或用户本期明确免除的依据；`handoff_ready` 只代表人物包，不表示第二步成片完成，`final_package_ready` 必须在素材使用、视听及原发布包验收全部通过后才可设为 true。

交付前新增检查：

- 图片及视频中的人物、服装、背景、光线连续，正面和侧面没有换人感；脸、嘴、眼睛未被裁掉或挡住。
- 所有镜头的 WAV 与图片配对正确；主音轨采样点范围连续且无重复遗漏；首句、数字、专有名词、末句完整。
- 视频拼接点无黑帧、声音重复、口型突然错位或跳动；开头、结尾及每次切换均实际观看。
- 用户提供的辅助素材已实际入片，内容对应讲解；插入区间首尾、截图重点/录屏操作/示意图关系均可辨认，画中画与字幕没有遮住重点。用户明确本期免除时记录该指令。
- 辅助画面切入和切出不改变口播音轨或总时长，录屏原音没有意外叠入，返回人物时口型保持同步。
- 最终字幕覆盖完整实际口播，辅助画面期间不断字幕；关键词高亮及可选轻强调与发声时机对应。混音无叠声、爆音，BGM与音效不遮人声。实际试听与自动检查分别报告。
- 原第二步全部视频/发布包检查继续执行；构图HTML能播放、ComfyUI工作流成功或MP4已导出都不等同于最终视频验收通过。

模板维护只保留本地修改，不属于各期自动Git范围；某期实际生产时，按原技能规则归档该期实际完成的素材、清单和必要证据。此次模板升级不改动任何已发布视频。
