# 四平台发布与验证

在制作平台物料或获得明确发布授权后读取本文件。平台 UI、审核规则和入口会变化；以下是智码航当前工作方式，执行时以登录账号的实际界面为准，不凭旧截图猜按钮。

## 1. 发布范围与授权

默认平台集合来自上一期台账；当前系列通常为：视频号、抖音、B站、YouTube。

- 用户只说“做视频”或“做发布资料”时，停在 `PACKAGE_READY`，不上传。
- 用户说“发布到抖音、B站、YouTube”时，只对点名平台上传并公开提交。
- 用户说“全流程发布到这些平台”时，包含上传、公开提交、发布评论、尝试置顶、公开验证和台账回填。
- Git commit / push 不包含在“发布视频”中，仍需单独授权。

执行前核对账号/频道、最终 MP4、对应封面和可见性。账号不确定、出现验证码/实名/频道验证、发布按钮可能作用于错误内容时暂停，让用户处理或确认。

不要关闭、规避或试图移除浏览器/代理的站点安全策略。平台后台无法安全操作时，交付完整手工发布包并记录为待用户发布。

## 2. 一个平台一份锁定物料

每个平台至少固定：

| 字段 | 要求 |
|---|---|
| 标题 | 记录实际粘贴文本；不要只写“长标题版” |
| 简介 | 钩子、要点、CTA、3–5 个标签；与事实边界一致 |
| 封面 | 记录实际文件名和裁切比例 |
| AI 声明 | 记录发布页选择项；发布后能否在前台看到另行核验 |
| 归因 | 沿用账号级或本期分条规则，不自行发明参数 |
| 评论 | 补一件片中没展开的内容，不复制简介 |
| 可见性 | 明确公开、定时、审核中或私密 |

发布物料定稿后逐字复制，平台页面临场改动必须回写台账。

### 评论写法

评论应至少完成一项：解释概念、扩展清单、补充来源/边界或提出具体问题。需要归因时再带合规入口；平台不适合外链时使用账号简介或项目约定的承接方式。

“评论已发送”和“评论已置顶”是两个状态。只有平台成功提示、置顶标识或菜单变为“取消置顶”等证据，才能记为已置顶；评论刚好排第一不算。

## 3. 平台要点

### 视频号

- 使用竖版成片和 3:4 封面；按实际发布页勾选 AI 生成声明。
- 简介与评论控制在平台当前限制内；项目既有置顶评论通常压在 400 字以内。
- 后台若被站点安全策略或扩展限制，停止自动操作，交给用户手工发布。提供成片、封面、标题、简介、评论和 AI 声明清单。
- 用户发布后拿回公开 URL、发布时间、AI 声明和评论状态再补账；不能因为用户说“我发了”就猜 URL。

### 抖音

- 使用竖版成片和 3:4 封面。简介通常不放分条外链；沿用账号简介的账号级归因时，不要擅自改成“本期编号”。
- 评论输入压成单行。曾出现换行触发提前提交、剩余字符落到播放器成为快捷键的事故；发送前检查完整文本，再点击发送按钮。
- 当前网页版可能没有自己的评论置顶入口。若菜单中确实没有，记录“评论已发，待手机 App 置顶”，不要把首位评论写成已置顶。
- 发布后打开公开页核对标题、账号、时长和状态。管理页 DOM 没有直接给出公开 ID 时，从已发布缩略图进入并核对内容，不凭列表顺序猜 URL。

### B站

- 使用 4:3 横版封面；竖版直接裁切常会切掉第二行文字。
- 按内容选择正确分区（本系列通常为“人工智能”），删除平台自动带入但不相关的生活类标签。
- 短片页面可能自动连播跳到推荐视频；核验或评论前先暂停/关闭自动连播，并重新核对当前 BV 号。
- 评论组件可能使用 shadow DOM；UI 自动化找不到输入框时，优先用可见交互或穿透当前组件，不向页面注入不受控脚本。
- 只有公开页可见且评论出现置顶标识/成功提示，才记录“已过审/公开”“评论已置顶”。多条 BV 同时存在时按标题、时长和封面逐项确认。

### YouTube Shorts

- 标题、简介和置顶评论按本项目约定提供中英双语；标题可保留 `#Shorts`，描述中的事实边界中英文必须一致。
- 使用 16:9 横封面或确认 Shorts 当前实际缩略图能力；不要假设上传封面一定会展示。
- 发布页按实际选项声明 altered/synthetic content 或 AI 使用情况，并设定用户要求的公开状态。
- 发布后从公开 Shorts URL 核对标题、时长、公开状态和是否识别为 Shorts。
- 置顶可能要求频道高级功能或手机验证。验证码与身份验证由用户完成；完成后刷新页面，以“已由 @频道 置顶”或菜单出现“取消置顶”为证据。

## 4. 发布顺序

对每个平台单独完成以下闭环，再进入下一个：

1. 确认当前账号、终版文件和封面；
2. 上传并等待处理完成；
3. 填实际标题、简介、标签、分区、AI 声明和可见性；
4. 提交发布；
5. 获取公开 URL，从公开页核对标题、时长、账号、可见性/过审；
6. 发布锁定评论；
7. 若在授权范围内，执行置顶并验证证据；
8. 立即回填台账，不等四个平台全部完成再凭记忆补。

草稿、上传 100%、处理完成或后台显示“已提交”仍可能处于审核/私密状态；这些都不能单独证明公开发布。

## 5. 发布记录语义

推荐状态词：

| 状态 | 含义 |
|---|---|
| 待发布 | 尚未上传或尚未公开提交 |
| 上传中 / 处理中 | 文件已交平台，但没有公开结果 |
| 审核中 | 已提交，尚未公开或尚未过审 |
| 已发布 · 公开可见 | 已取得公开 URL 并从前台核验 |
| 评论已发 | 公开评论可见，但没有置顶证据 |
| 评论已发并置顶 | 有明确置顶证据 |
| 待用户处理 | 验证码、安全策略、手机 App 或账号权限阻断 |

不要用一个“✅”同时代表上传、过审、AI 声明、评论和置顶。每个字段分别记录实际结果。

## 6. 发布后最小核验

每个平台至少保留：

- 公开 URL；
- 实际标题；
- 发布时间或平台显示日期；
- 公开/审核状态；
- AI 声明选择及前台显示状态；
- 评论文本和是否置顶；
- 实际归因入口；
- 任何需用户继续处理的阻断。

如某项平台前台不提供证据，写“待核验”，不要按发布时的计划值填成已完成。
