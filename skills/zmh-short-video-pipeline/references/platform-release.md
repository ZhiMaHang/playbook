# 五平台发布与验证

在制作平台物料或获得明确发布授权后读取本文件。平台 UI、审核规则和入口会变化；以下是智码航当前工作方式，执行时以登录账号的实际界面为准，不凭旧截图猜按钮。

## 1. 发布范围与授权

本系列默认平台为：视频号、抖音、B站、YouTube、小红书。

- 在三步流水线中，用户交回做好的源视频并要求“继续第二步”“加字幕”或同等意思，即授权后期质检通过后直接向默认五平台公开发布，不再二次询问。这是本技能记录的常驻默认，只在视频编号、锁定稿、第一步音频和源片能对应为同一期时生效；无关字幕任务不继承。
- 第二步授权包含上传、公开提交、平台 AI 声明、同步分发、公开验证和发布台账回填，但不包含发送评论或置顶。
- 用户说“给平台加评论”“补评论”“继续第三步”或同等意思时，才授权向本期已核验公开 URL 发送锁定评论、尝试置顶并回填评论状态。
- 用户明确指定部分平台、私密或定时时，以本轮指令覆盖默认值。明确只做预览时停在 `PREVIEW_READY`，不提前制作平台资产、不写正式归档、不进行任何平台操作；说“先别发布”或“暂不上传”时仍完成本地发布包并停在 `PACKAGE_READY`，不上传、评论或公开提交。只有同句明确只看成片、不做发布包时，才按预览处理。
- 只有收到文件、没有继续制作或第二步指令时，不视为发布授权。
- Git commit / push 不包含在视频发布中，仍需单独授权。

第二步默认不要把 `PACKAGE_READY` 当成终点；它只是在开始上传前的瞬时状态、受真实阻断时的降级交付状态，或用户明确要求“先别发布但仍要发布包”时的合法终点。

第二步发布授权不包含计费重生。源片质检失败且只能通过付费 TTS、数字人或视频生成修复时，停止并取得新的明确授权。

执行前核对账号/频道、最终 MP4、对应封面和可见性；YouTube Shorts 使用独立 9:16 图片，不制作普通 YouTube 16:9 图片。账号不确定、出现验证码/实名/频道验证、发布按钮可能作用于错误内容时，只暂停受影响平台并让用户处理；其他可安全发布的平台继续推进。

不要关闭、规避或试图移除浏览器/代理的站点安全策略。平台后台无法安全操作时，交付完整手工发布包并记录为待用户发布。

## 2. 一个平台一份锁定物料

每个平台至少固定：

| 字段 | 要求 |
|---|---|
| 标题 | 记录实际粘贴文本；不要只写“长标题版”。视频号短标题必须按 Unicode 字符逐字计数（中文、英文、数字、标点和 `#` 均计 1），去除首尾空白后不得超过 16 字；超限必须在生成发布物料时改写并重新计数，不能把超限标题留给用户手动处理。 |
| 正文 / 简介 | 钩子、要点、CTA、3–5 个标签；与事实边界一致；按平台实际字段记录 |
| 封面 | 记录实际文件名和裁切比例，或平台实际使用的视频帧；YouTube Shorts 使用 `封面-youtube-shorts.png`（9:16）；小红书保留 3:4 `封面.png` 候选，但只有页面提供独立图片入口并成功接受时才记录为已上传 |
| AI 声明 | 记录发布页选择项；发布后能否在前台看到另行核验 |
| 归因 | 沿用账号级或本期分条规则，不自行发明参数 |
| 评论 | 补一件片中没展开的内容，不复制简介 |
| 同步分发 | 仅抖音：默认开启“同步发布到今日头条”；用户明确要求不同步时才关闭 |
| 可见性 | 明确公开、定时、审核中或私密 |

发布物料定稿后逐字复制，平台页面临场改动必须回写台账。

### 第三步评论写法

评论应至少完成一项：解释概念、扩展清单、补充来源/边界或提出具体问题。需要归因时带发布物料锁定的合规入口，不自行发明参数；平台不适合外链时使用账号简介或项目约定的承接方式。智码航小红书评论按用户 2026-08-29 的最新要求使用独立归因链接：首期 `https://zhimahang.com/?f=xhs`，第 2 期起使用 `https://zhimahang.com/?f=xhs<期号>`。

“评论已发送”和“评论已置顶”是两个状态。只有平台成功提示、置顶标识或菜单变为“取消置顶”等证据，才能记为已置顶；评论刚好排第一不算。

## 3. 平台要点

### 视频号

- 使用竖版成片和 3:4 封面；按实际发布页勾选 AI 生成声明。
- 短标题上限为 16 字。发布物料中的视频号标题必须同时写出“字符数：N/16”；粘贴前再次按该计数核对，超限时先改标题，不得提交或交付超限文档。
- 简介与评论控制在平台当前限制内；项目既有置顶评论通常压在 400 字以内。
- 后台若被站点安全策略或扩展限制，停止自动操作，交给用户手工发布。提供成片、封面、标题、简介、评论和 AI 声明清单。
- 用户发布后拿回公开 URL、发布时间、AI 声明和评论状态再补账；不能因为用户说“我发了”就猜 URL。

### 抖音

- 使用竖版成片和 3:4 封面。简介通常不放分条外链；沿用账号简介的账号级归因时，不要擅自改成“本期编号”。
- 默认开启“同步发布到今日头条”，提交前从实际发布表单读回开关状态；只有用户明确要求本期不同步时才关闭。发布后在台账记录实际状态，不能只写计划值。
- 评论输入压成单行。曾出现换行触发提前提交、剩余字符落到播放器成为快捷键的事故；发送前检查完整文本，再点击发送按钮。
- 当前网页版可能没有自己的评论置顶入口。若菜单中确实没有，记录“评论已发，待手机 App 置顶”，不要把首位评论写成已置顶。
- 发布后打开公开页核对标题、账号、时长和状态。管理页 DOM 没有直接给出公开 ID 时，从已发布缩略图进入并核对内容，不凭列表顺序猜 URL。

### B站

- 必须上传独立的 4:3 `封面-横4x3.png`；按当前统一横版模板缩略核对左文右像、近黑标题区、金色标签、金/白两行和描边，不用竖封面裁切或两侧模糊延展代替。
- 按内容选择正确分区（本系列通常为“人工智能”），删除平台自动带入但不相关的生活类标签。
- 短片页面可能自动连播跳到推荐视频；核验或评论前先暂停/关闭自动连播，并重新核对当前 BV 号。
- 评论组件可能使用 shadow DOM；UI 自动化找不到输入框时，优先用可见交互或穿透当前组件，不向页面注入不受控脚本。
- 只有公开页可见且评论出现置顶标识/成功提示，才记录“已过审/公开”“评论已置顶”。多条 BV 同时存在时按标题、时长和封面逐项确认。
- 已发布稿件补改简介、标签或声明后可能重新进入审核；必须同时看到稿件管理恢复“已通过”和公开页出现新内容，才记录更新生效。

### YouTube Shorts

- 标题、简介、标签和置顶评论默认只提供中文，不追加完整英文标题或成段英文译文；产品名、人物名、技术缩写、命令与 URL 可按原样保留。只有用户明确要求英文或双语时才覆盖本默认。`#Shorts` 不是必填项，用户要求纯中文时不添加。
- 制作、归档并上传独立的 1080×1920 `封面-youtube-shorts.png`；缩略核对标题没有进入右侧操作列和底部标题/频道信息区。普通 YouTube 16:9 专用图不制作。
- 发布页按实际选项声明 altered/synthetic content 或 AI 使用情况，并设定用户要求的公开状态。
- 点击公开前，必须从 Studio 的标题和说明编辑框读回完整实际值并与锁定稿比对，同时核对 Shorts 图片、非面向儿童、AI 使用情况和公开范围；只显示上传文件名或缩略图不等于文字已填写。
- 发布后从公开 Shorts URL 核对标题、时长、公开状态和是否识别为 Shorts；公开页折叠说明时，再从 Studio 编辑页读回标题和完整说明，不能因为正文暂时不可见就跳过核验。
- 置顶可能要求频道高级功能或手机验证。验证码与身份验证由用户完成；完成后刷新页面，以“已由 @频道 置顶”或菜单出现“取消置顶”为证据。

### 小红书

- 发布前记录现有草稿数量并从“发布笔记 → 上传视频”新建；不要打开、复用或覆盖无法确认属于本期的既有草稿。
- 标题与正文是独立字段，分别保存锁定文本；不硬编码字符上限，以当前发布表单的计数器和校验提示为准。上传完成后必须逐字段读回，不能把文件名或平台自动填充当成已填写。
- 先查看实际封面控件。2026-08-29 实测：小红书桌面发布页外层只显出“默认视频首帧”和“智能推荐封面”，但把鼠标移到当前封面后会浮现“编辑封面”；进入内层编辑器后才出现“上传封面图片”。不得因为外层没露出文件按钮就判定不能上传独立封面。
- 内层有“上传封面图片”时上传 3:4 `封面.png`，查看实际裁切预览并确认标题、人脸不被切掉，再点击“完成”；回到表单后核对封面预览和“封面效果评估通过”等实际反馈。用户已经手动设置时，内层通常显示“已上传封面 / 清除已上传封面”，应先核对并保留，不能覆盖。只有内层确实没有图片入口时，才选择并应用视频首帧或智能推荐帧。页面默认显示首帧不等于封面已经设置；也不得通过隐藏输入、脚本注入或其他绕过方式强塞图片。
- 台账的封面来源统一写为 `独立图片：<文件名>`、`视频首帧` 或 `智能推荐帧：<页面可辨识序号/截图证据>`；无稳定标识时保留截图证据，不臆造帧号或时间戳。若页面明确要求其他规格，再新增专用封面并回写资产路径；后续 UI 若变化，以当次可见控件为准。
- 成片保留显式 AI 角标；发布页出现 AI 生成、合成内容或同类声明时按实际标签选择并读回。入口未见时写“入口未见 / 待核验”，不要假装已勾选。
- 正文不放站外链接、微信号或绕过平台规则的导流话术；第三步评论附发布物料中锁定的小红书归因链接，不写微信号。当前智码航规则是首期 `?f=xhs`、第 2 期起 `?f=xhs<期号>`，不得复用其他平台参数。话题要从当前页面实际可选结果中确认，不能只把 `#标签` 字符串写进文本就当成已选择。
- 发布后取得准确笔记 URL / ID，从公开页核对账号、标题、封面或首帧、时长、正文和公开/审核状态。后台“发布成功”或“审核中”都不能单独证明公开可见。
- 评论仍属于第三步。先查重再发送；评论使用单行 `正文。网址：<归因链接>`，不要依赖换行分隔，桌面端实测会把换行折叠并造成句号与 URL 粘连。发送后刷新或重新打开同一笔记 URL，核对评论者账号、完整文本和归因链接，只有公开页仍可见才记“评论已发”，仅有发送提示、作者态或待审核状态时记“待核验”。只有当前作者菜单实际提供置顶入口时才尝试，并以置顶标识、成功提示或菜单变为“取消置顶”为证据，否则记录“评论已发，置顶入口未见 / 待 App 处理”。

## 4. 第二步发布顺序

对每个平台单独完成以下闭环，再进入下一个：

1. 确认当前账号、终版文件和封面；YouTube Shorts 使用独立 9:16 图片；
2. 上传并等待处理完成；
3. 填实际标题、正文/简介、标签、分区、AI 声明和可见性；同步分发仅在抖音适用；
4. 从实际表单逐项读回并与锁定物料比对：标题与正文/简介非空且完整、实际封面文件或视频帧正确、声明与可见性已选；抖音默认确认“同步发布到今日头条”已开启；小红书核对账号、封面控件实际接受的文件或视频帧及其预览；
5. 提交发布；
6. 获取公开 URL，从公开页核对标题、时长、账号、可见性/过审；公开页折叠字段时回到后台编辑页读回核验；
7. 立即回填发布台账，把评论状态记为“待第三步”，不等五个平台全部完成再凭记忆补。

草稿、上传 100%、处理完成或后台显示“已提交”仍可能处于审核/私密状态；这些都不能单独证明公开发布。

## 5. 第三步评论顺序

对每个已取得可靠公开 URL 的平台单独完成以下闭环：

1. 读取本期锁定评论、公开 URL 和当前评论状态；
2. 打开准确公开页，重新核对标题、账号和视频 ID；
3. 检查锁定评论是否已经存在，避免重复发布；
4. 发送评论并确认公开可见；抖音必须保持单行并点击发送按钮；小红书必须读回完整评论和本期 `xhs` 归因链接；
5. 尝试置顶并核对明确证据；无网页入口、验证码或手机 App 专属操作时记为待用户处理；
6. 立即回填该平台评论状态，再继续其他平台。

第三步不上传视频、不改标题、简介、封面、AI 声明或公开范围。审核中或 URL 不可靠的平台暂不评论，不能凭后台列表顺序猜目标。

## 6. 发布记录语义

推荐状态词：

| 状态 | 含义 |
|---|---|
| 待发布 | 尚未上传或尚未公开提交 |
| 上传中 / 处理中 | 文件已交平台，但没有公开结果 |
| 审核中 | 已提交，尚未公开或尚未过审 |
| 已发布 · 公开可见 | 已取得公开 URL 并从前台核验 |
| 待第三步 | 视频已公开，但尚未执行评论步骤 |
| 评论已发 | 公开评论可见，但没有置顶证据 |
| 评论已发并置顶 | 有明确置顶证据 |
| 待用户处理 | 验证码、安全策略、手机 App 或账号权限阻断 |

不要用一个“✅”同时代表上传、过审、AI 声明、评论和置顶。每个字段分别记录实际结果。

## 7. 发布后最小核验

每个平台至少保留：

- 公开 URL；
- 实际标题；
- 发布时间或平台显示日期；
- 公开/审核状态；
- AI 声明选择及前台显示状态；
- 同步分发状态（仅抖音：是否同步发布到今日头条）；
- 评论文本和是否置顶；
- 实际归因入口；
- 任何需用户继续处理的阻断。

如某项平台前台不提供证据，写“待核验”，不要按发布时的计划值填成已完成。
