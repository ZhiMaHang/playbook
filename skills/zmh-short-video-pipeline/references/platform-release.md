# 视频号交付与三平台发布验证

在第二步制作四平台物料、第三步发布抖音/B站/YouTube或执行可选评论步骤时读取本文件。平台 UI、审核规则和入口会变化；以下是智码航当前工作方式，执行时以登录账号的实际界面为准，不凭旧截图猜按钮。

## 1. 发布范围与授权

本系列物料覆盖四个平台：视频号、抖音、B站、YouTube；发布职责固定拆开：视频号由用户手工发布，第三步只由 Codex 发布抖音、B站、YouTube。

- 用户要求“继续第二步”“加字幕”或同等意思，授权本地后期、三版封面、四平台物料、正式归档、QA 与本期 Git 提交推送；第二步不上传任何平台，固定停在 `PACKAGE_READY`，把视频号发布包交给用户。
- 用户在包完成后说“继续第三步”“视频号我发了，你发剩下三个平台”或同等意思，才授权上传、公开提交并验证抖音、B站、YouTube；第三步永远排除视频号。
- 三个目标平台都完成发布尝试并记录结果后，第三步停止，评论栏默认记为“未请求”。只有用户明确说“继续第四步”“给平台加评论”“发布后加评论”或同等意思，才对已取得可靠公开 URL 的平台执行评论、尝试置顶并回填状态；用户明确说“不需要评论”时记为 `COMMENTS_WAIVED`，不再追问或补做。
- 用户说“视频不行”“我要重做”“等我做好了再发”时，当前包立刻判废并停在 `SOURCE_REDO_PENDING`；新源片重新走完第二步且用户再次启动第三步前，不得上传或评论（实拍素材＋图卡路线不等新源片：重新核验素材后按意见重剪，见 [storyboard-motion.md 7.7](storyboard-motion.md#77-参数记录与状态)）。
- 用户明确指定第三步只发部分平台、设为私密或定时发布时，以本轮指令覆盖默认值。明确只做预览时停在 `PREVIEW_READY`，不制作平台资产、不写正式归档、不进行任何平台操作。
- 只有收到文件、没有继续制作或第二步指令时，不视为第二步授权；“等我做好了再发”也不是第三步授权。
- 每个已授权步骤完成后默认自动提交本期文件并推送，具体范围和远端核验见 [work-ledger.md](work-ledger.md) 的 Git 章节。第三步发布记录、第四步已授权评论记录即使只有部分完成或存在阻断，也按真实结果归档并推送；不再等待额外提交/push指令。用户本轮明确要求只保留本地、不提交或不推送时覆盖默认；Git 不扩大平台发布或评论授权。

`PACKAGE_READY` 是第二步的正常终点。第三步开始前必须重新确认该包没有被用户否定、替换或重做；有变化时退回第二步 QA。

第二步与第三步都不包含计费重生。源片质检失败且只能通过付费 TTS、数字人或视频生成修复时，停止并取得新的明确授权。

第三步执行前核对账号/频道、最终 MP4、对应封面和可见性；YouTube Shorts 使用第二步归档的独立 9:16 图片，不制作普通 YouTube 16:9 图片。账号不确定、出现验证码/实名/频道验证、发布按钮可能作用于错误内容时，只暂停受影响平台并让用户处理；其他可安全发布的平台继续推进。

不要关闭、规避或试图移除浏览器/代理的站点安全策略。平台后台无法安全操作时，交付完整手工发布包并记录为待用户发布。

## 2. 一个平台一份锁定物料

每个平台固定以下发布字段；评论字段只在用户明确要求提前准备或启动评论步骤时增加：

| 字段 | 要求 |
|---|---|
| 标题 | 记录实际粘贴文本；不要只写“长标题版”。视频号短标题必须按 Unicode 字符逐字计数（中文、英文、数字、标点和 `#` 均计 1），去除首尾空白后不得超过 16 字；超限必须在生成发布物料时改写并重新计数，不能把超限标题留给用户手动处理。抖音网页版作品标题上限 30 字，同样逐字计数，超限在写物料时就改短，并保住版本、条件等事实限定。 |
| 正文 / 简介 | 钩子、要点、事实边界、3–5 个内容标签；默认不放公司或产品营销信息；按平台实际字段记录 |
| 封面 | 记录实际文件名和裁切比例，或平台实际使用的视频帧；YouTube Shorts 使用 `封面-youtube-shorts.png`（9:16） |
| AI 声明 | 记录发布页选择项；发布后能否在前台看到另行核验（视频号只记用户回传） |
| 归因 | 作为内部记录保存；默认不写进简介或评论，不自行发明参数 |
| 评论 | 仅在用户明确要求提前准备或启动评论步骤时生成草稿；补一件片中没展开的内容，不复制简介，不追加营销 CTA；未获评论授权时不发送 |
| 同步分发 | 仅抖音：默认开启“同步发布到今日头条”；用户明确要求不同步时才关闭 |
| 可见性 | 明确公开、定时、审核中或私密 |

发布物料定稿后逐字复制，平台页面临场改动必须回写台账。

### 平台简介与评论默认无营销

- 四平台正文/简介默认只写本期视频的钩子、内容摘要、事实边界、必要来源和内容标签；不自动添加公司全称、智码航、引见 YinJen、偕行 Stride、产品能力、价格、试用、官网/产品链接、下载/咨询/关注主页等营销内容。
- 只有用户明确要求提前准备评论或启动可选评论步骤时，评论草稿才随发布物料准备；发送仍须有明确评论授权。草稿默认只补充片中未展开的来源、边界、解释、清单或具体问题，不追加产品介绍、价格、试用、营销 CTA、官网/产品链接或“官网见主页简介”。
- 归因参数默认只保留在内部发布物料和台账，不自动写入公开简介或评论。
- 视频主题本身就是相关公司/产品时，只写理解该主题必需的中性名称与可核验事实，仍不自动添加价格、试用、自有官网/产品链接、主页引导或 CTA。只有用户明确要求本期加入营销时，才允许这些推广元素；产品能力、价格、试用期、数量等动态事实须在提交前用官方来源复核，并记录实际采用的文本和链接。
- 平台文案不自动进入口播或字幕；若用户要求把新增营销内容说进口播，必须回到第一步展示合并后的完整口播并重新确认，不能在 `COPY_LOCKED` 后静默添加。

### 可选评论步骤写法

只有用户明确启动第四步时才使用评论草稿。评论应至少完成一项：解释概念、扩展清单、补充来源/边界或提出具体问题。默认不带公司或产品营销、归因入口或主页引导；只有用户明确要求本期加入时，才使用发布物料锁定的合规入口，不自行发明参数。

“评论已发送”和“评论已置顶”是两个状态。只有平台成功提示、置顶标识或菜单变为“取消置顶”等证据，才能记为已置顶；评论刚好排第一不算。

## 3. 平台要点

### 视频号

- 第二步把竖版成片、3:4 封面、标题、简介和 AI 声明清单交给用户；视频号始终由用户手工发布，不在第三步自动化范围内。
- 本期有权利依据“待确认”的素材时，视频号物料里列出这些素材，并提示视频号也应等权利依据补齐后再发，由用户决定。
- 短标题上限为 16 字。发布物料中的视频号标题必须同时写出“字符数：N/16”；粘贴前再次按该计数核对，超限时先改标题，不得提交或交付超限文档。
- 简介与评论控制在平台当前限制内；项目既有置顶评论通常压在 400 字以内。
- 视频号的分享链接一般只能在微信内打开，无法从公开网页核验：用户报告已发后，记录“用户已发布”和报告时刻，第三步抖音公开后在视频号行补填抖音同源作品 ID 作关联键（本期不发抖音或抖音未公开时，先以视频编号＋报告时刻登记，抖音之后公开的再补填）；不把索要链接列为用户待办，也不猜 URL。用户主动给了链接就原样括注在台账视频号行的 URL 栏里，标“用户提供、未经公开页核验”。只有用户明确启动第四步、主动提供了可靠链接，且能在代理操作的浏览器里打开并核对目标时，才给视频号评论。

### 抖音

- 使用竖版成片和 3:4 封面。简介默认不放公司/产品链接或主页引导；账号级归因只作内部记录，用户明确要求本期加入时也不要擅自改成“本期编号”。
- 默认开启“同步发布到今日头条”，提交前从实际发布表单读回开关状态；只有用户明确要求本期不同步时才关闭。发布后在台账记录实际状态，不能只写计划值。
- 评论输入压成单行。曾出现换行触发提前提交、剩余字符落到播放器成为快捷键的事故；发送前检查完整文本，再点击发送按钮。
- 当前网页版可能没有自己的评论置顶入口。若菜单中确实没有，记录“评论已发，待手机 App 置顶”，不要把首位评论写成已置顶。
- 网页版作品标题上限 30 字：发布物料写“字符数：N/30”，粘贴前再按该计数复核。
- 自主声明选“内容由AI生成”；发布后核对公开页是否显示“作者声明：内容由 AI 生成”，看不到时记“待核验”。
- 当前网页版同时有竖封面 3:4 和横封面 4:3 两个位置，上传竖封面后平台可能自动生成横封面；以封面检测结果和实际显示的封面为准记录。
- 话题要成为话题实体：输入“#词”后从下拉里选中对应项，纯文本 #词 不一定被识别。
- 发布后打开公开页核对标题、账号、时长和状态。管理页 DOM 没有直接给出公开 ID 时，从创作者中心同源的作品列表接口或已发布缩略图取作品 ID，并核对标题与时长，不凭列表顺序猜 URL。

### B站

- 必须上传独立的 4:3 `封面-横4x3.png`；按当前统一横版模板缩略核对左文右像、近黑标题区、金色标签、金/白两行和描边，不用竖封面裁切或两侧模糊延展代替。
- 按内容选择正确分区（科技类选题常用“人工智能”，其他选题按实际内容选），删除平台自动带入但不相关的生活类标签。新版分区编号可能与前台显示不一致，记录投稿时所选分区和公开页实际读到的分区数据，归属不清时标“待核验”。
- 新版投稿页把“自制／转载”并进了“创作声明”下拉：本系列选“含AI生成内容”。片中用了第三方画面时不选“内容为转载”（成片是本方剪辑），也不加“自制：未经作者允许禁止转载”这类授权声明；素材来源写在简介里。简介写来源不代替权利依据，权利依据仍按 [work-ledger.md 第 5 节](work-ledger.md#5-素材权利记录) 登记。
- 短片页面可能自动连播跳到推荐视频；核验或评论前先暂停/关闭自动连播，并重新核对当前 BV 号。
- 评论组件可能使用 shadow DOM；UI 自动化找不到输入框时，优先用可见交互或穿透当前组件，不向页面注入不受控脚本（“受控脚本”的界定见下方 [代发一节](#用不能挂本地文件的浏览器代发)）。
- 只有公开页可见且评论出现置顶标识/成功提示，才记录“已过审/公开”“评论已置顶”。多条 BV 同时存在时按标题、时长和封面逐项确认。
- 已发布稿件补改简介、标签或声明后可能重新进入审核；必须同时看到稿件管理恢复“已通过”和公开页出现新内容，才记录更新生效。

### YouTube Shorts

- 标题、简介、标签和置顶评论默认只提供中文，不追加完整英文标题或成段英文译文；本期内容确需出现的产品名、人物名、技术缩写、命令与外部事实来源 URL 可按原样保留，自有官网/产品 URL 仍受无营销规则约束。只有用户明确要求英文或双语时才覆盖本默认。`#Shorts` 不是必填项，用户要求纯中文时不添加。
- 第二步制作并归档、第三步上传独立的 1080×1920 `封面-youtube-shorts.png`；缩略核对标题没有进入右侧操作列和底部标题/频道信息区。普通 YouTube 16:9 专用图不制作。
- 发布页按实际选项声明 altered/synthetic content 或「AI 使用情况」，并设定用户要求的公开状态。配音为 AI 合成时，「AI 使用情况」选「是」。公开页不一定显示 AI 标签；看不到时记“后台已选、前台未见，待核验”，不写成已显示。
- 点击公开前，必须从 Studio 的标题和说明编辑框读回完整实际值并与锁定稿比对，同时核对 Shorts 图片、非面向儿童、AI 使用情况和公开范围；只显示上传文件名或缩略图不等于文字已填写。
- 发布后从公开 Shorts URL 核对标题、时长、公开状态和是否识别为 Shorts；公开页折叠说明时，再从 Studio 编辑页读回标题和完整说明，不能因为正文暂时不可见就跳过核验。
- 置顶可能要求频道高级功能或手机验证。验证码与身份验证由用户完成；完成后刷新页面，以“已由 @频道 置顶”或菜单出现“取消置顶”为证据。

### 用不能挂本地文件的浏览器代发

本节的上传分工只用于第三步的抖音、B站、YouTube；视频号由用户手工发布，不适用。下面“受控脚本”的界定同样适用于第四步评论等其他页面操作。

代理操作的浏览器窗口有时不能给文件输入框挂本地文件：直接赋值会被浏览器拒绝；在页面里向本机地址取文件，会被浏览器的本地网络访问限制拦下。⛔ 不要设法绕过这些安全限制：不用脚本往 DataTransfer、ClipboardEvent 或拖放事件里放 File 或 Blob，把文件塞进页面（只放文本数据、用来派发粘贴事件的不在此列），不请用户放行本地网络访问，也不另起本地服务转运文件。

本节说的“受控脚本”指：只读写本页的表单字段，向本页表单控件、编辑器或自定义下拉等组件派发输入、粘贴、点击类事件，或用 `execCommand` 让文字走编辑器自己的输入流程，只调用页面已有组件的接口或同源的只读接口，不加载外部代码，不改页面或浏览器的安全设置，执行前后都读回结果。超出这个范围的都算不受控脚本。

可行分工：

1. 本技能打开上传页，确认已登录正确账号。先确认用户能看到并操作该浏览器窗口，再请用户点“上传”，亲手选本期终版文件；封面、缩略图同样请用户亲手选。每次说清要选的文件路径。
2. 上传完成后，本技能核对挂上的文件：页面能读到文件输入框时，比对 `input.files[0]` 的文件名和字节数与本期终版一致；再核对平台显示的时长、画幅。核对通过后才填写其余字段，并逐项读回比对。
3. 富文本编辑器不要直接改 DOM（用 Range/Selection 的 `insertNode`、设置 `innerHTML` 等）：常见的是只插进第一段，或在原有内容后面重复追加。可行做法：
   - 先用真实按键全选删除，再派发一次粘贴事件；
   - 或调用编辑器组件自身的接口（如 Quill 的 `setText`）；
   - 或先用真实按键聚焦并全选，再用 `execCommand('insertText')` 加 `insertLineBreak`，让文字走编辑器自己的输入流程。

   无论用哪种，填完都读回全文逐字比对。
4. 自定义下拉、单选框找不到可点引用时，可对组件本身派发点击事件；选完读回所选值。
5. 发布按钮只点一次，之后到作品列表或公开页确认是否落地，不因页面慢而重复点击。
6. 某个平台的账号、文件或关键字段无法确认时，只暂停该平台，其余平台照常推进。

## 4. 第三步三平台发布顺序

只对抖音、B站、YouTube单独完成以下闭环，再进入下一个；不得把视频号加入本顺序：

1. 确认当前账号、终版文件和封面；YouTube Shorts 使用独立 9:16 图片；核对本期素材权利记录：权利依据为“待确认”、或使用范围不含本平台的素材，涉及的平台不上传，记“暂缓：权利待确认”或“暂缓：超出使用范围”；三个平台都因此暂缓时不进入上传，台账保持 `PACKAGE_READY`，不记 `PUBLISHED_PARTIAL`；
2. 上传并等待处理完成；
3. 填实际标题、正文/简介、标签、分区、AI 声明和可见性；同步分发仅在抖音适用；
4. 从实际表单逐项读回并与锁定物料比对：标题与正文/简介非空且完整、没有混入默认禁止的公司或产品营销内容、实际封面文件或视频帧正确、声明与可见性已选；抖音默认确认“同步发布到今日头条”已开启；
5. 提交发布；
6. 获取公开 URL，从公开页核对标题、时长、账号、可见性/过审；公开页折叠字段时回到后台编辑页读回核验；
7. 立即回填发布台账，评论状态默认记为“未请求”，不等三个目标平台全部完成再凭记忆补。

三个目标平台都完成发布尝试并记录结果后，在本次会话、当天按 [work-ledger.md 第 8 节](work-ledger.md#8-站外登记) 做站外登记（本机没有登记配置时跳过，在最终回复里写明），再做本期 Git 收口，然后停止。只有用户明确启动第四步时，才把授权范围内的评论状态改为“待第四步”并继续执行。

草稿、上传 100%、处理完成或后台显示“已提交”仍可能处于审核/私密状态；这些都不能单独证明公开发布。

## 5. 第四步评论顺序

对每个已取得可靠公开 URL 的平台单独完成以下闭环：

1. 读取本期锁定评论、公开 URL 和当前评论状态；
2. 打开准确公开页，重新核对标题、账号和视频 ID；
3. 检查锁定评论是否已经存在，避免重复发布；
4. 发送评论并确认公开可见；抖音必须保持单行并点击发送按钮；
5. 尝试置顶并核对明确证据；无网页入口、验证码或手机 App 专属操作时记为待用户处理；
6. 立即回填该平台评论状态，再继续其他平台。

第四步不上传视频、不改标题、简介、封面、AI 声明或公开范围。审核中或 URL 不可靠的平台暂不评论，不能凭后台列表顺序猜目标。

## 6. 发布记录语义

推荐状态词：

| 状态 | 含义 |
|---|---|
| 待发布 | 尚未上传或尚未公开提交 |
| 上传中 / 处理中 | 文件已交平台，但没有公开结果 |
| 审核中 | 已提交，尚未公开或尚未过审 |
| 已发布 · 公开可见 | 已取得公开 URL 并从前台核验 |
| 评论未请求 | 视频发布流程已结束，用户尚未明确启动第四步 |
| 待第四步（评论） | 用户已明确启动评论步骤，视频已公开但评论尚未执行 |
| 评论已放弃 | 用户明确表示本期不需要评论，记为 `COMMENTS_WAIVED` |
| 评论已发 | 公开评论可见，但没有置顶证据 |
| 评论已发并置顶 | 有明确置顶证据 |
| 待用户处理 | 验证码、安全策略、手机 App 或账号权限阻断 |
| 暂缓：权利待确认／超出使用范围 | 素材权利依据未确认，或本平台不在已确认的使用范围内；用户补齐依据或改用图卡重剪前不上传 |

不要用一个“✅”同时代表上传、过审、AI 声明、评论和置顶。每个字段分别记录实际结果。

## 7. 发布后最小核验

每个平台至少保留：

- 公开 URL（视频号通常没有：记关联的抖音同源作品 ID，本期不发抖音或抖音未公开时记视频编号＋报告时刻，不记待核验）；
- 实际标题；
- 发布时间或平台显示日期；
- 公开/审核状态；
- AI 声明选择及前台显示状态（视频号只记用户回传，不要求前台核验）；
- 同步分发状态（仅抖音：是否同步发布到今日头条）；
- 评论状态；只有明确执行第四步时才记录评论文本和是否置顶；
- 实际外部事实来源，以及仅供内部台账使用的归因记录；
- 任何需用户继续处理的阻断。

如某项平台前台不提供证据，写“待核验”，不要按发布时的计划值填成已完成（视频号除外：按上面两项只记用户回传，不列待办）。
