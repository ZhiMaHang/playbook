# 清洗与打标签

收集来的词常有几百上千个：重复、写法乱，混着大量无关的词。清洗的目标是让每一行代表一个真正不同的需求，并且每个数字都能追溯。

## 1. 清洗五步

| 步 | 做什么 | 为什么 |
|---|---|---|
| 1 合并去重 | 多个来源的词合到一张表，完全相同的只留一行 | 同一个词多行，后面统计会重复 |
| 2 规范写法 | 统一大小写、空格、全半角、单复数；变体并进规范写法那一行，变体记在备注 | 规划师已把变体合并计数，变体单独算量就重复了；备注里留着变体，以后在后台里核对 |
| 3 剔除无关 | 只看卖不卖、意图对不对，剔除前对照产品目录 | 剔错一个本站卖的品类，后面整条线都漏 |
| 4 标市场语言 | 美国英文、国内中文、法、德、日分开 | 同一个词在不同国家量差很多 |
| 5 标来源日期 | KE、GKP、GSC、必应、百度、询盘……写上取数日期 | 数据会过期；需求证据要数来源 |

规范写法示例：

| 原始写法 | 规范写法 | 说明 |
|---|---|---|
| LAN Transformers / lan-transformer | lan transformer | 大小写、连字符、复数 |
| STM32L151 VET6TR / stm32l151vet6tr | STM32L151VET6TR | 料号按原厂规格书写法，通常大写、不带空格 |
| ＰｏＥ变压器 / poe变压器 | PoE 变压器 | 全角转半角 |
| 網路變壓器 | 网络变压器 | 面向大陆市场转简体；繁体市场单独研究 |

常见误区：
- 变体单独算量；
- 没核结果页就合并同义词：先看前 10 名重合（`clustering-scoring.md`），确认真同义才能并、才能相加。同义判断错了，后面的归并和页面都会错。

脚本能做前两步的机械部分，并给出剔除和意图的初分建议：

```
node scripts/kw_table.mjs prep 候选词.csv --exclude 本站剔除词.txt --brand 本站品牌 --out 初分.csv
```

- 合并大小写、全半角、空格、连字符、单复数变体，取量最大的写法作规范写法候选，其余写进「变体」列，**数字不相加**；
- 标「疑似剔除」（命中剔除词片段）、「疑似料号」（要按原厂写法改）、「长查询」（问题集候选）、「长问句」（可能是 AI 工具检索，单列）；
- 按修饰词给「初分意图」，词面没有修饰的标「未带意图修饰」，比较类标「待定」。

脚本只看词面，输出全部要人工复核；繁简转换、料号大小写、近义叫法的合并它不做。

## 2. 剔除词清单

剔除词只看两条：**我们卖不卖这个东西，搜的人意图对不对**。剔除前先对照产品目录。

- 清单是一组「出现了多半就不是我们要的需求」的词片段，可以在表格里批量标出，也可以在 GSC 里用正则「不匹配」排除后再看数据。
- **每个站各维护一份**，每一条都对照本站产品目录确认过。示例见 `assets/exclude-fragments.example.txt`。
- **不能整组排除**：卖直通头的站，coupler 就是自己的词（rj45 coupler 美国月搜 2,400，KE，2026-10），不能因为它常和布线 DIY 一起出现就整组剔掉。
- **不照搬广告否定词**：否定词是为了不花冤枉钱；广告不转化可能是出价、落地页、匹配方式的问题，不等于不值得做 SEO。

正向修饰词正好相反：出现这些片段，搜的人多半是工程师或采购，优先保留。电子元器件类示例：pcb、smd、through hole、right angle、tab up、tab down、with magnetics、1000base-t、poe++、802.3bt、datasheet、footprint、cad model、equivalent、cross reference；贴片、插件、立式、带灯、千兆、规格书、封装、替代、选型。换行业要重写。

## 3. 打标签：固定选项

每个维度用固定选项，在表格里做成下拉菜单，不自由填写：今天写「参数资料」、明天写「规格书」，统计就对不上。

| 列 | 固定选项 | 用来做什么 |
|---|---|---|
| 意图大类 | 信息 / 商业 / 导航 / 未带意图修饰 / 待定 | 页面类型 |
| 意图细类 | 信息词九类、商业词九类（`classification.md`）/ 待定 | 页面上写什么 |
| 属性 | 品牌 / 型号 / 品类 / 参数 / 封装 / 应用 / 标准 / 地域 / 技术概念（可多选，用「、」隔开） | 对到哪条产品线、哪一页 |
| 范围 | 核心词 / 长尾词（另一列写相对哪个核心词） | 主题词还是辅助词；并入还是自成主题 |
| 热度 | 常青 / 季节 / 突发 / 待定（看 12 个月以上数据） | 常设页面还是时效内容 |
| 趋势 | 涨 / 平 / 跌 / 未知 / 待定 | 判断热度的依据 |
| 产品线 | 按本站产品目录 | 分给对应的分类页 |
| 主题内角色 | 主题词 / 同义叫法 / 辅助词 / 长尾 | 交给布局和 TDK 时知道每个词怎么用 |
| 市场语言 | 美国英文 / 国内中文 / 法 / 德 / 日…… | 同一个词分市场看数据 |
| 数据来源 | KE / GKP / GSC / 必应 / 百度 / 广告 / 竞品工具 / 平台 / 询盘 / FAE / 社区 / AI（可多选） | 打分时的「需求证据」 |
| 结论 | 先做 / 排队 / 暂缓 / 剔除 / 待定 | 优先级 |

- 词面看不出意图的光秃秃品类名和型号，大类先标「未带意图修饰」，看过结果页再定细类。
- 不设「人群」「阶段」列；从词出发的分析写进「承接理由」，一句话写可能谁在搜、痛点、页面要放什么。
- 表格做法：Excel / WPS 选中标签列 → 数据 → 数据验证（有效性）→ 允许「序列」，填入固定选项。首行冻结。

## 4. 让 AI 做初分，人来复核

几百个词的初分交给 AI 能省几小时，但必须人工复核：AI 不看结果页，容易把 rj45 connector 这种大词判成产品浏览；它也不知道本站的产品目录。

提示词模板（把 [ ] 换成自己的）：

```
【角色】你是 [行业] 行业的 B2B SEO 专员，熟悉 [主要品类]。
【背景】附件是 [300] 个 [美国英文] 关键词及搜索量，核心词是 [核心词]。
  本站卖的产品见附件产品目录。
【任务】逐词标注：意图大类（信息 / 商业 / 导航 / 未带意图修饰）、
  意图细类（信息词 9 类、商业词 9 类，见下）、属性（可多选）、范围（核心 / 长尾）、产品线。
  信息词 9 类：概念定义、原理机制、参数资料、选型方法、设计应用、故障排查、标准法规、技术对比、行业资讯。
  商业词 9 类：产品浏览、比较挑选、替代查询、找厂家、找供应渠道、询价、现货与下单、样品、定制。
  不要按人群分类。
【约束】只根据词本身判断；词里没有意图修饰的标「未带意图修饰」，不要猜；
  比较类词按比较对象分：比技术、规格归信息 · 技术对比，比品牌、供应商、可买产品归商业 · 比较挑选；
  拿不准的标「待定」并写原因；不要删行，不要改动或估算搜索量。
【输出】表格：关键词｜意图大类｜意图细类｜属性｜范围｜产品线｜理由（10 字内）。
```

人工复核规则：
- 随机抽查 20%（经验值），错误多就整批重做；
- 「待定」「未带意图修饰」逐个看结果页再定；
- 搜索量最大的 20 个词全部人工看结果页（经验值，可按词量调整）；
- 要剔除的词只按卖不卖、意图对不对判断，剔除前对照产品目录；
- 热度看 12 个月数据填，不让 AI 判断；
- AI 给出的任何数字都不用，搜索量只从工具和后台取。

## 5. 后台查询分类（只整理已有查询时）

从 GSC / 必应 / 百度后台导出近 3 个月的查询，按上面的标签打完后，做一张「意图 × 属性」交叉统计，看展示、点击、点击率落在哪：

```
node scripts/kw_table.mjs crosstab 已打标签的查询.csv
```

结论里要写：
- 数据范围、时间、国家；
- 可见查询只覆盖部分点击（写出覆盖率），只能看结构；
- 先剔除了哪些（机器查询、模板化长问句、垃圾查询）及条数；
- 例如「商业词展示少、点击为 0」「型号属性的点击主要来自型号 + datasheet」这类结构性发现，以及对应的机会词。

只按属性切会漏掉信息：同样是带型号的词，点击可能全来自「型号 + datasheet」的信息词，光型号很少。所以意图和属性要交叉着看。
