# 交付：关键词研究表、交接说明、维护

关键词研究的产出是一张表：每行一个词，数据写来源和日期，判断写依据。它是后面布局、TDK、内容、报告的起点，所以要让下游拿到就能用。

## 1. 关键词研究表

表头见 `assets/keyword-research-table.csv`（UTF-8 带 BOM，Excel、WPS 直接打开）。

**数据列**（原则：可追溯）

| 列 | 写什么 | 示例 |
|---|---|---|
| 关键词 | 规范写法（变体写进备注） | ethernet transformer |
| 市场语言 | 美国英文、国内中文…… | 美国英文 |
| 月搜索量 | 数字或区间；没有数据写「未知」，不估 | 140 |
| 搜索量来源 | 工具 + 市场 | KE 美国 |
| 取数日期 | YYYY-MM-DD | 2026-10-13 |
| 出价 | 工具里的点击单价 | $5.23 |
| 趋势 | 涨 / 平 / 跌 / 未知 / 待定 | 待定（看 12 个月数据后填） |
| 热度 | 常青 / 季节 / 突发 / 待定 | 常青 |
| 后台展示 / 后台排名 | 后台的真实数字 | 1 / 29 |
| 后台时间范围 | 有后台数字就必填 | 2026-09（GSC，全部国家） |
| 结果页前排 | 前排类型，看过才填 | 分销商、原厂系列页 |
| AI摘要 | 有 / 无 / 未看 | 无 |
| 数据来源 | 可多选，用「、」隔开 | KE、GSC |

**判断列**（原则：能复核）

| 列 | 写什么 | 示例 |
|---|---|---|
| 意图大类 | 信息 / 商业 / 导航 / 未带意图修饰 / 待定 | 未带意图修饰 |
| 意图细类 | 九类之一，按结果页定 | 产品浏览 |
| 属性 | 可多选 | 品类 |
| 范围 / 核心词 | 核心词或长尾词；长尾写相对哪个核心词 | 核心词 |
| 产品线 | 按产品目录 | LAN 磁件 |
| 主题 | 聚类后的主题名 | LAN 变压器 |
| 主题内角色 | 主题词 / 同义叫法 / 辅助词 / 长尾；一个主题只有一个主题词 | 主题词 |
| 承接页面类型 | 按意图 × 属性的默认分工（`classification.md` 第 8 节） | 分类页 |
| 现有可承接页面 | 已知的现有网址，或「无」；供布局核对 | 某分类页网址 |
| 承接理由 | 一句话：主导解释、可能谁在搜、痛点、页面要放什么（推断要标明） | 多是设计网口的工程师选型（推断） |
| 六项打分 | 意图匹配、业务相关度、需求证据、商业信号、承接能力、可赢性，各 0–2 | 2、2、2、1、2、2 |
| 总分 / 结论 | 总分；先做 / 排队 / 暂缓 / 剔除 / 待定 | 11 / 先做 |
| 动作 | 具体到要做什么（机会词标名次和在排的网址） | 作主题词；上线前再核一次和 lan transformer 的结果页重合 |
| 负责人 / 复查日期 | 一个人；何时看效果 | 填写 |
| 备注 | 变体写法、明确度、时效、口径提醒 | 变体：ethernet transformers |

规则：
- 四个维度各占一列，用固定选项；拿不准先标「待定」，看过结果页再改。
- 不设人群、阶段列。
- 一票否决的词结论填「剔除」，理由写进承接理由或备注，不打分。
- 表格做法：标签列做成下拉菜单；首行冻结；按总分降序；每次更新另存一个带日期的版本，不覆盖旧表。
- 交付前跑一遍：`node scripts/kw_table.mjs check 关键词研究表.csv --out 关键词研究表_带总分.csv`，错误清零再交。

**交付时附一段结论**（写在表格首页或回复里，结论放最前面）：
1. 范围：哪条产品线、哪个市场语言、哪些数据源、取数日期；
2. 先做的词和理由（三五条）；
3. 主题划分：几个主题、每个主题的主题词、哪些同义关系还没核结果页；
4. 机会词（第 4–20 名）清单；
5. 缺口：缺什么数据、哪些格子是「未知」、哪些结论因此是「待定」；
6. 要负责人定的事（例如某个叫法、口径能不能写），每项给建议和理由，单独列出；
7. 交接：下一步交给哪个技能、交什么。

## 2. 只整理后台查询时

交「分类表 + 交叉统计 + 200 字左右的结论」：
- 分类表：每个查询的意图大类、细类、属性、范围、产品线，一个维度一列；
- 交叉统计：`node scripts/kw_table.mjs crosstab 分类表.csv`，按意图 × 主属性看展示、点击、点击率；
- 结论：有数据和日期，写明只覆盖可见查询、剔除了什么，指出结构性问题和机会词。

## 3. 问题集

表头见 `assets/question-set.csv`，字段说明见 `ai-question-set.md` 第 5 节。交付时写清：版本号、题数、按产品线 × 采购阶段的覆盖情况、品牌题和非品牌题各几道、语言 × 平台组合、每题的来源。

## 4. 交给下游

| 下游 | 交什么 | 由它做什么 |
|---|---|---|
| seo-keyword-mapping | 关键词研究表（主题、主题词、同义叫法、承接页面类型、现有可承接页面）；没有对口页面的主题清单；几个主题指向同一页的提醒 | 落到具体网址，做关键词与页面对照表，站点结构、内链，诊断和处理内耗 |
| seo-tdk-page-elements | 主题词、同义叫法、辅助词；机会词（第 4–10 名）；身份词的需求证据和口径结论 | 写标题、描述、H1 |
| seo-content-writing | 信息词主题、问题集里的弱主题、高频问法、买家顾虑 | 定选题、写正文和问答 |
| seo-analytics-reporting | 要盯的词（先做的词、机会词）、问题集 v1 | 定 KPI、按固定节奏跑 AI 监测、出报告 |
| seo-audit-remediation | 发现的技术问题（例如后台查询暴露的收录、渲染问题） | 体检、整改 |

本技能不替下游做：不把词逐一分配到网址、不写 Title、不写正文。用户只要研究结果时，做到交付就停。

## 5. 维护

- **每月小更新**：导出后台新出现的查询，补进表格，更新排名和展示，标出新的机会词。这一步可以交给定时任务每月拉数据、标变化，由人复核。
- **每季度大更新**：重跑全流程，重新查量和看结果页，复核打分、同义关系和身份词的需求证据。
- **版本**：文件名 `站点_关键词研究表_YYYYMMDD.xlsx`（或 .csv）；旧版本不删，放进「历史版本」文件夹；表格首页写更新记录。
- 文中带日期的工具菜单、数据、规则，每季度复核一次；发现过时，以官方最新文档为准并登记。
