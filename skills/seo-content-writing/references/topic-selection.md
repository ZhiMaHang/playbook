# 选题：写什么、先写什么、哪些不该写成文章

内容不是越多越好。内容策略管三件事：规划（为谁写、写什么、先写什么）、交付（怎么写、谁审、怎么发）、治理（谁负责、口径是什么、什么时候改）。定义出自 Halvorson《Content Strategy for the Web》（2009）。「每月发 N 篇」只是产出量，不是策略：数量目标要配质量门槛（`review-checklist.md`）和发布后 4–8 周的效果复查（经验值）。

## 1. 从需求到处置

一个需求（后台里的一个查询、客户的一个问题、关键词表里的一个词）不直接变成「写一篇文章」。先做两件事，再分五种情况：

1. **判断意图细类**：信息词还是商业词，哪个细类（细类清单见 `intent-playbook.md`）。拿不准就看结果页前 10 名是什么类型的页面：全是产品列表，就是商业词；全是教程和百科，就是信息词。
2. **查关键词—页面对照表**：现在有没有页面在承接。

| 情况 | 处置 | 为什么 |
|---|---|---|
| 已有对口的页面 | 更新这一页，不新写 | 新写一篇讲同一件事会和自己抢词；更新通常比新写见效快，也不多出一个要维护的网址（经验） |
| 有页面，但意图不对口（例如文章在排品类商业词） | 先查是不是关键词内耗，交 seo-keyword-mapping 定改哪页，再决定改写还是新写 | 不先查就新写，常常变成两页互相拖累 |
| 商业词，没有页面 | 由分类页、产品页、替代对照页承接，不写成文章 | 买家要的是产品和下一步；文章里没有选型表和询价入口 |
| 小问题，没有页面 | 写进相关页面的问答 | 两三句话答得完的，单独成篇就是薄页 |
| 信息词，没有页面 | 拿得出一手内容 → 新写；拿不出 → 先不写 | 只能改写别人资料的文章，正落在 Google 警示信号「主要在概括别人的内容」上 |

**怎么判断「小问题」**（经验）：两三句话能答完、没有独立的搜索需求，或者答案离不开某个产品的参数，就写进那个页面的问答；有量、有多个子问题，才单独成篇。

**要新建页面时**，同时满足四个条件才建：结果页确实要一个专门的页面；我们有独有的内容；有需求；站内有页面会链向它。四个条件的判断方法归 seo-keyword-mapping，这里只用结论。

**自测一句**（对应 Google「为什么」一问）：假如这篇内容不会被搜到，客户直接来看，它还值得写吗？答不上来的，先别写。

## 2. 选题来源

按可信程度和具体程度大致排序。前三类优先；工具和 AI 扩出来的题，要回到后台数据和客户问题里验证。

| # | 来源 | 拿到什么 | 怎么取 | 多久看一次（经验值） |
|---|---|---|---|---|
| 1 | 后台数据 | 已有展示的查询：排第 4–20 位、展示多点击少、问句 | GSC、必应、百度资源平台按查询、按网页看；用正则筛问句（what、how、why、怎么、为什么、如何） | 每月 |
| 2 | 询盘与工程师记录 | 客户原话：怎么选、为什么坏、能不能换 | 每月汇总客户问到的问题和型号 | 每月 |
| 3 | 站内搜索 | 搜了却没找到的型号和问题 | GA4 等站内搜索词报告 | 每月 |
| 4 | 关键词表的空档 | 有量、但还没有承接页面的词 | 对照表里「承接页面」为空的行 | 每季度 |
| 5 | 竞品型号缺口 | 有人搜、还没有对照内容的竞品型号 | 关键词表 × 现有对照内容（写法守口径，见 `claims-wording.md`） | 每季度 |
| 6 | AI 搜索监测 | AI 回答里我们缺席的话题 | 固定问题集多次运行（归 seo-analytics-reporting） | 每月 |
| 7 | 产品与行业变化 | 新品、新标准、停产 | 产品部门、标准组织的公告 | 有事就写 |

没有后台数据时：用来源 2、3、7 和结果页前 10 名代替，需求一栏写「未知」或「客户问过 N 次（来源、日期）」，不编搜索量。

## 3. 选题表

一题一行。表头在 `assets/topic-sheet.csv`。意图、属性、处置做成下拉选项，免得同一件事写出三种说法。

| 字段 | 写什么 |
|---|---|
| 选题 | 一句话写清要回答的问题 |
| 主题词 | 本页主打的一个词，照搬用户真实的写法 |
| 意图 | 大类 · 细类，例如「信息词 · 故障排查」 |
| 属性 | 可多选：品牌、型号、品类、参数、应用、标准等 |
| 范围 | 核心词还是长尾；长尾写清它挂在哪个核心词上 |
| 热度 | 常青 / 季节 / 突发 |
| 数据 | 量、展示、排名，带来源和日期；工具估算的量只用来比大小 |
| 承接页面 | 现有网址，或要新建的页面类型 |
| 处置 | 新写 / 更新 / 并入 / 写进问答 / 不做；不是「新写」的写明哪个网址 |
| 一手证据 | 能拿出什么：实测、工程师记录、照片、规格书；拿不出写「无」 |
| 写稿 / 审核 | 写角色，不写人名也行 |
| 优先级 | 四项打分合计（第 4 节） |
| 计划日期 / 复查日期 | 没有复查日期的表只是一份报告 |

**示例**（虚构：做工业阀门出口的英文站，数据为演示值）：

| 查询 | 展示 / 排名 | 意图细类 | 处置 |
|---|---|---|---|
| ball valve vs gate valve | 410 / 11.2 | 信息词 · 技术对比 | 站上已有阀门类型对比文：更新，补「何时选哪种」一节 |
| how to fix leaking ball valve stem | 95 / 9.4 | 信息词 · 故障排查 | 已有阀门泄漏排查文：并入，补「阀杆泄漏」一节 |
| api 6d ball valve requirements | 120 / 18.0 | 信息词 · 标准法规 | 新写标准解读，结论交工程师审；动笔前先看结果页前排 |
| buy 2 inch ball valve | 70 / 16.1 | 商业词 · 现货与下单 | 不写文章：球阀分类页补询价入口和资料下载 |
| ball valve supplier | 40 / 20.4 | 商业词 · 找供应渠道 | 不写文章：分类页 H1 下一句写清我们是谁（按口径） |
| can a ball valve be used for throttling | 14 / 8.4 | 信息词 · 原理机制 | 写进球阀分类页的问答，不单独成篇 |
| valve market size forecast | 35 / 41.3 | 信息词 · 行业资讯 | 暂不写：拿不出一手数据 |

数一数：七个题里新写一个，更新或并入两个，归产品类页面两个，写进问答一个，不写一个。多数题不该新写文章，这是常态。

## 4. 排优先级

| 维度 | 3 分 | 1 分 | 看什么 |
|---|---|---|---|
| 商业价值 | 选型、替代、参数资料等离采购近的题 | 泛泛的科普，和产品线关系远 | 意图细类、对应产品线 |
| 可赢性 | 已有展示、排第 4–20 位 | 前 10 名全是大站，我们没有页面 | 后台排名、结果页 |
| 需求 | 后台展示多，或客户反复问 | 只有工具估算值 | 后台、询盘、工程师记录 |
| 证据 | 有实测、工程师记录、案例 | 只能改写别人的资料 | 手里的一手资料 |

四项相加，满分 12。分值是经验值，同一张表前后一致即可；同分时先做可赢性高的。

**一票否决**：证据 1 分且价值 1 分的不写（正落在 Google 警示信号「概括别人的内容」「没有专长只为流量进入某领域」上）；需要写价格、未登记的交期承诺等口径不允许内容的不写。

**示范**：上表的 api 6d ball valve requirements：价值 2 + 可赢 2（有展示，第 18 位）+ 需求 2 + 证据 2（要工程师补资料）= 8 分。

关键词研究里也给词打分（决定先做哪些词，归 seo-keyword-research）；这里给选题打分，决定先写哪篇，多了「证据」一项。

## 5. 组合与节奏

| 类型 | 例子 | 更新节奏（经验值） |
|---|---|---|
| 常青 | 原理、选型、设计、故障、参数资料 | 每 6–12 个月复核；参数或标准一变就更新 |
| 时效 | 新品、展会、标准发布、行业资讯 | 发布时写清日期；过了时效不必刷新日期 |
| 信任与采购 | 质量文件、采购指南、样品政策 | 证书、政策一变就改；有到期日的提前改 |

- 稳定的节奏比集中冲量好，例如每周或每两周一篇，留出技术审核的时间（经验）。
- 每次排期，常青内容和更新旧文占大头；时效内容按事件写，不为凑数写。
- 每季度盘点一次（`update-merge.md` 第 7 节），把该更新、合并的旧文排进下一期。
- 一份内容多处分发：官网版本做母本，其他平台改写后链回官网（经验）。站外发布的规矩见 `offsite-links.md`。
- 完整版资料（选型手册、参考设计）可以做成留资料下载，但公开页面上要有可抓取的摘要，否则搜索引擎和 AI 看不到任何内容。
