# 按意图细类写

关键词分类以意图为主轴（属性、范围、热度是另外三把尺子），细类划分以关键词研究的分法为准，叫法见 `glossary.md`。这里只回答下一个问题：每个细类的内容写成什么样。

用法：先给主题词定细类，再照对应那一行写；**一篇主打一个细类**，次要的问题放进问答。写法是经验做法，依据是 Google《创建实用、可靠、以用户为中心的内容》（2026-10-05）的自查问题和《写出高质量评测》（2025-12-10），不是搜索引擎的硬性规定。

## 1. 信息词九个细类

「开头先给」一栏最重要：读者读完还得再去搜，是 Google 列的警示信号。

| 细类 | 搜的人要什么 | 开头先给 | 必备要素 | 常见形式 | 正文小标题顺序 |
|---|---|---|---|---|---|
| 概念定义 | 是什么、有什么用 | 一句话定义 + 用途 | 定义、作用、和相近概念的区别 | 百科式指南 | 是什么 → 用来做什么 → 和相近概念的区别 → 例子 |
| 原理机制 | 怎么工作、为什么 | 一句话因果 | 原理图、关键参数的影响、常见误解 | 原理文章 | 是什么 → 怎么工作 → 关键参数 → 常见误解 → 设计上的含义 |
| 参数资料 | 具体数值、图纸 | 关键参数表 | 文字参数表、规格书下载、引脚和尺寸图 | **型号页**，不另写文章 | 见 `page-blueprints.md` 第 4 节 |
| 选型方法 | 怎么挑 | 判断条件清单 | 选型维度、取值范围、对照表、例子 | 选型指南 | 使用条件 → 看哪些参数 → 取值范围 → 对照表 → 例子 |
| 设计应用 | 电路、布局怎么做 | 推荐做法概要 | 电路图、布局要点、测试结果、注意事项 | 应用文章 | 电路 → 元件作用 → 布局要点 → 测试结果 → 注意事项 |
| 故障排查 | 出了问题怎么办 | 最常见的原因 | 现象 → 原因 → 排查 → 解决、何时找工程师 | 故障文章 | 现象 → 原因 → 排查步骤 → 解决 → 何时找工程师 |
| 标准法规 | 标准怎么要求 | 标准名、版本、要点 | 条款出处、对设计的影响、更新日期 | 标准解读 | 标准与版本 → 关键条款 → 对设计的影响 → 更新记录 |
| 技术对比 | 两种技术差在哪 | 一句话结论和适用场景 | 同条件对比表、各自适合谁 | 对比文章 | 结论 → 对比表 → 各自适合 → 选择建议 |
| 行业资讯 | 市场、新技术 | 发生了什么、和读者的关系 | 日期、来源、影响 | 资讯文章 | 发生了什么 → 和读者的关系 → 影响 → 来源 |

## 2. 逐类写法

### 概念定义

- 第一句就是定义：是什么、用来做什么。
- 第二段讲和相近概念的区别，这是新手最容易混的地方（例如网络变压器和共模电感、闸阀和截止阀）。
- 读者的叫法和工程师的叫法都写一遍：Google《SEO 新手指南》（2025-12-10）提醒专家和新手对同一个东西常用不同的词。各写一次即可，不为覆盖所有写法去堆词。
- 用一个具体例子帮助理解；链到原理、选型文章和分类页。

### 原理机制

- 先给一句话因果，再分步讲。
- 配自己画的原理图或波形图；用别人的图写出处。公式写出处和符号含义。
- 讲清关键参数怎样影响结果；列 2–3 个常见误解。
- 收尾落到「设计时要注意什么」，链到选型和设计文章，否则读者读完就走了。
- 常见错误：开头三段背景才进正题；原理图截图不注出处；只讲原理不讲设计上的含义；把「通常如此」写成「一定如此」。

### 参数资料

参数类搜索（「型号 + datasheet」「pinout」「dimensions」）要的是数据本身，由型号页承接最对口，不另写文章。写法见 `page-blueprints.md` 第 4 节。

### 选型方法（五步）

1. 先问使用条件：速率、功率等级、隔离、空间、温度、介质、压力……按品类定。
2. 每个条件看哪个参数、取值范围多少，取值写出处。
3. 给一张对照表：条件 → 推荐的系列或参数。
4. 举一个完整的选型例子。
5. 链到系列页、型号页；需要确认的交给工程师。

另写明适用边界：哪些情况这张对照表不适用。最常见的毛病是只列参数不给判断，结论是「请联系我们」。

### 设计应用

- 给电路图（或安装图、系统图），讲清关键元件的作用。
- 外接元件的取值要有依据。规格书里没有推荐电路的，取值由工程师提供，不自己编；没有就不写具体取值。
- 布局要点按「为什么 → 怎么做」写。
- 有实测就放结果并写测试条件；写清适用和不适用的情况。

### 故障排查（五步）

1. 现象：用读者自己的话描述（测试不过、灯不亮、掉线、泄漏）。
2. 可能原因：按常见程度排，最可能的放前面。
3. 排查步骤：先简单后复杂，写清用什么工具、看到什么算正常。
4. 解决办法：每个原因对应一种改法，写适用条件。
5. 何时找工程师：写清要带上什么（原理图、测试数据、样品信息）。

排名尚可但点击率低的故障文章，先看首段是不是直接列出了最常见的原因。

### 标准法规

- 写标准全名、版本号和发布机构；引用写条款号，不整段转贴原文。
- 重点说明这条要求对选型和设计意味着什么。
- 标准出新版就更新文章，写更新记录（实质更新，可以改日期）。
- 器件或部件供应方只说明自身参数和测试报告，不替客户判断整机能否通过认证（见 `evidence.md` 第 8 节）。

### 技术对比

参考 Google《写出高质量评测》（2025-12-10）里对评测内容的要求：

- 用可以量化的指标比较，条件相同才可比。
- 说明各自适合谁、不适合谁；讲清取舍对设计的影响。
- 结论有自己的测试或资料依据，不复述厂商宣传。

对比表示意（只说明怎么排，取舍以规格书和工程师意见为准）：

| 维度 | 方案 A：集成式（例：带磁 RJ45） | 方案 B：分立式（例：变压器 + RJ45） |
|---|---|---|
| 占板面积 | 通常更小 | 通常更大 |
| 布局灵活性 | 受封装限制 | 可单独摆放、调整走线 |
| 适合 | 空间紧、要快速完成设计 | 要灵活调 EMI 或定制 |

### 行业资讯

- 写清日期和来源，只写和读者有关的事；写出自己的视角：这件事对产品线、对客户的设计意味着什么。
- Google 的「更新系统」（常说的新鲜度）只在用户期待新内容的查询上优先新内容（排名系统指南，2025-12-10），资讯过了时效不必刷新日期。
- 拿不出一手信息的资讯少写：只因话题热门才写、没有专长只为流量进入某个领域，都是 Google 列的警示信号。

## 3. 两种「比较」：按比较对象分

| 比较对象 | 意图 | 承接 | 能写什么 |
|---|---|---|---|
| 两种技术、两种结构、两种方案 | 信息词 · 技术对比 | 对比文章 | 优缺点、适用场景、取舍，结论有依据 |
| 品牌、供应商、可直接买的产品（best、top、review） | 商业词 · 比较挑选 | 选型指南、系列页 | 选型依据、对照表、适用场景；不写 best、不写谁更好 |
| 竞品型号和我们的型号 | 商业词 · 替代查询 | 替代对照页、型号页 | 参数对照、差异、验证方法；写「替代候选，用样品验证」（`claims-wording.md`） |

## 4. 商业词九个细类

商业词的读者已经打算采购或找供应商，他们要的「答案」是产品和下一步：参数、对照、资料、入口。写多写少看能不能帮客户做决定，不看字数。buy、price、supplier 这类词写成文章，会和产品页抢词，读者也找不到询价入口。

| 细类 | 承接页面 | 页面上必须有的内容 | 口径提醒 |
|---|---|---|---|
| 产品浏览 | 分类页、系列页 | 系列概述、选型表、各系列区别、应用、资料下载 | 不写死型号个数 |
| 比较挑选 | 选型指南、系列页 | 选型依据、对照表、适用场景 | 不写最高级和谁更好 |
| 替代查询 | 替代对照页、型号页 | 原型号与候选型号的参数对照、差异、验证方法 | 不泛称 pin-to-pin、drop-in；写候选 + 样品验证 |
| 找厂家 | 分类页、关于页 | 我们是谁、哪些自产、证书与检测报告 | 自产才写制造商；按品类分开写 |
| 找供应渠道 | 分类页、关于页 | 自产还是代理、怎么供货、联系方式与回复时效 | 代理写清代理身份；时效用登记原句 |
| 询价 | 型号页、询价入口 | 询价表单、需要客户提供的信息 | 不写价格 |
| 现货与下单 | 型号页、询价入口 | 下单方式 | 交期、库存只在口径允许的页面写 |
| 样品 | 样品页 | 申请方式、流程 | 样品说法用口径文件的固定句 |
| 定制 | 定制页 | 定制范围、流程、评估时间 | 评估时间用登记原句 |

每一类具体能写什么、不能写什么，以本站口径文件为准；通用规则见 `claims-wording.md`。系列页、分类页的分块写法见 `page-blueprints.md`。
