# 数据来源与降级

原则：有什么数据用什么数据，缺的不硬凑。每个数字都写清楚三件事：来源、取数日期、统计口径。缺的数据列进报告的「范围与方法」，对应评分项标「未验证」，并选定一种处理方法，全报告统一：

- **剔除**（推荐）：这一项不计分，把它的满分从总分里减掉，再折算回 100。
- **保守给分**：按已知最坏的合理情况给分，在扣分原因里注明「未验证」。

后台数据为主，第三方工具为辅：后台数据来自搜索引擎自己，通常最可信，但只覆盖一部分（例如 GSC 不显示匿名查询、表格最多 1,000 行），要写清数据范围。第三方工具没有 Google 的内部排名数据，它的分数和预测是它自己的（Google《第三方 SEO 工具、服务和建议指南》，2026-06-05）。

## 开工前备好六样东西

换一个人拿着这六样，能重复你的检查，才算准备好了。

| # | 准备什么 | 要点 |
|---|---|---|
| 1 | 范围清单 | 站点、语言、页面类型、抽样网址；写进报告的「范围与方法」，没查的模板写「未检查」 |
| 2 | 时间段 | 近 3 个月对比上一周期和去年同期；跨统计口径断点的分段看（如 2025-09 中旬 Google 停用 num=100 参数） |
| 3 | 统计口径 | GSC 按美国太平洋时间切日，GA4 按站点时区；按资源汇总与按网页汇总合计不同；匿名查询不进明细 |
| 4 | 基线 | 后台的展示、点击、排名、收录数，加页面截图，全部带日期；内部评分只作附录，不能代替后台数据当基线 |
| 5 | 证据存档 | 截图能看到网址和日期；导出文件名带日期；写明工具版本、抓取身份、是否渲染 JS |
| 6 | 本站口径文件和历史决定 | 读最新版本站口径文件；以前审计已经定下的事（例外、保留、待定）不要每次当新问题报 |

基线要在动手之前记。改完再回头找「改之前是什么样」，往往已经找不到了。

## 数据清单

| 数据 | 回答什么问题 | 没有时怎么降级 | 注意 |
|---|---|---|---|
| **直接请求线上页面**（必有） | 状态码、跳转链、head 标签、正文、结构化数据、robots.txt、站点地图、llms.txt | 无法降级，这是底线 | 用多个 UA 请求，见下文；记录请求时用的 UA |
| **渲染后的页面**（无头浏览器） | 脚本渲染出的内容、隐藏元素、布局、性能 | 只看源码，报告注明「未渲染」，正文统计可能偏差 | 收起的问答要算进正文；隐藏在 textarea、JSON 里的数据不算正文，但要算进 HTML 体积 |
| **搜索控制台**（谷歌 Search Console、百度资源平台、必应网站管理员工具） | 收录量、未收录原因、查询词、展示、点击、排名、抓取统计与主机状态、人工处置、安全问题 | 用 `site:` 查询估量级；用日志看抓取 | `site:` 只能估量级，不当收录数；必应的 `site:` 从本机查常不准，不计分。GSC 数据一般 2–3 天后可见，保留 16 个月 |
| **GSC 网址检查** | 单个网址是否已编入、抓取设备、声明的和 Google 选的规范网址、渲染后 HTML | 无替代 | 默认显示上次收录的版本；改完要点「测试实际网址」；实时测试不判断重复和规范 |
| **百度抓取诊断、抓取异常、索引量** | 百度蜘蛛实际拿到什么；抓取失败的类型；收录趋势 | 用日志里的真百度蜘蛛记录 | 抓取诊断每站每周 70 次、只显示前 200KB；有 CDN 防护的站，以它为准，不拿自己的脚本结果下结论 |
| **必应站点扫描（Site Scan）** | 整站的错误、警告、提示 | 用其他抓取工具 | 月配额必应核定，不能提额；最多保存 5 次；可导出 CSV |
| **服务器访问日志** | 蜘蛛抓了多少、抓了哪类页、拿到什么状态码、重要页多久没来 | 无替代，报告注明 | 蜘蛛真假要反查：IP 反解出域名，再正解回同一 IP。要去掉自家代理、回源、监控的流量。有 CDN 时，被 CDN 拦下的请求源站日志里看不到 |
| **关键词工具** | 搜索量、出价、相关词、域名排名词、外链 | 中文市场用搜索框下拉词、相关搜索、指数 | 多数工具没有中国数据，纯中文词给 0 不代表没人搜。下拉词只能说明有人在搜、怎么说，不代表搜索量。查询要花额度：先列清单再批量查，记录花了多少 |
| **网站统计** | 着陆页流量、关键事件（询盘、样品、下载）、来源 | 用搜索控制台的点击代替 | 统计口径和搜索控制台不同，不要混着加；GA4 只记同意了统计 Cookie 的访问；手机端独立页面常漏装统计 |
| **询盘记录** | 询盘带没带着陆页和来源 | 用统计里的关键事件代替，注明 | 用测试数据实际提交一次（事先和负责询盘的人约好），看统计和询盘记录里能不能都找到 |
| **数据库只读查询** | 全量字段值、批量统计、后台存的值和页面渲染出的值是否一致 | 全站抓取后反推 | 只读事务；不打印连接密码；中文字段注意字符集 |
| **网页存档**（如 Wayback Machine） | 域名历史：以前是谁的、放过什么内容 | 搜旧网址、问域名卖家 | 新接手的域名、收录异常时必查 |
| **外链数据** | 外链数量、来源质量、垃圾外链占比、锚文本 | 搜索控制台的「链接」报告；必应反向链接 | 小站在第三方库里覆盖不全，「查不到」只能说明「几乎没有」。DR、AS、DA 是各家估算，Google 不用，不能跨工具比 |
| **搜索结果页** | 意图判断、同义词是否算同一主题、竞品格局、标题是否被改写 | 无 | 看前 10 个结果；国内搜索引擎查询注意防刷，频率放低 |
| **AI 回答抽查** | AI 搜索有没有提到本站、引用官网，引用的说法对不对 | 用站方公开的监测数据，注明「未独立复核」 | 选 5–10 个目标问题实际问一遍，记日期和原问法；这是抽样，不是统计 |
| **结构化数据校验** | JSON-LD 能否解析、能否进富媒体结果 | 脚本解析 JSON，并和可见文字比对 | 官方测试工具要人工打开，结果截图存证 |
| **性能** | LCP、CLS、INP、请求数、体积 | 本机无头 Chrome 按手机档模拟，跑 3 次取中位数 | 判断好坏用实测（CrUX 75 分位），实验室数据只找原因。公共测速接口有每日额度；和线上对比时，两边都要开压缩；TTFB 波动大时扣掉 TTFB 再比 |

## 用工具结果前先问三句

1. 它测的是哪个网址？有跳转时，工具测到的可能是跳转后的页面。
2. 用的什么身份？手机、桌面、哪家爬虫。
3. 数据是不是最新的？有没有缓存（CDN、浏览器、渲染服务）？

工具分数不是结论：PageSpeed Insights 里的 SEO 一栏只做少量基础检查，满分只说明这些基础项没缺（Chrome for Developers《Lighthouse SEO audits》）；第三方的「网站评分」「权重分」是各家自己的估算，不是搜索引擎指标，不能跨工具比。

## 多 UA 请求

至少比较下面几种 UA。看状态码、跳转目标、标题、正文长度、robots 标签：

- 桌面浏览器
- 手机浏览器（真人）
- 谷歌爬虫（手机版、桌面版）
- 百度爬虫
- 必应爬虫
- AI 爬虫（GPTBot、ClaudeBot、PerplexityBot、OAI-SearchBot 等，训练类和搜索类分开看）

常见问题有这几种：

- 真人手机被跳到另一个应用（往往是 noindex 的单页应用），爬虫却拿到桌面页；
- CDN 按 UA 拦截或放行；
- 防火墙按频率把蜘蛛限流成 503。

`node scripts/seo_measure.mjs uacheck <网址>` 能一次比完。UA 谁都能填，这只能说明服务器怎么区别对待各种 UA；真爬虫有没有被拦，看日志和各家后台。

## 抓取礼仪

- 并发低一点：海外站 4 个以内；有防刷 CDN 的国内站用 1 个，放慢速度。
- 监测请求的 UA 里带上可识别的标记，便于事后在日志里区分。注意：有的站内功能会把带 bot 字样的请求过滤掉，比如「热门搜索」「求购榜」。这时看到的数据和真人看到的可能不一样，要换成浏览器 UA 再看一次。
- 国内站有 CDN 时，网址后面加随机参数看源站，再等缓存过期看正常网址。
- 全程只读：不提交表单（约好的测试提交除外），不登录后台写数据。
