# 文案规范

适用范围：Title、描述、H1、H2、正文、问答、结构化数据里的文字、llms.txt。

总原则：先有事实，再有文字。搜索引擎和 AI 会原样引用页面上的话，写错一句的代价比少写一句大。

## 1. 事实与口径

- **只写口径登记表里「可以写」的说法。** 待定的不写；禁止的不写。新的说法先请负责人登记，再写进页面。凭旧记忆判断「这个还没批」或「这个批过了」都容易出错，每次写之前重读登记表。
- **以证照为准**：
  - 公司法定名称、地址，照营业执照和证书原文写；证书上有错别字的，引用时改正。
  - 证书编号、覆盖范围、有效期，照证书原文写。认证范围是「研发和销售」的，不能写成「认证的生产」。
- **说法要分清三组**：
  - 认证证书、第三方检测报告、「符合某标准」，三者不是一回事。没有证书的不写 certified。
  - 自己生产、代理、贸易，三者不是一回事。一句话里如果同时说到代理的产品，就按代理写。
  - 某个型号有某证书，不等于全线都有。证书只覆盖部分型号的，写明是部分型号。
- **一手资料优先**：参数、尺寸、脚位、测试条件、包装数量这类规格书里有的，直接取规格书。不用等别人确认，取完逐项核对。
  - 规格书和站上数据冲突时，报给负责人定，不要自己挑一个用。
  - 规格书里没有的不要编，原样留「待确认」：推荐电路、商务条款、交期、产地、质保。

## 2. 不写会变的数字

后台手写的文字里，不写会随上下架失效的数字：

- 料号个数、系列个数、选项个数（「共 600 个型号」「六个系列」「四种规格」）
- 料号区间（「从 A-011 到 A-014」）
- 相对最值（「本系列型号最多的分支」）

改成描述结构：「含直立、沉板、低高度等系列」「匝比覆盖 1:50 到 1:200」。

页面上自动计算的数字（列表顶部的「共 N 个」、结构化数据里的 numberOfItems），不要在文案里再写一遍。

自查用的正则（中文，按需要扩充）：

```
\d+\s*个(料号|型号|系列|产品)|共\s*\d+\s*(个|款|种)|[一二三四五六七八九十]\s*(个系列|种|个分支|款)|最多的
```

## 3. 不夸大、不承诺做不到的

- **不用最高级和无法证明的比较**：best、leading、world-class、No.1、top，领先、顶级、第一、最好。泛泛的 cost-effective 可以留，带比较对象的删掉。
- **替代和兼容不打包票**：
  - 不写 pin-to-pin、drop-in、直接替换、完全兼容；
  - 写「替代候选，参数和封装经工程师比对，量产前用样品验证」。
- **服务承诺只写登记过的**：样品、交期、回复时效、最小起订量、价格，照登记的原句写。
- **顺口不能顺成夸大**：面向大众的内容可以用叙事、问句、生活场景，但每一句都要核对属实。用户给的示范句也要核，不属实就说明原因并给替代写法。

## 4. 不泄露

不写这些：

- 内部编码；
- 客户名和项目名（负责人批准的例外要登记）；
- 测试数据；
- 员工个人邮箱和手机号；
- 内部术语（后台、已发布、字段、记录这类词）。

联系方式统一用站点的公共入口：询盘表单、样品申请页、公共邮箱。

## 5. 结构

- **一页一个主题词。** 主题词要出现在这几处：Title、H1、正文第一句、至少一个 H2、至少一个问答。
- **H2 用平实说法**回答这一页要回答的子问题，例如怎么选、用在哪、怎么买、怎么替代、去哪下资料。不堆词。
- **商业意图要有真实入口**：样品申请、询价、替代比对、规格书下载。只承诺真实存在的入口和文件。
- **问答**：
  - 每页至少 3 条；
  - 不重复页面上已有的问答；
  - 答案开头先给结论；
  - 问答格式要能被抽取；结构化数据里的问答和可见文字逐字一致。
- **锚文字写成描述性的。** 不用「Read more」「了解更多」「→」。跳转入口做成正规按钮。
- **要承接意图，篇幅得够。** 末级分类或系列页的独有正文，参考 500 词以上，按评分表的目标来。字数多不是目的：每一段都要围绕主题词，写本页独有的信息。

## 6. 长度与密度

- 长度目标见 [page-rubrics.md](page-rubrics.md)，量法见 [measurement.md](measurement.md)。
- 主题词组密度按评分表的目标写，单个词不超过 3%。读起来像在堆词，就算达标也要改。
- 标签会被代码加工的（自动加品牌后缀、截断），按最终渲染结果控制长度。

## 7. 多语言

- 译文和源文同步更新，术语用统一的对照表。
- 译文里的链接，目标页必须有这个语言的版本，不然改成链到有这个语言版本的页面。
- 小语种页面的 Title、描述也要按长度目标量一遍，译文常常偏长。
- 小语种页面只有界面是译文、正文还是源语言的，在报告里写明。

## 8. 交付与自查

- 文案稿以结构化文件为准（JSON、配置文件、表格），再从它生成可读的稿子。要改稿就改源文件，改完重跑检查。不要只改可读稿。
- 写完逐页跑检查。人工数字数已被证明不可靠，下面这些都用脚本跑：
  - 长度：Title、描述、H1；
  - 主题词出现的位置；
  - 主题词组密度、单个词密度；
  - 禁用词正则、会变数字的正则；
  - 链接逐个请求，看是不是 200；
  - 问答和结构化数据逐字比对。
- 口径对照：凡是涉及对外说法的句子，逐句对照登记表。
- 交给负责人审的稿子要完整：多语言的，每种语言都给全文，不只给摘要。
