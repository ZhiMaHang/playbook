# 整改文案的底线与自查

适用范围：审文案时查什么；整改方案里少量改写 Title、描述、H1、问答、结构化数据里的文字、llms.txt 时守什么。

怎么写交给兄弟技能：

- Title、描述、H1–H3、网址、alt、锚文本的写法、长度、批量模板：详见 **seo-tdk-page-elements** 技能。
- 分类页、产品页、文章正文怎么写，E-E-A-T、作者与证据、更新与合并、审稿清单：详见 **seo-content-writing** 技能。
- 成批改写（几十页以上）交给这两个技能做，本技能出问题清单和验收标准，改完回来按同一张评分表复测。

总原则：先有事实，再有文字。搜索引擎和 AI 会原样引用页面上的话，写错一句的代价比少写一句大。本站口径的通用原则见 [seo-basics.md](seo-basics.md) 第 8.2 节，这里只列诊断和整改时要逐条核对的项。

## 1. 事实与本站口径

- **只写本站口径文件里「可以写」的说法。** 待定的不写；禁止的不写。新的说法先请负责人登记，再写进页面。凭旧记忆判断「这个还没批」或「这个批过了」都容易出错，每次写之前重读最新版，交付时注明依据的版本日期。
- **以证照为准**：公司法定名称、地址照营业执照和证书原文写，证书上有错别字的，引用时改正；证书编号、覆盖范围、有效期照原文写，范围是「研发和销售」的，不能写成「认证的生产」。
- **说法要分清三组**：认证证书、第三方检测报告、「符合某标准」不是一回事，没有证书的不写 certified；自己生产、代理、贸易不是一回事；某个型号有某证书，不等于全线都有。
- **一手资料优先**：参数、尺寸、脚位、测试条件、包装数量这类规格书里有的，直接取规格书，取完逐项核对。规格书和站上数据冲突时，报给负责人定，不要自己挑一个用。规格书里没有的不要编，原样留「待确认」：推荐电路、商务条款、交期、产地、质保。
- **结构化数据、llms.txt、og 标签同样守本站口径**：给机器看的文字平时没人读，写错了最容易漏。

## 2. 不写会变的数字

后台手写的文字里，不写会随上下架失效的数字：

- 型号个数、系列个数、选项个数（「共 600 个型号」「六个系列」「四种规格」）；
- 型号区间（「从 A-011 到 A-014」）；
- 相对最值（「本系列型号最多的分支」）。

改成描述结构：「含直立、沉板、低高度等系列」「匝比覆盖 1:50 到 1:200」。页面上自动计算的数字（列表顶部的「共 N 个」、结构化数据里的 numberOfItems），不要在文案里再写一遍。

自查用的正则（中文，按需要扩充）：

```
\d+\s*个(料号|型号|系列|产品)|共\s*\d+\s*(个|款|种)|[一二三四五六七八九十]\s*(个系列|种|个分支|款)|最多的
```

## 3. 不夸大、不承诺做不到的

- **不用最高级和无法证明的比较**：best、leading、world-class、No.1、top，领先、顶级、第一、最好。泛泛的 cost-effective 可以留，带比较对象的删掉。图片里的文字（logo 图、横幅）同样要查。
- **替代和兼容不打包票**：不写 pin-to-pin、drop-in、直接替换、完全兼容（本站口径文件明确允许的具体型号对除外）；写「替代候选，参数和封装经工程师比对，量产前用样品验证」。
- **服务承诺只写登记过的**：样品、交期、回复时效、最小起订量、价格，照本站口径文件登记的原句写。
- **顺口不能顺成夸大**：面向大众的内容可以用叙事、问句、生活场景，但每一句都要核对属实。用户给的示范句也要核，不属实就说明原因并给替代写法。

## 4. 不泄露

不写：内部编码；客户名和项目名（负责人批准的例外要登记）；测试数据；员工个人邮箱和手机号；内部术语（后台、已发布、字段、记录这类词）。联系方式统一用站点的公共入口：询盘表单、样品申请页、本站域名的公共邮箱。

## 5. 整改文案的最低结构要求

诊断时按这几条查，写作方法详见 seo-content-writing 技能，标题和描述写法详见 seo-tdk-page-elements 技能：

- 一页一个主题词，出现在 Title、H1、正文第一句、至少一个 H2，读起来不堆砌。
- 字数、问答条数不是搜索引擎的指标：Google 没有字数偏好。「每页 3–5 条问答」「末级页独有正文多少词」都是经验值，作为本站内部检查口径在站点档案里设定，用来发现照搬多、独有少的页面，不当扣分硬线；为凑字数、凑条数加内容反而有害。
- 商业意图要有真实入口：样品申请、询价、替代比对、规格书下载；只承诺真实存在的入口和文件。
- 问答答案开头先给结论；页面上的问答和结构化数据逐字一致，同源生成。
- 锚文本写成描述性的，不用「Read more」「了解更多」「→」；跳转入口做成正规按钮。
- 标签会被代码加工的（自动加品牌后缀、截断），按最终渲染结果控制长度。
- 多语言：译文里的链接，目标页必须有这个语言的版本；小语种页面只有界面是译文、正文还是源语言的，在报告里写明。

## 6. 交付与自查

- 文案稿以结构化文件为准（JSON、配置文件、表格），再从它生成可读的稿子。要改稿就改源文件，改完重跑检查，不要只改可读稿。
- 写完逐页跑脚本检查，人工数字数已被证明不可靠：长度（Title、描述、H1，对照经验值）；主题词出现的位置；密度读数（只作参考，读数偏高就通读一遍查堆砌）；禁用词正则、会变数字的正则；链接逐个请求看是不是 200；问答和结构化数据逐字比对。
- 本站口径对照：凡是涉及对外说法的句子，逐句对照本站口径文件，注明对照的版本。
- 交给负责人审的稿子要完整：多语言的，每种语言都给全文，不只给摘要。
