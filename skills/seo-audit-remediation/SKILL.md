# 站点 SEO 评分与整改

一句话：先取证再下结论，前后用同一把尺子量；分数只是手段，最后看收录、曝光和询盘。

这套做法来自多个企业站（B2B 制造、分销平台、中英文双站、多语言）的评分和整改实战。站点之间差别很大，所以把「每个站不一样的东西」放进站点档案，把「每个站都一样的方法」放在这里。

## 先判断做到哪一步

| 用户要的 | 做到哪 | 交付 |
|---|---|---|
| 评分、体检、诊断 | 阶段 0–1 | 评分报告 |
| 整改方案、文案 | 阶段 0–2 | 报告 + 整改清单 + 文案稿 + 预估分 |
| 落地 | 阶段 0–4 | 以上 + 预览 + 上线 + 核对记录 |
| 复测 | 阶段 5 | 前后对比 |

用户只要评分时，做完阶段 1 就停，不要顺手改东西。

## 开工前：读站点档案

1. 找这个站的 `站点档案.md`，一般放在站点工作目录。找不到就问用户放哪了。
2. 确实没有：拿 [references/site-profile-template.md](references/site-profile-template.md) 和用户一起填。至少要填齐这几项，才能开始阶段 2 以后的工作：
   - 面向的市场和主口径；
   - 页面文字从哪来（模板、后台还是配置）；
   - 怎么发布、怎么回滚；
   - 谁批发布；
   - 对外口径登记表在哪；
   - 有哪些数据账号。

   只做评分时，缺的项写「未知」继续做，在报告里注明。
3. 先读档案里的「已知坑」。那是这个站反复出过事的地方，比通用经验更要紧。

## 工作原则

每条后面写了为什么。遇到这里没覆盖的情况，按「为什么」去判断。

1. **结论来自实测，不来自印象。** 每个判断都要有证据：直接请求线上拿到的结果、日志、平台数据、数据库只读查询。每个数字都写清来源、日期和口径。凭记忆写的结论（「这个站有某个函数」「标题会自动加后缀」）在实战里一再出错。
2. **一把尺子量到底。** 默认用严苛口径：查到的问题都扣分，全站共性的老问题也算进每一页。前后对比要用同一张评分表、同一个脚本、同一种正文口径。换了口径的两个分数不能直接比，报告里要写明。
3. **数字交给脚本算。** 长度、密度、重合率、字数、链接数，人工数错是常态。用 [scripts/seo_measure.mjs](scripts/seo_measure.mjs) 或自己写脚本，并保留下来，复测时重跑。
4. **先找根因，再看表面。** 分数大头往往丢在页面以外：
   - 收录通道断了（平台没验证、推送失败、限流挡了蜘蛛）；
   - 域名有不良历史；
   - 同一模板的薄页成千上万；
   - 真人和爬虫拿到的是不同页面。

   这些不解决，改标签没有意义。报告里根因一般不超过 3 条。
5. **分清收录、排名和转化。** 收录是被看见，排名还取决于外链和站点权重，转化看页面能不能让人留下询盘。页面分高不等于能排上，这句话要对用户讲清楚。
6. **只写登记过的事实。** 对外说法（制造还是代理、认证、客户数、交期、样品政策）一律以站点的口径登记表为准，证照为准。待定的不写；新事实先请负责人登记，再写进页面。
7. **评分不是效果。** 评分标准是我们自定的，不是搜索引擎的官方分，搜索引擎也不公开页面分数。「分数涨了」「已上线」「验收通过」都不能证明做法正确。效果要几周后看平台数据：收录量、曝光、查询词有没有扩展。
8. **讨论时先表态，确认后再动手。** 用户问「对不对」「你认不认可」时，逐条说认可、部分认可或不认可，并给出理由和依据，有异议要明说。用户明确说「改」再改。
9. **每个改动都要能核对、能回滚。** 改之前想好两件事：上线后怎么证明它生效了，出事了怎么撤回。

## 阶段 0：定范围

- 写清楚这次的对象：
  - 站点、语言版本、姊妹站（共用代码或数据库的站）；
  - 页面清单和页面类型；
  - 主口径：谷歌、百度、AI 搜索，可以多选，选一个为主。
- 页面多（超过约 30 页）时：同模板的页用脚本全量跑，关键页逐页人工看，其余按类型分层抽样。抽样方法写进报告。
- 先定每页的主题词。有词表就用词表；没有就从页面现状和搜索数据推定，并标「推定」。主题词定错，后面的密度、覆盖和防抢词全会跟着错。

## 阶段 1：评分

1. **收集数据**：按 [references/data-sources.md](references/data-sources.md) 逐类取。缺的不硬凑，记下来降级处理。
2. **全站体检**（对象是整站或页面类型多时）：按 [references/site-audit.md](references/site-audit.md) 给每种口径分别打分，再找根因。
3. **页面评分**：
   - 按页面类型选评分表，见 [references/page-rubrics.md](references/page-rubrics.md)。三套：首页 + 关于 / 联系、分类页 + 产品详情页、文章 / 新闻。
   - 测量口径见 [references/measurement.md](references/measurement.md)。
   - 每项写实测值和扣分理由，不只给分数。
4. **分级**：
   - P0：不修，其余全白做。例如收录通道断了、整类页面报错、泄露内部信息、违背对外承诺。
   - P1：两到四周内要做的主要失分项。
   - P2：顺手修的小问题。

   每条都写全六项：现象、证据、影响、改法、经办人、验收标准。
5. **出报告**：按 [references/report.md](references/report.md)。存一份 Markdown；HTML 看板用 `node scripts/build_report.mjs 数据.json 报告.html` 生成。生成出来的是静态页，内容直接写在页面里，预览面板、关掉脚本也能看到。不要手工替换模板里的数据，那样做出来的页面要靠脚本现画，在预览里是空白的。

## 阶段 2：整改方案与文案

1. **关键词布局**：按 [references/keywords.md](references/keywords.md) 做「词 → 承接页」对照表。
   - 一页一个主题；
   - 长尾词交给真正承担它的页面；
   - 上级页的通用词不塞进下级页。
2. **方案**：每条落到具体改哪里，分四类：
   - 代码模板；
   - 后台字段；
   - 服务器或平台配置；
   - 内容。

   要负责人拍板的事单独列出，每项给建议和理由。有几类改动必须单独成题，不能捎带在「推荐方案」的说明里：删除或关闭访客看得见的板块，以及改定稿口号、改网址。
3. **文案**：按 [references/copy-rules.md](references/copy-rules.md) 写。写完跑自查：长度、密度、禁用说法、会变的数字、口径对照。
4. **预估分**：改完按同一张评分表估分，分两档：
   - 「上线版」：不需要别人拍板就能做完的部分；
   - 「全部完成」：待拍板项也落地后。

   两档分别写清还差在哪。

## 阶段 3：实施

要点如下，细节见 [references/ship-and-verify.md](references/ship-and-verify.md)。

- **先预览给负责人看**：本地预览，或代理线上页面后套用改动。预览不提交表单、屏蔽统计。预览页可以加 noindex，但这个标记不能带上线。
- **要原话口令**：负责人明确说「提交」「上线」「合并」才做对应动作。一次批准只管那一次。含糊的话（「继续」「再试一次」）先问清楚指哪一步。
- **改后台数据**：
  - 先读出旧值存备份，能试运行就先试运行；
  - 只改涉及的字段，写完读回逐字核对；
  - 批量接口会不会把没传的字段清空，先确认。
- **改代码**：
  - 遵守站点档案里的坑；
  - 用到的函数、配置键、数据 ID，先确认真实存在；
  - 找数据按 ID，不按标题或网址别名；
  - 全局模板、中间件这类改动，先在本地跑通一个样页；
  - 本次的验收项写成可重跑的检查脚本，随改动一起提交。

## 阶段 4：上线核对

- **流水线显示成功，不等于页面已经变了。** 到线上真实页面逐项核对：
  - 新加的标识在不在源码里；
  - Title、描述、H1、canonical、hreflang、robots 标签；
  - 结构化数据能不能解析、和可见文字是否一致；
  - 状态码和跳转；
  - 多语言、姊妹站、多种 UA（真人手机、搜索引擎爬虫、AI 爬虫）。
- **有缓存层的站**：先看部署日志，确认目标文件真的同步了；再对比源站和公网，判断是不是缓存。清缓存按站点档案的权限来，不要擅自操作。
- **报错或明显变慢，先回滚再查原因。** 不要在线上边查边修。
- **搜索平台侧**：网址检查、请求编入索引、重新提交站点地图、推送或 IndexNow。
- **记录**：改了什么、什么时候生效、怎么回滚、核对结果，写进站点的工作日志。

## 阶段 5：复测

- 用同一脚本、同一口径重跑，和上次的结果逐项对比。
- 报告里放一张复测指标表，列五栏：指标、现在、目标、怎么看、复查日期。
- 观察窗口：收录看 1–2 周，曝光和查询词看 4–8 周。
- 分数涨了不等于有效果，要拿平台数据说话。

## 汇报方式

- 结论放最前面，短。数字带口径，例如「正文按渲染后主体区计」「宽度按全角 2」。
- 「待拍板」单独一节。每项写清选项、建议和理由，只问真正要负责人定的事。
- 照实写问题，不表扬、不迎合。已达标的项可以列出，但只列事实，不加评价。
- 区分「已核实」「推定」「未验证」三种状态。
